# Solana Meme Expert Research Writing｜专家研究写作技能 V1.0

**知识结构依据：** [知识架构 V2.0](../../docs/knowledge-architecture-v2.0.md)。本 Skill 的工作位于深度研究/知识转换能力，不另建一套领域层级；研究原则遵循 [V5 机制发现宪章](../../docs/economic-mechanism-discovery-charter-v5.md)，运行/调度边界遵循 [V4 双循环架构](../../docs/dual-loop-research-runtime-architecture-v4.md)。

> 目的：不是帮 AI 把资料“写漂亮”，而是驱动 AI **理解真实知识、发现机制连接、形成有深度且可审查的专业原创论述**，再把有价值的部分转换给 Grok 使用。
>
> 优先级：研究问题与证据 > 市场机制 > 新认知 > 表达技巧 > 文档格式。
>
> 状态：研究写作 Skill 草案。被保存或安装不代表实际云端 Grok Bot 已加载或验证。

## 范围修正（2026-10-31）：全市场监控优先，跟单只是专题

本项目的真正目标是 Solana Meme **市场级监控和机制研判**，包括批量资金转账、同 Slot/多钱包协同、正常和异常账户基准、疑似关联资金网络、跨 Mint 操作、市场结构和交易条件。此前文稿主要以“盈利钱包可跟随性”作为研究示例，**不代表系统整体方向**。

先调用 [`solana-meme-system-intelligence`](../solana-meme-system-intelligence/SKILL.md) 确定事件对象、监控问题和竞争机制；本 Skill 随后负责从一手知识与真实证据中写出机制深度、反证、知识增量和可迁移能力。钱包复制性研究仅在任务确实涉及跟单时启用。

具体范围见 [`docs/solana-meme-marketwide-monitoring-scope-v1.md`](../../docs/solana-meme-marketwide-monitoring-scope-v1.md)。写任何“庄家”“捆绑”“可交易”结论前先区分：同 Slot 多笔交易、Jito Bundle 证明、经济同控假设、统计异常和真实净收益并非一件事。

## 0. 何时使用，何时不要使用

**触发：** 需要精读旧 Hermes / meme- / qb- / Why-Solana / OKX 等参考资料；将多仓库概念转成 Meme 跟单专业知识；写深度专题、机制评估、反证研究、案例复盘、知识演化分析或 Grok 能理解的研究成果。

**不要代替：**
- `skills/solana-meme-knowledge/SKILL.md` 的简短来源检索、常规知识问答；
- `skills/solana-meme-monitor/SKILL.md` 的只读监控与状态持久化；
- 真实行情收集、链上取证脚本、统计检验和执行模拟本身；
- 未经批准的规则发布、Grok Bot 部署、实盘下单。

如果用户只问一个事实，准确回答即可；**只有需要深化知识和产出系统研究文本时，才启动长篇写作。**

## 1. 初始化：先读实际项目，不凭提示词想象项目

1. 阅读 `AGENTS.md`、`CONTEXT.md`，确认研究对象、当前只读/paper-only 边界和已有工作成果。
2. 读取 `knowledge/README.md`、`knowledge/method.md`、`knowledge/catalog.v1.json`、`knowledge/source_index.v1.json` 与 `docs/knowledge-assets-logic-audit-wave1.md`（若该文件尚不存在，回到有效来源，不伪造）。
3. 针对问题**按需读取原始仓库的具体文件**，优先精读少数真正相关的原文、数据与代码，而不是批量导入全部仓库。注意路径、版本、许可和上游文件之间的矛盾。
4. 证据不足时主动扩展仓库内的资料、真实案例或工具验证；不能只凭现有 15 张知识卡封闭研究范围。
5. 记录：原始问题、决策场景、已读文件路径及提交、直接证据与未确认事项。没有访问到原文就明确写“未核验原文”。

## 2. 在写作前先确定“真正的问题”

把宽泛主题压缩成一个能产生专业分歧的问题，不必生硬套模板。

例如“钱包分析”太宽；优先问：“某钱包在链上有历史盈利时，其收益有多大部分是其他观察者在发现后还能复制的？”

确定它时检查：
- **对象**：钱包地址、经济实体、账户簇、代币、池子、交易事件还是信号？
- **情境**：发行初期、迁移后、薄流动性、第二波、风险崩塌，还是跨事件长期行为？
- **问题性质**：解释过去、预测未来、判定机制，还是计算执行净期望？
- **时间界限**：创建、交易、确认、供应商获取、Bot 可见、决定、模拟成交、退出分别是什么时候？
- **最易错的跳跃**：哪个熟悉结论看似顺理成章，却尚缺关键因果或经济证据？

**写作从问题的张力开始，不从术语百科开始。** 若用户明确要求全景，则先给足够广的专业地图，再选一处有价值的机制纵向钻透；不把地图误充成果。

## 3. 原文“吃透”至少要跨越四层

**理解作者说了什么：** 识别概念定义、单位、适用市场、隐含假设、参数、具体算法、引用事实和结论所依赖的数据。

**理解为何这样说：** 还原交易主体的约束、资本动机、风险暴露、市场反馈及可能的因果路径。不要以“庄家有意”代替机制解释。

**理解它何处可能不成立：** 对照不同仓库、不同市场阶段、样本缺失、共享基础设施、信息延迟、外推范围和反例。优先找能推翻叙事而不是补强叙事的证据。

**理解能否发生知识迁移：** 判断这个模型在 Solana 实际运行条件下哪些是一般机制、哪些是平台实现、哪些只适用于历史样本；最终能否映射为观测特征、可检验命题或仅作为开放思路。

不能把“阅读到理论文档”写成“证明了理论”；也不能只摘关键词就声称“已吃透”。

### 对每条关键主张留下简短来源账

- **出处**：仓库/文件/提交或具体链上签名；
- **原作者主张**：作者实际说的是什么；
- **我们观察到的证据**：能独立核验到哪一层；
- **扩展解释**：我们的推断如何超出原文；
- **竞争解释**：哪些事实可令两种解释分离；
- **可迁移性**：适用/不适用及缺口。

来源摘录和我们新提出的思想必须分开。专业写作要产生增量观点，不要改写原作者段落充数。

## 4. 跨项目机制重构：执行“深度推演”而不是文件拼贴

根据研究问题灵活选择以下认知动作，不要求每篇文章写满每一项：

1. **概念拆核**：一个名词实际上代表了什么可观测对象？如“聪明钱”可拆成平台标签、历史账面结果、执行角色、可复制优势。
2. **本体分离**：地址 ≠ 实际操作者 ≠ 经济受益者 ≠ 担风险的实体；价格形态 ≠ 控制权；资金流 ≠ 信息流。
3. **机制重建**：从行为产生过程写出“谁在何种约束下做了什么、为什么会产生这组可观察痕迹”。包括激励、库存、流动性、策略竞争与反身性。
4. **竞争模型**：提出两个以上解释并说明各自独特预测，而不是形式化列出“也可能是其他原因”。
5. **逆向追问**：如果观察事实全部正确但结论依然错误，最可能是哪条桥梁断了？共享交易所、同步公开信号、幸存者偏差、数据时间错位、币池迁移、可执行性缺失？
6. **跨文献增量**：用 A 仓库的测量方法检验 B 仓库的语义机制，再用 C 仓库的反证程序挑战；写清它们之间是“支持/冲突/条件适用/互补/尚无联系”。
7. **新假设创造**：推演已有框架遗漏的机制，允许反直觉甚至与主策略方向相反，但要给出何种结果会推翻它。
8. **经济条件检验**：区分发现、解释、预测和可交易。考虑价格冲击、滑点、路由、优先费、延迟、实际持仓和退出深度。
9. **面向能力**：提炼 Grok 应学会回答的研究问题、调用的原始证据和拒绝误断的条件，不直接编造交易策略结论。

这些动作是扩展思路的工具箱，**不是禁止探索其他维度的唯一方法**。

## 5. 专业论述的写法：让读者看到“推理如何发生”

研究正文采用**主张—依据—机制—反例—新认识—应用含义**的自然推进；标题和顺序由问题本身决定。

- 开篇先回答“当前理解最重要的变化是什么”，不要写通用背景口号。
- 每个中心段落只推进一个可讨论的判断，并交代为什么；如果删去所有专有术语仍能套用于其他市场，该段落通常太空泛。
- 复杂概念由浅入深：先用本项目具体事件解释，再引入统计/微观结构术语与计算条件。
- 对看似矛盾的历史材料，不强行调和。先判断研究对象、时间、数据口径是否相同，再决定真矛盾或伪矛盾。
- 把**来源原结论、作者解释、本项目新假说、已经复算的事实**分别表述；在重要数字旁给出人群、分母、观测时间和单位。
- 至少在关键位置给出一个“如果是另一种机制，哪些可观测事实应当不同”的论证。
- 用真实候选样本展示证据链缺口；没有真实交易数据时用明确标注的思想实验，不将示意数字伪装为观测。
- 结尾交代**获得了哪项新认知、可以迁移到何处、什么尚未证明、下一步应该追查哪个最有区分力的事实**。可附一句短的认知引导词，不要强制冗长路线图。

### 反空洞写作检查

不合格：“通过多维度分析，构建钱包评分体系，提高专业水平。”  
合格方向：“把地址标签与可复制收益拆开：标签依赖平台对过去盈亏的归类，而跟单收益取决于信息何时可用、市场是否已经反应及跟单订单是否能实际成交。因此仅提高钱包历史胜率阈值，不足以提高复制策略净收益。”

不合格：“同源买入证明庄家控盘。”  
合格方向：“共享资助者是资金关联边，不是同一受益人的确认；若该资助者同时连接大量彼此无关的账户，原归因应被削弱，必须比较非公共基础设施上的重复共同路径和同步交易。”

## 6. 面向交易研究的时间与成本约束

如果文章声称“信号有领先性”或“可以跟随”，必须明示可观察时间链：

`交易发生/确认 → 索引器可得 → 平台推送可得 → 监控收到 → 决策 → 预计成交 → 可执行退出`

同一信号在不同环节可以具有完全不同的盈利意义。历史峰值价格不是可执行的退出价格；统计价格上升不等于可成交净收益。不得使用信号之后才产生的字段来解释信号当时的决策。

对经济论断，至少指出：参与资金规模、路径与流动性、价格冲击与滑点、费用、延迟、未成交、退出限制、缺失价位及实际收益口径。现阶段没有数据就给出**研究设计**，而非一组假定成功率。

## 7. 写作模式（按用户任务选择，不强迫固定格式）

- **深读模式**：一份文章/代码/样本，写出它的真实论证、隐含条件、未证明部分及可迁移知识。
- **跨源融合模式**：同一问题对照多个仓库，构建相互竞争、可被区分的市场机制。
- **机制专题模式**：以具体跟单问题纵向研究到底层约束、行为时序和经济后果。
- **反证模式**：专门攻击一个看似正确的模型，寻找最能使它失效的观察与基准。
- **案例复盘模式**：基于已留存原始交易/行情及时间，重构当时可知、事后出现、推断改变的全过程。
- **知识转化模式**：把通过审查的推断转为来源绑定的知识单元、研究契约或 Grok 观察需求；不擅自发布交易规则。

推荐的正文结构是“核心发现 → 机制深挖 → 反证 → 跨源新认识 → 在项目中的意义”；只在适用时使用。可以完全改写结构，只要推理链真实、清楚、可审查。

## 8. 从文章到 Grok 知识：有选择地转化

文章成果至少区分以下三种：
- **研究洞见**：有新的机制解释但未经实证，可进入开放研究记录；
- **可检验命题**：变量、样本、时间和关键反证已明示，可进入测试候选；
- **可运行知识**：有真实观测条件、有效性边界、复现和人工审查，可供 Bot 按需调用。

三者不等价。首次写出新假说，不应自动往 `knowledge/catalog.v1.json` 或 `rules/` 加入已验证结论。允许研究中暂时出现互相矛盾的候选解释，后续以证据淘汰。

与已有 Grok 系统的接口：`knowledge/method.md`、`knowledge/case-template.md`、`knowledge/source_index.v1.json`、`src/solana_meme_os/research.py`。任何运行时修改都应单独评估兼容性和测试。

## 9. 写作质量验收：用“专业认知增量”衡量

写完后自问：

1. 删除项目名和术语后，这篇文章是否仍像通用 AI 文章？如果是，回到原始场景重写。
2. 是否对至少一个实际参考文档做到了“定义、机制、限制、证据”级别的精读，而非目录摘录？
3. 是否出现至少一个**原材料没有直接提供、但能由跨源分析推导且可证伪的新认识**？
4. 是否真正比较了竞争机制，指出能区分它们的数据，而不只是笼统承认不确定？
5. 是否明确分离原始事实、平台解释、我们的推断和交易可得性？
6. 如果市场环境变化，这个认识的哪些部分会保留，哪些会失效？
7. 能否具体改变下一次 Grok 的研究提问、观测选择或错误拒绝？如果不能，说明知识尚未完成转化。
8. 关键主张能否追溯到文件及版本；未核查内容是否准确标识？

若不满足，修订对应论证段落，不要依靠补充更多框架标题或扩充知识词典来掩盖。

## 11. 交付与版本纪律

当用户要求产出专业研究文稿时，交付完整可读的原创研究文本及必要来源，不只给出提纲。写作前可先做高层计划，但必须推进到真实论证。跨源原创观点必须有清楚的推导理由；研究假设不得冒充原文结论。

写入 GitHub 时优先使用草案分支、来源路径和明确版本；不同主题按需产出文件，不机械创造空模板。重要 Skill 修改保留简短变更记录，并重新读取核查。禁止未获授权修改 `main`、`rules/`、交易接口或实际 Bot/Routine。

**持续写作的认知指令：** 深入原始机制，发现不同知识之间的真实联系；挑战熟悉解释，形成可反驳的新认识，并把有价值的部分转化为实际研究能力。
