## 1｜主专家必须从这个矛盾开始

> “我不是想知道价格涨了多少，而是想知道：**在何种池子与资产约束下，哪一笔买入改变了可交换储备，为什么后来者付出的真实价格不同，以及早期库存到底能从池里换走多少报价资产？**”

常见市场解释把“资金入场→价格上涨→赚钱”当成一句话。但它实际上包含三件独立的事：

1. **成交机制**：哪个程序以什么余额变化完成了交换；
2. **价格机制**：交易顺序、规模和费用怎样改变下一笔的可得报价；
3. **财富变现机制**：已经持有的 Token 在未来通过何种池/报价和对手承接能换回多少 SOL。

如果第三步不成立，第二步的高报价可能只代表账面价值。若第二步的价格上升来自薄池，不足以证明第一步包含了很多独立资本。

## 2｜专家向下追到的最小知识层

### 2.1 交易不是一个“buy_volume”标签

在 Solana 中要区分：Token Account 的余额变化、钱包的净 Token 风险、池 vault 中储备变化、LP 增减、发币/销毁和交易费。单一 Token transfer 不等于一次独立买卖，且一笔聚合 swap 可包含多段程序/转移。D01-K07/K08 应支持对事件类别的语义解释。

**要说明**：如果 A 给 B 转入 Token 而没有对池执行 swap，为什么 holder 分布可能变化，池价格未必由该转账直接改变？反过来，同一池的交易为何能够改变以后每一个交易者的可得交换比例？

### 2.2 先研究一个明确的价格模型，再研究模型失效

**第一层：理想化、无费传统 CPMM**。分别推导 X、Y 两种储备，以及固定报价资产投入 q 后取得多少 Token。区分买入前边际价格、交易过程中平均价格、交易后新边际价格。再从反方向推导固定 Token 数量卖回能拿到多少报价资产。明确即时完整反向交易在理想无费无其他交易环境中恢复原状态，避免把“买入造成价格冲击”错误解释为该理想模型必然产生即时往返损失。

**第二层：真实 CPMM 费用与储备会计**。核对具体程序版本与 fee buckets：LP所得交易费、协议费、可选创建者费如何计提；vault实际余额与用于定价的有效储备未必完全相同。来源优先 [Raydium CPMM Math](https://github.com/raydium-io/raydium-docs-v1/blob/main/products/cpmm/math.mdx) 与 [Fees](https://github.com/raydium-io/raydium-docs-v1/blob/main/products/cpmm/fees.mdx)。这些是具体文档的版本化解释，不自动推广到 Solana 所有DEX。

**第三层：虚拟储备发币曲线与迁移**。研究真实可提出报价资产与虚拟定价参数的区别；不同曲线类型可能形成不同价格路径，曲线迁移后的池又改变报价条件。来源先读 [Raydium LaunchLab curve](https://github.com/raydium-io/raydium-docs-v1/blob/main/products/launchlab/bonding-curve.mdx)；其它发行平台需独立按版本核对，不以“Pump-style”一词统一全部实现。

**第四层：不同流动性安排**。再向 CLMM / DLMM / 多池路由扩展：有效流动性随价格区间/分箱改变，因此不能无限外推 CPMM `x*y=k`；池价差是否会被套利压平，取决于费用、冲击和套利可用路径。

### 2.3 真正的价格研究必须和卖出方向相连

需要同时区分：

- **买入增量成本**：固定 SOL 预算在某交易后能多拿或少拿多少 Token；
- **卖出净可得额**：固定 Token 仓位在某交易/LP状态下能换回多少 SOL；
- **账面市值**：按某个价格乘供应或持仓数量，不是池子承诺支付的现金；
- **LP 权利和流动性**：池 vault 中资产与 Token 持有人的自由库存不是同类权益。

明确模型讨论的是报价，而非保证可执行 fill；真实延迟、priority费、tip、Token-2022约束、路由错误属于执行阶段的其他机制。

## 2026-11-09｜纯知识转化：成本锚与观察时点（不把 K 线当链上身份）

> 原知识：[meme- AVWAP 锚点选择](https://github.com/sunshihao001/meme-/blob/main/06_资料吸收/资料吸收_AVWAP锚点选择_v0.1.md)（blob 8f5b48ee7b9fe11762cf4a84e8c02fe0fbf6bee5）、[Accumulation Range/第一控盘区](https://github.com/sunshihao001/meme-/blob/main/06_资料吸收/资料吸收_AccumulationRange_第一控盘区_v0.1.md)（blob 4b89d573cfe7a5f16d8982b82904bc07f5863324）、[meme- 反证实验](https://github.com/sunshihao001/meme-/blob/main/09_规则与回测/反证实验设计_v0.1.md)。本节既保存有价值的理论关系，也明确原知识的代理/事后偏差，不要求以图表取代本项目链上研究。

### 价格“成本锚”到底在测什么？

一个按所选时间点起算的成交量加权均价（AVWAP），描述的是**被选择的市场窗口中、按成交量加权的公开成交价格平均值**，并不能直接告诉我们某个地址/实体实际购买了多少、后续转给谁、成本是否经跨池换仓和手续费调整。价格分布的 POC/Value Area 同样是公开交易活动的统计描述，**不是特定操盘主体真实成本账本**。

原meme-明确提出 ZoneStart（早期区间起点）、ImpulseStart（首次拉升起点）、Reclaim（重新回收）、PullbackLow（回落低点）四种锚点。其有价值的知识在于：**参照点的选择本身是研究假设，不能把多个锚点的不同结论当噪声抹平**。不同锚点可能对应不同时间段参与者的交易成本代理，但不自动代表四类真实经济主体。“多锚点共振更可靠”也需要独立性与样本外测试：锚点之间共享成交序列，信号天然高度相关。

### 事前识别与事后解释是两个不同知识命题

原meme-在“第一控盘区”定义里要求**后续第一波有效拉升**确认早期横盘的意义。它适合作为**事后市场阶段归档候选**，不能在拉升发生前声称已识别“确认控盘区”。否则会把未来信息泄漏到当时的判断中。

研究时至少要区分：
- **事前（t时可见）**：价格/成交聚集、池流动性、Owner与库存轨迹、在t时真实取得的来源版本，输出“可能的早期成本聚集区域/待证”。
- **事后（t之后才知）**：拉升、回撤、回收后的阶段重述，仅用于检验以前的判断并研究失败条件，不能回写当时的输入与触发状态。
- **因果机制解释**：上涨可能来自新资金的风险承接、薄池价格冲击、流动性变化、套利/多池迁移或人为重复交易；“后来上涨”不提供特定控制者身份的充分证据。

### 从纯理论到 Blix 的跨域新问题（不必立即开发图表）

如果某个早期区间的价格基准多次被尊重，但链上追踪的候选群体已将大量 Token 转移到接收钱包，那么 **“价格区间稳定”与“原地址库存稳定”可能发生背离**。这是值得研究的新矛盾：
1. 相同Mint的历史Swap/Transfer/LP事件，在事件时点上有什么可追踪对价与库存变动？
2. 市场价格锚是否只是多群体共同反应/自证预测，而非某个主控人的成本？是否跨池出现完全不同的成本代理？
3. 时间窗口固定前后，此解释是否仍然成立？失败和未触发的Token是不是也进入了分母？

**专业结论**：保留meme-关于市场阶段与成本锚的概念深度，但将“控盘”、“吸筹”、“庄家成本线”视作需要链上库存/交易/行为反证的**经济解释候选**。该知识可进入理论研究、调查问题生成和历史反证，即使Blix不做以K线为主的信号交易。没有独立实证证明某锚点稳定、策略能盈利或该机制普遍存在。


## 2026-11-09｜保留旧meme-的完整事件顺序知识，而不是只留下Spring/LPS标签

**原文**：[meme-术语的工作定义与误判清单](https://github.com/sunshihao001/meme-/blob/main/03_语义概念/核心术语表_v0.1.md)（blob `e3bd45a8fe32ac8b17f2ce5ff6f7e5fe606b0b50`），[Spring/Test/SOS/LPS吸收记录](https://github.com/sunshihao001/meme-/blob/main/06_资料吸收/资料吸收_Wyckoff_Spring_Test_LPS_v0.1.md)（blob `365d67bcc9762142d0f5e7f1c5e57583a9c371ed`），[结构风险评分工作框架](https://github.com/sunshihao001/meme-/blob/main/04_风险管理/结构风险评分模型_v0.1.md)（blob `d8cc71a1bfc3535bf34789b05bd0e40fb07ef58b`），[策略成熟度自我质疑](https://github.com/sunshihao001/meme-/blob/main/09_规则与回测/策略成熟度质疑审计与商业诊断_v0.1.md)。这些是研究假说和借用经典框架的方法，不是已验证的操盘人行为或交易策略。

**纯知识核心不是价格形态名单，而是序列与上下文依赖**。Spring、SOS、LPS等概念的语义依赖先前区间是否存在、该区间定义何时冻结、事件是否按先后发生、后续回撤是否出现。孤立的跌破/上涨/回撤既可能是这些阶段的候选，也可能只是薄池冲击、套利、LP变化、真实独立买盘和卖盘。把名称从meme-复制到Blix如果丢失序列，就把动态机制研究退化成静态标签。

研究时分清三种时间：
- **事件本身的链上/市场时间**：成交、价格、池状态、Token转移有事件时点/Slot。
- **定义在当时是否已经可得**：某区间、AVWAP锚点、阶段阈值能否在t时固定，还是后来看到“拉升成功”才回头标注。事后才能成立的阶段只能用于历史解释。
