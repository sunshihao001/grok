# L4–L5｜Solana Meme 跟单优势、策略路径与真实交易成本

> 对应 D08（交易策略与 Alpha）和 D09（执行与风险），依赖但不覆盖 D01–D07 的原始观察。本篇是**策略假设与可执行性知识**，不是盈利保证或已经通过 F4/F5 的规则。Phase 1 仅只读与纸面回放，不提供自动交易命令。

## 0｜首先明确“到底跟什么”

Meme 跟单至少存在五个不同目标：

1. **交易复制**：按钱包公开买卖动作复制同一 Mint、方向与仓位。
2. **钱包行为预警**：利用地址操作提前发现市场事件，未必买入同一币。
3. **结构性机会识别**：利用钱包群、资金与池子变化寻找后续仍可捕获的市场阶段。
4. **风险排除**：识别那些可能大涨却严重不可卖、集中或有重大权限风险的候选。
5. **观察/研究调度**：从跨币资金和行为中发现下一步值得调查的币，不承诺产生交易机会。

这五个目标必须有不同的证据和评价指标。**钱包赚到钱、我们识别了它、我们能在后面赚钱，是三种不同命题。**

## D08｜跟单策略的内部知识

### D08-01｜钱包的历史利润是否真实、完整且可解释？

对于候选钱包，至少重建：

- **资金流与头寸**：初始 token 与 SOL 余额、所有 swap、转入转出、可见残余仓位、失败交易、是否发生跨地址转仓。
- **净收益**：已实现收益与未实现市值分开；按自有原始交易重建和平台 PnL 各保留一版，并记录差额。
- **盈利来源**：低价极早进入、市场趋势、专有消息、流动性提供、自动化套利、跟随市场总体上涨等均可能造成高 PnL；不能单看胜率推断“选择能力”。
- **策略持续性**：交易频率、持币时长、平均/分位收益、极端亏损、最近与历史阶段、跨币/跨时间样本覆盖。
- **高偏差警告**：从排行榜挑最赚钱钱包再回测该钱包，会形成严重选择/幸存者偏差。

**钱包质量的正确报告**：历史表现、来源覆盖、可解释行为、跟单可见差距、真实不可复制条件分别列出，不合成“最强钱包”一个分数。

### D08-02｜钱包领先优势能否成为跟随者优势？

定义几个独立时点：

`T_wallet_event` → `T_provider_receive` → `T_decode` → `T_signal` → `T_quote` → `T_hypothetical_fill`。

对于每条信号，评价：

- **可观测性**：提供者在 T_signal 前是否真的已给出钱包和 Mint 信息？是否是历史回填？
- **时间衰减**：从原钱包买入到我方能询价，价格变化、池储备变化、剩余买方需求如何？
- **复制误差**：我们能否识别其真正成交方向和币种？目标是否已经迁移池子？是否被许多跟随者同时追赶？
- **容量**：给定我方仓位与其他竞争订单，买入冲击和卖出冲击有多大？
- **退出差异**：原钱包或许有多地址、分批离场及流量优势；我们的退出触发是否在可见信息下成立？

**核心指标应该分为两条**：`wallet_realized_net_result` 与 `follower_asof_net_result`。两者的差额才是复制损失的直接研究对象；没有报价或真实成交时必须将结果标为估算而非已兑现。

### D08-03｜不同的钱包行为，可能对应完全不同的策略家族

| 策略家族 | 观察线索 | 真正要检验的问题 | 常见失败 |
|---|---|---|---|
| A. 首买/狙击跟随 | 极早进入、快速重复交易 | 我方首次发现时是否已太迟？ | 原钱包有时间优势，信号过后价格被吸收 |
| B. 多钱包协调出现 | 同窗口共同买入、相似资金路径 | 这比普通 launch 时同步买入多提供什么信息？ | 公共 HUB、交易服务与共同市场事件 |
| C. 独立资金后续承接 | 已识别群组卖出时出现另一批净买方 | 是否存在可事前确认的第二阶段需求？ | 换地址、刷量、价格反弹但无真实深度 |
| D. 跨币重复参与 | 地址/资金组在多枚币重新参与 | 是否比一般市场热度更早确定下一 Mint？ | 只能猜到“可能再次活跃”，无法选出币 |
| E. 结构回收/二次启动 | 阶段价格与持仓变化、成本锚回收 | 条件能否事前固定、胜过简单突破或 VWAP？ | 事后画线、死亡盘反抽、低流动性假象 |
| F. 风险过滤 | 权限、深度、筹码异常、不可卖报价 | 是否在相同机会/资金预算下提高风险调整后结果？ | 仅靠少交易减少亏损、漏掉大量有效机会 |

**这些都是研究路径，而不是已成立的策略。** 一条路径失败，不等于其他路径不存在优势；反之亦然。

### D08-04｜策略的触发、失效、停止是三个不同定义

每条候选策略要有明确、事先冻结的：

`eligible_universe`、`observation_trigger`、`required_features`、`decision_cutoff`、`entry_quote_window`、`exit_rule`、`hard_veto`、`no_signal_reason`、`censor_reason`。

- **触发**：当时已经看到的特征成立。
- **失效**：当时确定的机制条件被破坏，例如池子停用、卖出路线消失、数据变迟、识别的主体关系无效。
- **停止研究/发布**：无法获得事前输入、该策略没有可卖报价、外部样本不支持增量或来源条件变化。
- **不能做的事**：事后调换触发点或成本锚，使失败交易被改写为“其实没触发”。

### D08-05｜新机会可以来自不复制原钱包的行为

这是应该重点保留的研究自由度：当原钱包首买不可复制，不必只研究如何更快追它；还可以研究后续独立承接、群组退出与市场清算、风险不对称、开发者反复行动、流动性阶段切换后的新机会。

但每种新机制仍需证明：**当时可看见 → 比简单基准有信息增量 → 扣成本后仍可能被实现**。不能因为换了故事，就继承旧钱包的收益。

## D09｜执行知识：从“信号好”到“跟随者能实现”

### D09-01｜真实成本账本

以单笔纸面回放（不是实盘交易）为单位：

`estimated_net_pnl = exit_proceeds - entry_cost - all_fees - priority_fees - tips - other_measured_costs`。

所有金额必须统一到同一种记账单位，区别 raw token 数量、SOL 与 USD 估值；避免将报价造成的冲击重复记费。保留用于观察的 quote 时间、原始 JSON、路线、资产 decimals 和失败原因。

- **买入**：使用真实时点可取得的买入 quote 和目标仓位；不能套用原钱包成交价。
- **卖出**：预定退出时点必须取得对应方向、对应仓位的卖出 quote；不存在有效路线即标为 `EXIT_ROUTE_UNAVAILABLE`，不能用 K 线的收盘价代替。
- **费用**：基础交易费、可选 priority fee、tip、路由费和失败成本分别建模，不假定未来始终固定。
- **持仓**：未退出、部分退出、转账、余额不足、执行时间超限都需要明确结局状态。

### D09-02｜跟单者执行问题的四个量

1. **决策延迟**：原钱包成交到本监控真实拿到有效信号之间的间隔及分布。
2. **边际价格冲击**：给定金额在可见池状态下能换回多少资产，而非仅报滑点百分比。
3. **尾部退出能力**：价格快速下跌时能否获得卖出路线、残余 SOL 深度与成交确认。
4. **机会容量与并发**：同一时间多个新币或钱包同时触发时，资金能否分配；同一行情多次重复报警不得视作独立机会。

### D09-03｜风险过滤与机会成本

拒绝某类高风险 token 可能减少单笔亏损，但不自动提高所有资金的净期望。必须同时比较：机会覆盖率、每机会净结果、资金占用、尾部损失、跳过成功行情的机会成本，以及与简单流动性/年龄过滤的差异。

### D09-04｜钱包评分应当避免混成万能分数

建议仅做并列的诊断面板：

- `behavior_consistency`：该钱包策略节奏是否稳定，偏差/覆盖未知时不评分。
- `earliest_visible_lag`：与我方提供者的可见差距。
- `position_overlap`：历史买入时点后是否还有重叠窗口。
- `two_sided_quote_coverage`：当时进入和退出双向路线是否可得。
- `follower_net_outcome`：按事前协议、仓位与成本得到的收益分布。
- `regime_sensitivity`：在不同发行阶段、行情/来源条件下是否变化。

先保留每维度原始分母、缺失和分布，**没有独立验证时不要合成 0–100 的“跟单可买评分”**。

## 正确的应用示例（纯假设）

钱包 W 在新币可交易初期买入，历史账户显示其最终赚了不少。系统在钱包买入后数秒才收到信号。

**错误处理**：“W 胜率高，立即给这个币 WATCH/可以买。”

**正确处理**：

1. D04 证实这是一笔 swap 而不是转仓，净买入金额和方向正确。
2. D02/D03 判断当时处于哪种池/曲线市场，识别真实钱包成交后价格变化。
3. D08 测量我方 `T_signal` 和当时可见的双侧报价；若没有，记下不可复制的原因。
4. D09 对该仓位和计划退出方式进行纸面估算，包含失败/未成交的分布。
5. D11 比较同阶段没有 W 的普通候选，以及较弱、失败和未入选钱包样本。
6. 不能因为 W 自己赚了钱，就把系统监控阈值升级为盈利规则。
