## 一｜从“谁是这个钱包”转成“谁有哪种权力、承担什么经济后果”

Solana 的单一地址并不能直接代表一个交易者或经济组织。至少需要区别：

1. **账户层**：Mint 地址（Token 种类与供给元数据）、Token Account（特定 Mint 的持仓容器）、ATA（一个 owner+mint+token program 组合的标准派生 Token Account）、SOL 系统账户、AMM 的 vault、PDA；同一 owner 可以为同一 Mint 持有多个非 ATA Token Account。
2. **密码学权限层**：transaction signer、fee payer、Token Account owner/authority、delegate、Token-2022 permanent delegate、mint/freeze authority、PDA 可由哪个程序 `invoke_signed` 授权。它们并不等价。支付 ATA 初始化租金的 payer 可与 Token Account 的 owner 不同；拥有转账授权者并不必然是经济受益人。
3. **业务操作层**：负责发币的用户、托管平台、机器人服务商、路由器、头寸管理者、钱包代管代理、LP 操作者。可以由不同地址组合承担，也可能同一地址跨 Mint 变角色。
4. **经济权属层**：谁出资，谁享受剩余收益，谁承担亏损，谁能决定资金如何退出。这是最需要研究的对象，却不是 token-account `owner` 字段的同义词。

**协议事实**：Token Account 存储 `mint/owner/amount/delegate`；Token Program 或 Token-2022 才是该账户的 program owner。ATA 只是标准地址。PDA 没有对应私钥，使用调用程序和签名种子授权 CPI。Token-2022 还可以有 permanent delegate 或 transfer hook，可能直接改变转出能力（见后列 Solana 官方技术文档）。

**研究推论**：同一经济主体能拥有许多地址；许多真实经济主体也可能共同使用一个托管地址；一个地址由程序或服务方操作时，能观察到“执行权限”却未必知道“盈亏归属”。因此，把 holder_count、Top10、`native_transfer_from`、签名者、fee payer 或创建者字段中的任意一个直接当“庄家人数”会犯对象级别错误。

研究对象不应该是静态函数 `role(address)`，而是 `role(address, mint, market_stage, interval, observed_authority)`。一个“早期买家”地址可能同时是其他币的分发地址；类似“dev”只是涉及角色的关系，不是天然的全局身份。

## 二｜一条链上关系能证明什么？先分别建立不同语义

### 2.1 资金转移关系 F

`F(A→B, asset, amount, signature, instruction_index, slot)` 只说明观察到特定指令导致资产从 A 指向 B 的余额转移。实际重建应依据完整指令、可能的 CPI 和 pre/post 余额；把某个钱包当交易对手之前还需排除池 vault、账户租金、Wrapped SOL 包装/解包、Token 关联账户初始化、Token-2022 转账费、失败交易。

**不能由此直接证明**：A 与 B 同一人、B 受 A 控制、是投资还是工资/退款、这是新买盘、A/B 共同承担市场风险。

### 2.2 密码学或程序控制关系 C

`C(subject, capability, target_account, scope, interval)` 记录谁有何种权限：transaction signer、Token Account owner、delegate allowance、特定 Mint 的永久委托、程序派生地址的授权程序等。

可以由协议账户状态和交易签名在某时点直接核实部分权限；但签名证明授权消息，并不表明签名地址背后的现实受益所有人或资金决策者。多签、托管与服务端签名使这一差距更明显。

### 2.3 行为相关关系 B

`B(A,B | event_context, mint, time_window, behavior)` 指两个地址表现出相近入场、成本、持仓、退出或多币参与模式。相关不是控制；在新币公开开盘或关注度集中时，共同驱动因素可以使互不相关的地址同步。

### 2.4 净经济风险关系 E

`E(actor_candidate, inventory, quote_asset_exposure, PnL_rights?, disposal_rights?, time)` 区分经济头寸、资产承担与收益归属。库存和 quote asset 收支可以做会计上的候选重建；`PnL_rights` 和实际受益人一般不能仅凭链上数据确证。

### 2.5 信息协同关系 I

`I(A,B,event,signal_context,availability)` 表示研究人员怀疑多个策略受相同交易信号、社交事件、交易机器人服务或内部协同信息影响。需要比较**共同公开事件**与真正特异的重复顺序，而非把相近 blockTime 直接看成秘密交流。

**关键结论**：F、C、B、E、I 是不同问题。不能以“同一 funding + 同一成本 + 同一时间”在没有排除共同背景时自动升级为“同一主体”。

## 三｜旧同源聚类的根本盲点：可能根本无法识别

设钱包 A、B、C 都从 X 收到 SOL，且在某个 Mint 开盘后的很短时间相似价格买入。

至少存在三个竞争世界：
- **世界 U（统一控制）**：X 为某个主体的钱包组补款，主体使用多个执行钱包。
- **世界 S（共享服务）**：X 是大规模交易服务/托管/公共资金中转，A/B/C 为独立客户，他们响应相同公开开盘。
- **世界 R（机器人服务）**：不同客户雇用同一自动化服务商，时间同步来自程序或统一信号，但资产风险归客户承担。

在只观察 `funding_source + entry_time + avg_cost` 的情况下，三个世界**可能产生完全相同的数据**。不是“模型不够复杂”，而是现有观测变量对经济实控关系没有足够的辨识力。增加基于同一数据生成的排行榜标签或更多线性指标不会自动解决这个问题。

旧研究 `00d-GMGN-多维度推理扩展.txt` 中“同源+同成本+同时间 = 极高概率同一实体”的跳跃应作废；保留三类关联为候选观察。旧 `Skill 04` 把共同资金地址连接多个钱包作为“疑似控制人”，其实更合理的输出是 `funder_links_n_wallets`，而非 `verified_controller`。旧代码的固定 `0.8 - 0.1×缺口` 也不是已校准的经济主体后验概率。

由此可得**资金关联研究的思维纪律**：

1. 对每条共享资金边，先问它属于私有出资者、共享服务，还是类型未知。
2. 对同步交易，先问哪些公开事件/同一路由使多个独立主体必然接近。
3. 仅剩的无法由共同事件解释的**独特重复关系**，才可能提高统一操作解释的相对支持。
4. 高可疑关联强度仍只是一种机制解释，不会自动得到私人法律身份或经济受益人。

可以写理论上的相对解释支持：
`LR = P(observations | coordinated operator, context) / P(observations | independent service users, context)`。
分母必须包含“共同开盘与公共服务”背景，不能随意把多个高度相关的特征概率相乘。**没有实际校准就不能给 LR 一个数字，也不能把它显示成“90%同控概率”。**

## 四｜公共枢纽不是简单的噪声：它决定了资金图的信息量

同一个上游节点 X 服务很多下游地址时，它所连接的数量越大，“A 与 B 都连接 X”对两者共同控制的辨别能力可能越弱。这与一些小型私有资金节点相反。

应当研究的不是“是否同源”这个布尔量，而是：
- X 的**服务性质**：CEX 充值/提现、托管归集、公共路由/机器人服务、支付/手续费代付、AMM 池 vault、无标签未知地址。
- X 的**分发模式**：上游是否由大量不同用户入金，是否向众多不相关 Mint 的交易者付款，还是局限于少数钱包。
- X 的**独立重复性**：在不同公开事件、不同 Mint 上，同一组下游地址是否维持独特的资金与库存关系。
- X 的**后续净经济路径**：A/B/C 的卖出回款是否进入共同私有地址，但不能忽略正常托管结算。
- **对手方边界**：资金进入交易所或托管账户后，公开链上不再展示平台内部的账户与资金权属；不能跨这一缺口假装继续逐笔追踪原资金。

重要的是不要机械删除所有 HUB：服务商集中分发本身可以是市场活动的一个重要主题，但它对**判断同一受益人**通常不是强证据。相同图边对不同研究问题的信息价值可能完全不同。

## 五｜交易不是转账的同义词；交易量不是主体数的同义词

一个 AMM swap 可能包含多次内部 Token Transfer、路由转账、WSOL 包装/解包、费用支付，甚至跨池路径。以 Token Account 层原始 transfer 次数直接计算“买方人数”“卖方人数”将出现多重计数。

正确的研究定义应区分：
- **资金移动**：token 在账户间转移，可能是内部调仓，通常不必有价格发现。
- **主动交换**：一个策略发出资产交换请求，由池/路径执行，产生实际两侧资产流与费用。
- **流动性操作**：LP 增减和 vault 余额变化，它改变可成交深度，不等价于现货买入。
- **净库存变化**：对于有充分证据可合并的账户组，在同一 Mint、同一时间窗汇总余额变动；内部转账会抵消，但 Mint/burn、transfer fee、桥接/托管缺口与外部池操作仍需拆分。
- **经济交易盈亏**：需区分 token 库存变动、出售所得 quote asset、成本基础与尚未实现的库存价值，不能把 swap 的累计 volume 直接当净资本流入。

概念关系：`gross_volume >> net_position_change` **可能**来自高频双向换手、套利或自相关成交，也可能来自真实不同交易者交易活跃。这个不等式本身不能证明 wash trading。

更深一层：通过 AMM 自买自卖不是两个地址像撮合盘那样直接互为买卖对手。AMM 池是合约对手方；要研究“同一经济主体制造交易量”，需要考虑同一经济受益人是否承受了两方向的风险、最终库存是否回到原点、费用与价格冲击由谁承担。简单地发现“反复买卖”仍不能区分做市/套利/机器人策略与人为刷量。

## 六｜经济主体的跨 Mint 生命周期：从“相似地址”走向“资本约束”

旧研究将资金循环描绘成“X 币退出→Y 币买入”，值得深入，但同时必须满足资金可用性。

令同一**已知**钱包集合在时点 t 持有 quote asset 的可支配余额为 `Q(t)`，时段内可以观察的外部净入金为 `F_in`，已确认的卖出所得为 `S_realized`，已确认的买入、提现及网络/交易费用总支出分别为 `B, F_out, C`：

`Q(t2) = Q(t1) + F_in + S_realized - B - F_out - C + adjustments`。

其中 `adjustments` 必须显式说明包装/解包、退款、账本范围外的资产、被忽略的账户或其他来源；这个等式是按相同计价资产和同一已知账户集合计算的**会计检查**，不是经济身份识别公式。

它带来的认知转变：如果假设一个钱包团伙“卖掉旧币，立刻用同一笔 SOL 进下一币”，就必须解释换回来的 quote asset 是否真正经过可见路径到达下一个买入账户。如果观察到的资金不足，该机制解释可能被排除；但若资金穿过 CEX 等链上不可追踪内部系统，结论应降为 UNKNOWN，而非强行连续串起。

由此形成几个候选经济机制（**都未验证具有预测优势**）：
1. **库存接力**：一组地址持有 token，另一些地址在接管公开买盘或流动性后承担退出；需要观察库存和收益归属，而非只看谁先买。
2. **执行服务型同步**：多个账户遵循同一 bot/路由时间约束，形成“团伙同步”外观，但资金与收益不一定合并。
3. **资本再部署**：部分已实现 quote 收益被转为下一 Mint 仓位；需考察相同账户组的余额可行性、重新出资顺序和外部来源。
4. **注意力同步**：多个地址受共同社交或公开开盘事件驱动，资金路径无真正协调；同样可造成时间/价格趋同。
5. **托管错位**：可见 token holder 地址背后的经济受益人为多人；地址集中度高而实际受益人未必集中。
6. **权限错位**：操作权限或 delegate 集中但经济库存分散；“谁能转出”与“谁最终获利”并非一个维度。

这些机制之间不一定互斥，不能将一切现象强行塞进“庄家吸筹/出货”一个解释中。

## 七｜三种“控制”必须分开，否则筹码知识永远混乱

**协议控制**：拥有 Mint/freeze/delegate/token-account authority，能在授权范围内改变供应或转出状态。Token-2022 permanent delegate 的能力尤其不能用传统 Token Program 的“只有 owner 能转账”来概括。

**库存控制**：候选主体可调度的 token 数量、锁仓、托管余额或 LP 仓位。它依赖可调整的账户群组假设、合法可转移性、池 vault 排除。

**价格影响能力**：在给定池深度、时间和可用外部买盘下，主体通过合法买卖产生价格冲击的能力。少量自由流通、薄池和高度不对称的报价可以让较小净资金形成较大价格变化；这既不能自动证明幕后统一控制，也不能证明主体具有可盈利的退出路径。

重要推论：`Top10持仓集中度`、`疑似同源组持仓`、`有权操作余额`、`对价格的实际影响` 均是不同度量。它们不能相互替代，也不能相加构成一个未经定义的“控盘分”。

对于同一 Mint，固定账户类别和供应分母尤其重要。池 vault、托管、销毁地址、授权可转出的持仓与普通持仓混在 Top10 中，会让静态集中度失去经济含义。

## 八｜原有“同步=协调”“捆绑=同控”两个典型陷阱

**同步交易**存在共同时间原因：公开 launchpad 开盘、交易工具的同一观察更新、共享机器人服务、同一 X/Telegram 信号、市场冲击或套利机会。比较同一 slot 或相近秒数的买入，不足以单独确认私下协调。

**Jito bundle** 是一种可将多笔有序交易提交为同一 slot 内原子执行序列的技术机制；官方文档中 bundle 的“原子性”说的是这些交易共同执行的方式，不等于所有签名钱包属于一个受益人。反过来，同一 slot 的多笔交易也不必来自已确认的同一个 bundle。

专业专家应把“交易组合方式”“执行服务”“经济控制”分开。这能防止将技术术语 bundler/sniper/MEV 误当同一种组织身份。

## 九｜钱包的“聪明”来自何处？必须区分五种优势

将“聪明钱”当永久标签会掩盖不同利润来源：
1. **信息先见**：策略在公开可见前或早于大众获得有效信号；需区分合法公开信息速度、私有渠道和无法观察的来源，不能武断归因内幕。
2. **执行排序**：相同信息下，通过监测、优先费用、交易路由、打包等更快取得成交。原钱包的收益往往具有很强的时间排他性。
3. **市场选择**：只参与少数具有特殊生命周期/流动性条件的 Mint；看似“钱包能力”部分来自选择何时不交易。
4. **库存与资本容量**：能承受较长锁仓/回撤或提供流动性；小规模跟随者没有相同资金约束，也不必具备同一优势。
5. **退出与风险控制**：长尾亏损有限、盈利迅速兑现或动态缩仓；跟随者若只观察买入，不观察退出条件，复制到的是残缺策略。

**新推导：最佳观察钱包未必是最值得跟随的钱包。** 极速首发钱包可能有较高原始收益，却在跟随者能观察到时已完成大部分价格发现；某些较慢、持仓时间更长、交易发生后剩余行情更长的策略，理论上反而可能保留更多可复制的信息价值。这里只是机制推论，没有比较其现实净收益。

研究应先分清 `original_wallet_edge`、`observable_signal_edge`、`follower_net_edge`，不能从第一个自动跳到第三个。

## 十｜五个可继续深化的专家级研究命题

**命题 H1：共享基础设施能够制造“团伙假象”。**
- 机制：共用 CEX/机器人服务→入金和时间相近→简单钱包聚类错误归并。
- 可解释：为何同源+同买同时存在却没有共同经济控制。
- 反面：非公共资金闭环与跨事件独特库存/退出序列能提高统一操作解释的相对支持。
- 研究状态：机制合理，具体普遍性未知。

**命题 H2：资金复用和信息复用是两种不同的跨币现象。**
- 机制：相同地址/集团在多币轮动不等于同一笔 SOL 反复使用；不同地址也可独立响应同一社交信号。
- 推论：跨 Mint 时序相似性需要与可解释的 quote 余额变化分离。
- 研究状态：概念区分成立，预测价值未知。

**命题 H3：经济集中度既可能比地址集中度高，也可能低。**
- 高的路径：一个实控者分散持有多账户。
- 低的路径：托管/服务地址归集多名独立受益人的资产。
- 推论：地址 HHI 不提供经济 HHI 的单向可靠上下界，除非已证明额外主体关系与托管分配。
- 研究状态：由多对一/一对多账户关系逻辑推得，具体市场规模未知。

**命题 H4：成交活跃与筹码真正易手可以脱钩。**
- 机制：同一或相关策略频繁双向交换，或独立套利者往返交易，累计 volume 很高而净持仓转移不大。
- 推论：高成交不自动指向真实新资金持续吸筹，也不自动是恶意 wash。
- 研究状态：微观结构解释，真实程度未知。

**命题 H5：钱包标签本身会影响后来者行为，可能削弱可复制性。**
- 机制：公开智能钱包标签→监控者同时跟入→价格冲击集中、抢先成交、原钱包退出环境变化。
- 推论：被发现的“聪明钱”质量与被广泛复制后留下的收益可能出现反向关系，需区别反身性与市场普遍情绪。
- 研究状态：机制假说，未证明任何特定钱包/市场上成立。

## 十一｜五位 L3 专家如何真正分工（只是知识分配，不创建 Bot）

- **E-L3-01 钱包行为**：研究信息、执行、市场选择、库存和退出五种收益来源；不要把供应商 PnL、标签、钱包称号作为解释。
- **E-L3-02 资金溯源**：以 F/C/E 分层，追究“资金边”对经济主体主张到底提供何种增量，什么时候因公共 HUB 而失去区分力。
- **E-L3-03 筹码结构**：区分地址数量、可能主体数、可控制库存、实际可卖供应、协议/委托权限和价格影响能力。
- **E-L3-04 开发者历史**：分清 launchpad 工厂/程序创建、真正签名用户、Mint 管理权、提款对象和历史发行的重复经济联系。
- **E-L3-05 群体时序与轮动**：比较公开信息同步、执行服务同步、库存再部署；研究相同策略特征的稳定性和跨 Mint 的资金约束。
- **交叉边界**：E-L1-01 校验指令真实含义，E-L1-02 校验信息当时可见性，E-L2-02 校验池子/报价，E-L4-02 研究跟单信息衰减，E-L6-01 处理不同机制之间的不可区分问题。

这些是同一专业知识的不同认知问题，不是流水线、固定权重，也不是专家互相投票。

## 十二｜旧项目哪些思想保留，哪些必须纠偏

| 来源 | 真正应继承 | 必须纠偏 |
|---|---|---|
| Hermes `00b Canonical Bytes` | 字段范围、单位、对象及原始返回语义的重视 | 同名字段跨接口未必同一窗口或口径；供应商原始字段不是原始链上事实 |
| Hermes `00c 思维模型` | 市场机制→链上痕迹→字段组合→反面解释，原始/特征/结构分离 | “否定反面即肯定正面”的逻辑不足；条件层级不能生成真实概率或阈值 |
| Hermes `00d 多维度推理` | 同一市场数据从钱包/微观结构/生命周期/策略适配不同视角研究 | 同源+相近成本+同步不能直接推出同一个实体；旧数值阈值未经 Solana Meme 经济语境独立校准 |
| Hermes `00e 反推未知框架` | 异常驱动、对立机制、时间序列和不依赖已知概念发现新问题 | 80 字段任意配对不是知识发现本身；由同一分母和共同事件制造的伪模式需排除 |
| Hermes Skill 03/04 | 钱包角色与资金结构分开、池/CEX排除、保留警告与阻断 | `suspected_controller_wallets` 是主张而不是验证；固定置信分无统计校准 |
| meme- 多 Agent 方向 | 不把 FCZ 固定为全部市场的解释；容许不同领域独立反驳 | “专家”不是市场事实来源；不是谈判投票决定链上经济关系 |

**迁移限制**：本篇只研究知识，不迁移 Hermes 运行路径、旧 GMGN 付费接口，不使用后期 Why-Solana 报告的未经独立审计数字，不变更 Grok B07 生产规则。

## 十三｜研究结论与待拓展的专业问题

**相对确定（协议或逻辑）**：Token Account/ATA/authority/程序/交易转移是不同对象；签名权与受益权不必相同；资金边不天然表示共同实控；净资产变化、成交量、持有人和资本权属不是同一度量；多重共因让“字段越多=证据越强”不成立。

**理论推演（非经验规律）**：公共服务造成主体假象、经济权属与授权权力错位、跨币资本约束比简单地址同步更具有辨别力、超高原钱包收益可能伴随更短的跟单机会窗口。

**仍需 GPT 深入研究的方向（暂不以案例为前置）**：
1. 经不同发币平台、曲线与 AMM 市场阶段后，“资金与控制”关系怎样改变？
2. 托管、多签、委托、PDA 和交易执行服务在不同 wallet role 上怎样重叠？
3. 池 vault、LP、交易所托管和地址拆分怎样改变集中度、浮动供应、价格影响？
4. 如何从交易微观经济学区分“共同买入”“共同公开信息反应”“同一服务执行”？
5. 信息领先、执行领先、资金容量和市场选择这四类优势各有什么逻辑上的可复制性上限？
6. 用户支付给服务商的手续费与真实资本部署，为什么可能产生相似链上行为却完全不同的经济收益归属？
