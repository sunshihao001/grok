## 二、Hermes 00c / 00d / 00e：知识不是三份相同的“指标研究”

### 00c：从市场想知道的事实出发（意图正向）
重要对象可拆为：**问题表征 → 相关经济实体/动作 → 可观测的链上痕迹 → 供应商可见字段 → 聚合/分母/时间语义 → 候选解释 → 竞争解释 → 需要的新证据**。00c的“Raw/Feature/Structure”是有价值的分析边界，但Raw如果来自供应商，也只是**供应商返回的字段**而不必然是已经独立复算的经济事实。

00c把 `required/supporting/warning` 拆开，是强于加权打分的结构：某条件是**定义前提**，某条件只是支持，某证据可能推翻主张。需纠正其反证逻辑：缺少某种反例**不能逻辑上证明目标机制存在**；要把竞争机制的独有预测放进观察设计。比如“买入增加、价格不涨”兼容积累、派发时买盘被卖方吸收、做市服务、流动性增加和数据延迟。

### 00d：换研究维度，改变可观察对象与解释模型（多视角）
原文明确五种市场问题表征，最有价值的是**同一数据的再询问能力**：

| 研究切面 | 原文背后的专业问题 | 同样的观测可以如何被重新解释 |
|---|---|---|
| 市场结构 | 资金压力和价格如何变化？ | 交易量增加可能是真需求、反复自成交或薄池高周转，不是自动趋势 |
| 钱包角色演化 | 同一钱包跨时间/跨币怎样变？ | 初期参与钱包可以持有、分发、转仓、出货、代理执行，角色应随行为更新 |
| 微观结构 | 是真实订单流、池深还是外部报价推着价格走？ | K线形态不等于真实可成交性；AMM没有传统CEX挂单簿时不能把储备比当订单簿价差 |
| 资本/操作者生命周期 | 库存怎样集中、迁移、兑现或放弃？ | 同一形状也可能由普通交易者、CEX/LP路由、公共机器人、社交热度产生 |
| 策略/机会适用性 | 观察到模式能否及时发现并在成本后具有价值？ | 结构描述和未来可预测性/他人跟随可交易性必须分开验证 |

**新认识 A**：多视角不是把相同事实交给多个“专家”复述，而是每个视角提出一个会改变**研究对象、数据请求、反例集合**的独立问题。真正的专家“介入”应是问题需要额外信息时启用其原理，而非固定22位专家投票。

### 00e：从未解释的现象向上生成新机制（逆向）
保留原文六条探索入口的**原理**：无预设组合、异常对照、无标签聚类、对立假设、时间序列、跨链差异。应把“发现新模式”和“产生新机制结论”彻底分开。

- **未解释的差异**应保留为“异常观测/未知机制候选”，既不贴庄家标签，也不认定无价值。先保存Mint、slot、交易签名、钱包/Pool类型、数据源、采集时间、样本入选条件、上下文/阶段及反例；信息不完整时明确未知。
- **异常的竞争解释**：供给/需求、库存迁移、API/价格口径、CPI重复计算、公共设施代理、缓存与采样变化、外生叙事、真实新执行机制。提出能分别支持/反驳它们的进一步观测。
- **新机制的上升条件**：不同Mint和时间窗下重复；控制明显的选择/市场阶段偏差；足够的样本外观察；能解释经济动作而不仅是拟合K线；有可信数据覆盖。否则保持开放问题而不命名新规律。
- **可反向否证**：出现看似相同的形状却由不同经济过程造成的“异机制同表象”；出现同一种经济过程却有不同形状的“同机制异表象”。这是比贴标签更有价值的研究入口。

**新认识 B**：00c解决“知道要查什么”，00d解决“怎样换角度理解”，00e解决“怎样发现原先根本没想过要查什么”。三者互相校正，不应强制排成三个开发阶段：异常可以首先触发00e，再由00d寻找相关视角，由00c提出数据需求；也可以先以具体市场问题启发未知异常。

## 三、00e需要跨行业方法补强：发现未知≠证明规律

**统计学/金融实证视角**：
- 80个数值字段的无序两两配对有3160对；若进一步试比值、差、乘、变换、币龄、时间窗、不同目标及阈值，探索空间更大。即使全部是噪声，反复挑选“最大差异”也可能发现表面显著项。因此要保留探索试验次数、选择路径，并在不同币和未来时段冻结条件做样本外再检验。参见 [Bailey & López de Prado，Backtest Overfitting，Significance](https://academic.oup.com/jrssig/article/18/6/22/7038278)，[Chordia等，Anomalies and False Rejections，RFS](https://academic.oup.com/rfs/article-abstract/33/5/2134/5739455)。
- 00e建议“10个赚钱币对10个亏钱币”和“100币聚类后看结果”：作为探索性构思可以保留，**绝不能在事后选择标签/时间窗后把它宣称预测有效**。要先定义样本总体和入选规则，划分训练/验证/留出时间，记录失败组及未命名组。聚类形成的只是观测相似性，不是共同经济主体。
- 跨链差异的基准必须控制交易机制、发行模式、计价资产、数据源覆盖和时间段；无法同口径就只说明“观察不同”，不能推Solana独有机制。

**因果推理与经济学视角**：
- 像“早期钱包集中 + 放量横盘 + 后续拉升”，不能反推所有早期钱包均由同一资本控制。需要区分哪个对象承受风险、谁下单、谁提供流动性、谁获Token、谁后续变现及谁受益。
- “价格涨跌”是多参与者在给定池深/库存下的结果，不等于某人的意图。模型间争议可以转成可鉴别预测：例如如果是单一控制者，除同步交易外是否有跨币资金再部署、转仓/代付与出货闭环；如果是共享服务，是否有许多无关客户相同执行形状。

**数字取证/档案视角**：
- [NIST SP 800-86](https://csrc.nist.gov/pubs/sp/800/86/final)提供跨数据源收集、检验、分析与报告的调查原则；[W3C PROV-O](https://www.w3.org/TR/prov-o/)区分资料实体、生成活动和责任主体。这些可启发Blix**保留观测怎样从原始交易/供应商快照得到特征与解释**，但这些外行业规范并未验证特定钱包身份。
- 同一来源分发到多数据服务并不构成多个独立证据；链上同一交易的多个CPI和重复索引也不能按多次资金事件算。

**认知科学/专家知识选择视角**：
- [美国国家科学院《How People Learn》专家知识章节](https://www.nationalacademies.org/read/9853/chapter/5)强调专家的知识围绕深层概念和适用条件组织，并注意到新手忽视的特征。对Blix的具体启发是从**“重要线索→适用原理→新问题→能改变结论的额外证据”**组织知识，不是添加“量化专家/法证专家”人格提示词或永久清单。

以上为有来源依据的**跨行业方法迁移与本项目的专业推论**；并非现实专家受邀作出的意见，不可冒充真实专家审稿。

## 四、旧 qb-：独特价值不是钱包角色“分类器”，而是调查工作产品

[原代码](https://github.com/sunshihao001/qb-/blob/main/sikk_gmgn_token_report.py)实际生成的八个输出：
`01_analysis_depth`、`02_token_basic`、`03_structure_metrics`、`04_key_address_matrix`、`05_infrastructure_registry`、`06_low_weight_scope`、`07_review_plan`、`08_summary`，另有报告与ZIP。这是一次调查的组织成果，而非8个互不关联的功能。

真正值得继承的独特知识：
1. **不同观察列表的候选钱包并集**：Top Holder、盈利Trader、SM、Bundler、Token转入、KOL、新钱包、疑似问题交易者。来源列表本身就是“它为何值得调查”的线索；
2. **Token来源与SOL来源分开**：主动Swap、受转Token、交易手续费来源、原始funding信息不能由单个身份标签代替；
3. **基础设施登记且不删除关系边**：Pool、交易路由、服务地址可能并非可疑实体，却是图网络必须保留的上下文；
4. **未来复查计划原生化**：T+1h/6h/24h/72h/7d与钱包后续卖出、转仓、回流、角色变化关联。调查不是一次静态截图，而是随证据变化可迭代；
5. **普通地址低优先深挖**：在预算有限时不是所有地址都立刻查完，但应保留“未调查覆盖范围”，否则无法区别没发现和没看到。

与此同存的重大缺陷：
- `classify(w)` 中的 `rat_trader`、`smart_degen`、`bundler`、`kol`、`transfer_in`等为供应商/规则触发的**候选观察理由**，不等于人的身份/操纵意图；
- `or 0` 对某些核心数据把“缺字段/失败/没历史”与真实0混为一谈；
- Top20/Top15/Top10→最多25地址，系统容易选择性忽视不在榜单的派发接收钱包，且优先分数可能让Pool记录占用有限深挖名额；
- 部分字段别名不一致、字符串前缀识别工具地址、`gmgn-cli`旧计费/格式依赖和shell执行风险，不能直接运行或融合。

**新认识 C**：qb的高价值是**调查问题与观察后续的组织能力**，而不是继承其`E4/R2`等分类名字。Blix已有Coin/Wallet/BubbleMap，但其现有界面是否保存“为何选它—哪些字段缺失—下次重看什么—什么结果会改判”的完整调查记录，仍须独立代码/实际报告验收。

## 五、旧 meme-：独特价值是失败定义、时序化概念和反事实

[meme-原术语表](https://github.com/sunshihao001/meme-/blob/main/03_%E8%AF%AD%E4%B9%89%E6%A6%82%E5%BF%B5/%E6%A0%B8%E5%BF%83%E6%9C%AF%E8%AF%AD%E8%A1%A8_v0.1.md)不仅规定“深洗/回收/二次启动”，还分别记录**什么不是它、为什么容易误判、哪些地方尚未确定**；[反证实验](https://github.com/sunshihao001/meme-/blob/main/09_%E8%A7%84%E5%88%99%E4%B8%8E%E5%9B%9E%E6%B5%8B/%E5%8F%8D%E8%AF%81%E5%AE%9E%E9%AA%8C%E8%AE%BE%E8%AE%A1_v0.1.md)把样本划为“符合且成功/符合却失败/不符合却大涨/看似符合但死亡/图形成立但不可执行”等，要求事前冻结定义、消融与简单基准比较。

这些概念不一定在Blix中成为K线或交易策略模块；**可以迁移为“序列事件如何形成、怎样明确失败和遗漏、历史证据何时真正可得”的研究经验**。

与Hermes形成关键张力：
- Hermes 00e鼓励异常出现后**生成**新框架；
- meme-要求框架生成后**不能根据同一成功/失败样本反复改写原定义**；
- ai-d提醒只有真正改变判断与行动才有价值，不能不断生成新理论而无交付。

**新认识 D**：三项目不应简单合并成某个“最佳规则”。Hermes帮助拓展假说空间，meme-帮助限制事后拟合，qb-把值得追的对象和未知放进持续调查过程。三者是**互相制衡的研究能力**，适合由Blix单一产品按需使用，而不是三套同时运行的Bot。

## 六、跨领域专家问题视角：真正能产生不同信息的专业问题

> 这些是基于各学科方法提出的**审查视角**，不是声称采访过领域专家。按问题选择，不成立则不调用；不另建固定专家编制。

| 专业视角 | 面对Hermes“异常同源钱包”会先提出的不同问题 | 会改变什么判断 |
|---|---|---|
| **链上协议/取证** | 签名、Token Account owner/authority、fee payer、System CPI、WSOL包装、池Vault和公共程序分别代表什么？ | 确认是否真实资金转移，排除虚假入金/重复记账 |
| **微观结构与经济学** | 相同资金活动是否改变了可卖库存、池深、净需求、价格冲击和经济收益分配？ | 分清同现象的不同经济机制 |
| **网络科学/经济主体识别** | 多跳路径是同一资本预算、服务中心辐射、独立交易者连通，还是算法图的传递闭包？ | 阻止把路径连通升级为共同控制 |
| **异常检测/统计学习** | 异常相对于什么可比基线？阈值是否事后调节？筛选了多少组合？负样本和漏报在哪里？ | 阻止发现伪规律、同时不因无标签漏掉新群体 |
| **因果推断/科学方法** | 哪个假说能解释另一假说解释不了的观测？谁在什么条件下可能被推翻？ | 从“像吸筹”转为可鉴别的经济机制假说 |
| **情报分析/数字取证** | 原数据、采集时间、供应商加工、历史覆盖与工具错误能否追回？多个证据是否同源？ | 区分资料缺口、公共服务与真实异常 |
| **认知科学/知识组织** | 原研究作者注意到了哪些看似微小的重要线索？在什么条件下这些知识才适用？ | 防止分类压平专业原理、提高可迁移性 |
| **软件设计/可靠性** | 原项目是怎样将洞察放入业务接口、记录、失败处理和可恢复观察流程？Blix已经有哪部分、缺哪部分？ | 从研究认识转化为可评估产品缺口，而非再造程序 |

## 七、知识如何在Blix中真实继承：先保全源，再连接认识与现有能力

- **Blix应用映射**：D02/D03研究发行和微观结构；D04/D05/D06研究钱包、资本与库存；D07研究异常与跨币演化；D08/D09仅研究潜在机会及执行限制；D10/D11是数据/反证；D12从ai-d读取问题表征/知识选择。与现有`server/coverage.js`、`bubblemap.js`、`wtrack.js`、`quality.js`、`research.js`、`brain.js`等核对时不应以“代码已存在”证明专业能力已到位。

## 九、下一轮的先行源码追溯：发现旧知识本身存在“跨文件深度不对称”

本轮继续读取了 [Hermes drill/grill 原始问答审计](https://github.com/sunshihao001/-/blob/main/design/phase1-research/grill-sessions/2026-05-26-grill-bytes-to-framework.md)（blob `605c2a73e641204d18f15fe6ff27be5a03036f02`）、[完整字节分解规格](https://github.com/sunshihao001/-/blob/main/design/phase1-research/gmgn-byte-decomposition-v0.1.md)（blob `c787b9c8abafae11a9f73315acfeb2603ceec414`）、[逐条推理研究](https://github.com/sunshihao001/-/blob/main/design/phase1-research/gmgn-byte-combination-reasoning-v0.1.md)（blob `4f7f70dcf8bb6d77373fec859cc0ef8ab5c0b994`）和 [Skill4筹码控制权设计](https://github.com/sunshihao001/-/blob/main/design/Skill4-%E7%AD%B9%E7%A0%81%E6%8E%A7%E5%88%B6%E6%9D%83%E7%8A%B6%E6%80%81%E5%B1%82%E8%AE%BE%E8%AE%A1.md)（blob `79cb0fc30037e83f7b3e4f511167f1cd9f08414a`）。

### 9.1 37/16不是“同一文档都已经逐条解释完”的证据

- 完整规格`gmgn-byte-decomposition-v0.1.md`列出 **37个L1与16个L2**，其中16个L2为A1–A3、B1–B3、C1–C3、D1–D3、E1–E3和 **F1 `HEALTHY_ORGANIC_MARKET`**。
- `gmgn-byte-combination-reasoning-v0.1.md`的标题/总述称`37 L1 + 16 L2`，但源文件中实际逐项标题可解析为 **37个L1、15个L2**；缺少F1作为单独逐条推理章节。F1在另一份规格里存在，**不是整个Hermes项目没有此知识**。
- 这反而提供了一个很实在的“不要把项目轻易贴完标签”反例：如果只读“逐条研究”或只读“规格”，都会误判**知识完整性或深度**。同一项目的规格、推理解释、反例、实现与验收可能深度不同，应按具体知识对象跨文件核对。
- F1“健康市场”又涉及更深问题：**没有明显异常**并不意味着真实交易健康、所有参与者独立、未来安全或正收益。正向健康结论往往比“发现一个异常”需要更充分的覆盖和反证。下一轮应将F1同其他15个候选一起审其理论前提、反证与可观测性，而不是填上一个标题就宣告完整。

### 9.2 Grill原始研究比00e单篇更完整地表达“数据不会说真话”

旧Grill明确写到：所谓`raw`实际上是GMGN已经处理过的“准raw”；同一批字段可被不同模型解释，不能把字段组合自动说成真理；“套框架”与“生框架”应该并行；价格、流动性、SM盈亏、离场和模式重复构成原作者希望观察的验证回路。

需要保留的专业思路是**不受预设理论约束、但以新证据重新检验理论**。需要修正的是把`3+/5验证回路`直接作为足以进入某种交易研究状态的硬门槛——不同回路可能不独立，且实际问题不一定以价格变化为最终价值标准：风险监控、真实资本/库存关系和可证伪的资金异常也可以是独立研究成果。

### 9.3 Skill4不是“要不要复制一个控盘标签”，而是另一套状态化问题

原文将所谓筹码控制力区分为`ESTABLISHING / ESTABLISHED / MAINTAINED / LOOSENING / TRANSFERRING / COLLAPSED / UNKNOWN`，并设计了剩余库存、入出金/派发、反向资金回流、时间新鲜度、输入时间对齐、历史完整度和不确定原因等不同因素。

值得保留：**一个经济主体/钱包群的影响可能随时间增强、松动、转移或无法识别**；不能只用当下Top10和一个静态标签。原文提出`UNKNOWN`原因，识别数据过期、冲突、聚类尚未验证、时间错位等，是高信息价值知识。

必须抵抗：模型从“候选经济实体”直接跃到“控制权状态”，使用多个自定义权重、`state_probabilities`、Bayes更新和`status_confidence=0.68`示例，缺实际身份真值与独立校准；这类分数不因数学公式复杂就成为概率事实。应将其视为**时序化经济状态的研究问题**，而不是可直接运行/可以承认控制权的识别器。

### 9.4 由这一轮直接生成的待研究核心矛盾

**矛盾一：数据是供应商加工结果，却被后续研究当“直接Raw”使用。** 应从已加工字段追到原始交易/Pool/Wallet，区分真实可观测事实、供应商标签和模型预测。

**矛盾二：大量异常组合能生成新假说，但固定旧阈值与同控标签容易使这些假说提前固化。** 应保留异常来源、采样条件与竞争解释，只有独立结果才能提高认识成熟度。

**矛盾三：Skill4希望判断控制权的动态转移，但主体Owner身份可能根本不可观察。** 需要研究是否可以先建立不依赖真实同控假设的**库存流向、直接转账和协同行为变化**描述，再在证据允许时提出竞争性主体解释。

**矛盾四：全项目有16个L2结构候选，逐条推理文档只有15个；健康类F1缺独立推导。** 需要补足“无异常≠健康”反面问题，并核验其是否被其他资料或现有Blix知识覆盖，避免凭文件标题做完整性结论。

这些新问题接在上一节A–D四条全链研究之后，属于**已经完成的下一轮先行源码发现**，不只是计划。下一次深入应从F1与Skill4的原始可观测性延伸至资金/库存/群体行为，而非围绕“缺一个标题”做文件填空。
