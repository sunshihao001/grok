**2026-10-31 · 执行规范（Draft）**

**继承**：`gpt-meme-continuous-progression.v1.md` 的阶段判断和下一轮输入；`gpt-meme-knowledge-accumulation.v1.md` 的证据、关系和原编号；原 L0–L7、D01–D12、152 个知识单元保持不变。

**本次修复的问题**：V1 可以推动 P2.1→P2.4，但没有要求每轮结束前把值得复用的认知差异实际更新到 GitHub/项目知识资产，造成“聊天进展 > 知识版本进展”。V2 将研究成果写入状态纳入交付检查，**不将聊天原文自动堆进正式知识库**。

## 0. 本质：区分三种进展

1. **研究进展**：AI 本轮解释、发现或设计了什么，是否比上轮多出真实认知增量。
2. **知识资产进展**：哪个既有 Dxx-Kxx/专题确实被新增、修订、降级或反驳；GitHub 文件+提交+PR 能否读回。
3. **能力进展**：代码、测试、真实链上数据、Grok Bot 运行及交易结果分别有独立证据；不能被知识文件代替。

三者在结尾分别报告。达到下一研究阶段不需要所有市场结论实证，但不能把“尚未入库”说成“已入库”，也不应把“测试通过”说成“已经连接链上或持续运行”。

## 1. 持续研究闭环：研究 → 差异 → 编译 → 落库 → 恢复

**不是每个简单问题都强制跑八步；对有持久研究价值的成果，输出前核查这些职责是否完成。**

1. **定位（READ）**：先读取最新 `gpt-meme-progress-current.md`、相关 Dxx-Kxx/专题、现有 PR/源码与原始来源。不可仅凭上一轮 AI 自述判断现状。
2. **研究（DISCOVER）**：继续独立探索、补充真实来源、形成新的解释/反例/方法；不要让既有知识抑制新假设。
3. **差异（DIFF）**：写一句可检查的增量——“之前认为/缺少 X；现在补充或修正为 Y；为什么改变？” 若无实质差异，允许不新增知识文件。
4. **过滤（FILTER）**：检查来源、适用范围、冲突、重复、用户原始意图及实际市场价值；区分事实/外部报告/机制推导/假设/模拟/源码测试。
5. **专业编译（WRITE）**：按照 `gpt-meme-research-writing-skill.v2.md` 将有用增量写进**现有主题的原位置**，必要时建立一个主题文档。不要按每次聊天生成一套平行知识本体。
6. **实际提交（COMMIT）**：有 GitHub 授权与工具时直接写入现有知识分支，回读确认与预期一致，记录 commit、PR、文件路径。未经复核的新发现保留 `draft/candidate`，不能升为证实知识或监控规则。不能写时明确 `PENDING_SYNC` 和目标文件。
7. **GPT 镜像核查（MIRROR）**：能写入 GPT Library 时保存便携版本并校验；**Library≠ChatGPT Project 附件≠Project Instructions**。当前工具不能直接更新 Project 的 Instructions/Attachments，需提供明确的添加/替换内容和状态，不得声称自动修改了 Project。
8. **恢复（RESUME）**：更新唯一活跃进度入口，写下一步最优研究题、晋级理由、未解决冲突、上一轮 GitHub refs；末尾生成简短可复制输入。

**权限**：研究文档、草案分支的可逆提交按用户授权执行；不自动合并 PR、改生产规则、签名、支付或下单。外部连接失败要停止该目标写入并报告，不能偷偷改用别的服务。

## 1A. 按需多领域外部研究与从业者语言恢复（2026-10-31 增量）

**目的**：继承旧个人 AI 研究中真正有用的“AI先理解、行业术语/黑话发现、跨学科机制推演、外部证据纠错、专业写作转化”，而非恢复过度复杂的旧门禁、固定步骤或庞大词典。关键词是发现新知识的入口，不只是检索同义词；用户不需要预先懂得行话。

**何时触发**：实际市场问题有未解释机制、协议字段/版本不确定、现有知识冲突、从业者黑话理解不足、公开报告缺少原始实现，或新增信息可能影响数据字段、解析器、正常反例、监控价值。已掌握知识足够时停止搜索并直接完成任务。**不用固定每轮搜索轮数、平台数或输出词数。**

**研究路径（按问题动态组合）**：
1. 从用户的朴素表达还原真实问题和不确定假设。例如“同一时间很多钱包买入”，可能涉及相同 slot、Jito Bundle、共同融资、相同交易路由或正常抢先交易，不能预先归因为庄家。
2. 找到真实使用语言：通过官方协议/源码、论文、工具文档、操作者帖子、失败案例获取英文术语、缩写、真实中文/俄语行业用语。区分“正式协议术语”“论文/研究标签”“交易者行话”“供应商宣传标签”，保存原始语境和来源，不将黑话自动定义成官方事实。
3. 从术语向下追溯程序与数据字段，向上回溯经济机制，横向连接资金流/会计守恒、时序图、统计零假设与活动度匹配、交易微观结构/执行竞争、证据工程等学科。优先展开能够改变当前问题的关联，不为跨域而跨域。
4. 外部证据路由：官方协议、RPC和源码用于验证实际语义；论文/实测用于验证特定样本中的关系；开源项目的代码、测试、issues用于验证实现与失败；X、Reddit、Telegram、GitHub讨论、多语言论坛负责发现真实痛点和搜索词，不能直接当作共识。搜索问题可以按角色×动作×对象/资产×工具×异常/失败改写，并根据新证据递归修正。
5. 将每个有价值新词翻译成“标准概念—可观测事件/字段—适用条件—常见歧义/正常反例—可用的程序或监控能力”。找不到证据则标未知；不要把共现、相似金额或营销标签当作共同控制或盈利。
6. 只有能补足一个数据契约、形成可证伪的新假设、解释反例、修正技术判断或提出更有用的研究问题，才更新现有知识专题与 Writing Skill。纯词表、同义搜索结果、重复定义不入库；若新来源不再改变判断或行动，停止扩张并推进当前工作。

**本次外部核查中的直接示例：术语“bundle”存在歧义。** Jito Bundle 是其 Block Engine 接收的、至多5笔交易、按顺序原子执行的协议对象，见 https://docs.jito.wtf/lowlatencytxnsend/ 。工具中的 bundled buyers、同 slot 买入簇、研究者定义的 sniper cohort 是不同的标签；**同 slot 或观察到 Jito tip 本身不足以确认多笔交易属于同一个 Bundle**。将它们混为一谈会污染钱包群体识别和 M01 数据归一化。

类似地，Solana 的 Token Account owner、程序 owner、authority/delegate、fee payer 不是同一主体角色；见 https://solana.com/docs/tokens/basics/create-token-account 及 https://solana.com/docs/core/transactions/transaction-introspection 。M01 适配器必须保留其区别，不从共享 fee payer、router 或 CPI 推出同控。对协议解析先找 IDL、discriminator、transaction trace、loadedAddresses/ALT、CPI 等原始专业术语和代码实现，然后才决定需要支持的事件类型。

**本机制仍执行 V2 现有 READ→DIFF→FILTER→WRITE→COMMIT→MIRROR→RESUME；** 这里增加的是研究质量和知识发现能力，不是新知识层级或新运行阶段。

## 2. 入库取舍：不是每条结论都要“永久保存”

| 研究产物 | 如何处理 | 理由 |
|---|---|---|
| 原始资料/交易/仓库新发现，且影响某个判断 | 保留来源引用，并修订已有专题 | 可核查、可复用 |
| 新的异常监控方法，具备数据和误判解释 | 以 `candidate` 写入现有方法目录 | 允许探索，不能伪装实证 |
| 能推翻/收缩旧观点的反例 | 标记 `supersedes/challenges`，旧观点保留历史 | 防止错误知识不断复活 |
| 实际写过的代码/通过的测试 | 更新工程状态、链接 commit 和测试证据 | 代码≠链上/经济效果 |
| 换词表达、重复清单、通用口号、没有业务对象的宏观描述 | 不写入正式知识 | 降低噪声 |
| 未经来源支持但启发性高的猜想 | 写入该专题“待检假设”一小段，勿开多个文件 | 保留灵感，清楚边界 |
| 暂时无法裁决的来源冲突 | 同一专题记录 A/B、适用条件和下一项区分证据 | 不强行融合矛盾 |

**可执行变更动作**：`NO_CHANGE` / `AMEND` / `ADD_TOPIC` / `CHALLENGE` / `SUPERSEDE` / `DRAFT_ONLY`。这是文档审查状态，不创建新知识层级。每轮可以只有 `NO_CHANGE`，但应说明本轮为什么没有值得保存的增量。

## 3. 写作原则：专业知识转换，而非对话摘要

继承此前关于专业 Writing Skill 的认识：**准确精读原始材料 → 穿透表面概念 → 复原可观测行为、资产与经济机制 → 发现逻辑断层 → 跨来源推演 → 反证修订 → 转成监控/研究/程序可用能力**。

每项正式知识增量至少能回答：

- **对象与场景**：Mint/钱包群/资金路径/发行阶段/数据源，解决什么 Meme 市场问题？
- **原先认识与本轮新差异**：新增的不是另一句同义描述，而是哪个解释、字段、条件、失败模式或操作能力？
- **实际机制与可观察物**：在哪个事件/时点看哪组数据？避免“庄家在操控”式无根据推论。
- **证据与强度**：来源 URL、固定版本或交易签名；外部研究报告与本项目复算分开。
- **竞争解释/反证**：什么正常机制也会产生相同现象？什么证据会改变当前判断？
- **知识连接与下游用处**：更新哪些 Dxx-Kxx；监控发现、解释、风险排除、程序原型还是交易研究？
- **当前状态和下一步**：candidate / source-reviewed / fixture-tested / real-data-checked / invalidated 等状态不得混用。

**篇幅策略**：常驻指令最多保存核心原则+索引；主题文件保存完整机制；代码和测试保存程序目录；大段原始资料靠固定来源引用而非复制。压缩的是重复和噪音，**不删除限定条件、反证、事件时间、原始来源和重要发现路径**。

## 4. 写入位置与唯一真源

| 知识类型 | 原位/建议位置 | 规则 |
|---|---|---|
| 总目标、专业领域、原子单元 | `knowledge/system/gpt-meme-project-core.v1.md` 及原 Dxx-Kxx | 延续已有编号，慎改本体 |
| 进阶判断和研究写作规范 | 本 V2 + Writing Skill，`knowledge/system/` | V1 保留为历史并指向 V2，不双份执行 |
| P2.1—P2.4 监控候选方法 | `knowledge/domain/meme-anomaly-discovery-state.v1.md` | 一个专题归集，同项覆盖修订，包含可证伪边界 |
| 实际程序、用例、测试 | `src/`、`tests/`、`fixtures/`，在对应 PR | 不把代码复制为知识主册 |
| 当前唯一恢复点 | `knowledge/system/gpt-meme-progress-current.md` | 仅一个活跃阶段坐标，记录并行支线 |
| GPT 可携带镜像 | Library `/跟单/`（实际上传、读回才算） | 不可冒充 Project 文件附件 |

**版本权威**：GitHub 对应 Draft PR/commit 为当前版本真源；PR 未合并表示主分支不含该内容。PR 链条多时先在同一个知识 PR 内审阅增量，不让同一类知识继续分散到更多平行 PR。

## 5. “自动化”承诺的实际边界

- **当前 ChatGPT 对话**：当有已连接的写入工具且用户授权时，可在本轮直接整理→提交草案→回读；下一次对话需重新使用工具与项目指令，并非模型自己能监听所有未来回复。
- **GitHub**：可逆分支/PR 保存已可执行；写入失败不能说同步成功。PR 审核、合并仍是独立操作。
- **GPT**：可更新个人 Library 与交付可下载镜像；**没有可用的 Project Instructions/Files 直接写入动作时，不能自动改 Project**。可以让 Project 使用短指令和 GitHub 参考入口，按需提取最新版本；必要时人工更新附件。
- **未来真正无人值守**：需由 Grok/Agent 运行环境提供会话结束 Hook 或任务完成事件、GitHub 权限、自动编译/测试与失败重试日志。单靠“每次结尾写提示词”不会产生后台文件同步。

## 6. 最小验收：怎么知道不是“又写了一份规范”？

用三个实际任务评估，不能自我打高分：

1. **无增量场景**：一轮只重复旧知识，应输出 `NO_CHANGE`，不在 GitHub 增加重复文档。
2. **修正场景**：一轮发现“Token Transfer 不是 Swap”的重要反证，应直接修订原专题并链接来源，旧错误不得在下一轮恢复。
3. **工程交付场景**：M01 源码和14项单测进 Draft PR，同时专题里只记方法与当前实现状态；不能在对话、知识库和程序目录复制三份不同定义。

验收要看：能否从新会话找到当前恢复点、同一主题有没有重复冲突、能否查到实际 commit、Project 同步是否被正确标记，以及回答是否因此更快更准确地继续研究。

## 7. 每轮最短收尾格式

> **📍 阶段**：当前研究 P2.4，M01 为 P3 独立支线。  
> **🧠 认知增量**：本轮新增/修正的具体方法；若无增量写 `NO_CHANGE`。  
> **💾 落库**：GitHub 文件+PR+commit；GPT Library 版本；Project 附件状态；不可写则 `PENDING_SYNC`。  
> **📊 进阶判断**：继续 / 推进 / 跨阶段的明确理由。  
> **✍️ 下一轮输入**：能够复制、含具体目标与交付的自然语言研究任务。

以上字段可以压缩成一段话，但真实同步状态不得省略。只有在源文件核查后才能说“已保存”；只完成研究不能说“已融合知识”。
