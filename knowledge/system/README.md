# 统一知识系统（架构真源） V1.0

**状态：体系结构已定义；知识内容仅部分填充；不代表策略已验证。** 本目录是 Grok 项目领域知识的上层契约，不替代已有 `knowledge/catalog.v1.json`（15 张遗留知识候选卡）和 `knowledge/legacy-snapshots/`（21 份固定快照）。

## 一、两种完整性

1. **结构完整**：8 层、12 领域、跨域关系、来源注册、事实/推断/反证区分、样本与成本、规则发布门槛、Owner 和版本、失效退役均有定义。
2. **证据完整**：必须通过真实数据与独立复验才能逐渐完成。当前不满足；所有缺口显式标为 `declared_research_gap`，不以空文档或模型自信充数。

## 二、正式知识分层

- **L0 治理**：来源、版本、权威分歧、版权、审计。
- **L1 原语**：链上交易、时间语义、GMGN/RPC 字段可用性、异常。
- **L2 市场**：发币、曲线、迁移、池子、深度、MEV。
- **L3 主体**：钱包角色、资金/筹码图、群体动态、资本循环。
- **L4 机制与策略**：可证伪假说；不能用「庄家」做未经证实的人身归因。
- **L5 交易经济学**：可执行价、延迟、退出、流动性、风险和净期望。
- **L6 实证**：先冻结问题和标签，再做零假设、反证、对照、负例、消融、OOS。
- **L7 AI 应用**：开发 Bot 研究与审核，单一 Monitor 消费冻结规则；不自动自我升级。

专业主题 **D01–D12**、现有 15 张卡的主归属与依赖关系，见 [ontology.v1.json](ontology.v1.json)。领域之间的边为 **研究关联**，绝非互相证明的因果箭头。具体例子：`D05 资金同源 → D06 控制结构` 只能提出问题，不能确立实控人；`D08 策略 → D09 交易经济学` 是必要验证依赖。

## 三、知识对象：必须能表达“未知、反面和限制”

| 对象 | 含义 | 可写入内容 | 禁止跨越 |
|---|---|---|---|
| Source | 带 commit/path 的一手或二手来源 | 许可、版本、时间、获取方式 | 来源存在 ≠ 内容正确 |
| Measurement | 工具读数/链上交易 | 原始值、单位、Slot、来源时间、错误状态 | 缺失 ≠ 零 |
| Observation | 截止时刻可观察事实 | 有效期、数据完整性、可回放输入 | 观察 ≠ 因果 |
| Mechanism | 可能产生行为的机制 | 替代解释、成立条件 | 机制 ≠ 方向预测 |
| Hypothesis | 可证伪预设 | 对照、失败条件、禁用未来信息 | 假设 ≠ 规则 |
| Finding / Counterexample | 研究结论或反例 | 正负结果、范围、统计功效、争议 | 样本内 ≠ 样本外 |
| Rule | 冻结后的只读观察规则 | 版本、回滚、批准记录、失效条件 | 规则 ≠ 下单许可 |
| Decision | 对指定观测的纸面输出 | 来源、知识引用、门控、UNKNOWN | AI 判断 ≠ 自行执行 |

版本状态 `proposed / historical_documented / external_reported / locally_reproduced / independently_validated / falsified / superseded` 与当前旧卡的 `source_contract / documented_legacy_method / unverified_hypothesis` **不是同一枚举**：前者对应研究证据状态，后者是兼容的旧卡分类。转换必须审查，不自动等同。

## 四、检索与推理流程（知识不是关键词列表）

```text
自然语言研究问题 / 监控事件
  → 研究问题规范化：目标、标的/阶段、时点、可执行动作
  → 领域路由：D01..D12 + 必需上游依赖
  → 概念/机制检索：旧卡 + 来源 + 证据单元 + 反例
  → 按适用总体、时间、数据有效期重新排序（而非仅关键词）
  → 分离事实 / 外部报告 / 因果解释 / 未知
  → 找出足以区分相反解释的下一项证据
  → 判断结构信号、预测信号、可执行优势各自是否成立
  → 研究输出 / BLOCK、WATCH、PAPER_ONLY、NEED_MORE_DATA
  → 人工独立复核 → 可能的候选规则 → 版本冻结
```

`python -m solana_meme_os.knowledge` 仍然是旧系统的关键词预选，不得宣传为完整推理器。新增 `knowledge_system.py` 提供领域图导航/结构检查，仍不执行语义推理。真正的 Grok Agent 需要在提供足够上下文后阅读机制、原始来源和反证。

## 五、机器可读契约

- [ontology.v1.json](ontology.v1.json)：完整专业主题及依赖，明确空白领域。
- [source-registry.v1.json](source-registry.v1.json)：四个历史/外部研究源的精确提交与许可限制。
- [research-units.v1.json](research-units.v1.json)：**仅有三张外部研究摘要**，按研究记录而非策略入库。
- [research-unit.schema.json](research-unit.schema.json)：单元字段契约；核心检查由 `knowledge_system.py` 执行。
- [MIGRATION.md](MIGRATION.md)：每批迁移范围、入口测试、验收与回滚。
- [RESEARCH.md](RESEARCH.md)：研究流程、推理界限、候选方向及 Bot 交接要求。

## 六、知识更新与冲突解决

1. **原始事实不可覆写**：交易证据与采集错误单独记录，所有修改带修订历史；旧结论标记 superseded，不静默删除。
2. **上下文优先于表面矛盾**：比较市场阶段、采集时间、样本总体、执行方式。两个不同适用范围的结论可以并存。
3. **反证与失败长期保留**：记录预期与失败原因、重启标准、负结果检验功效；不因失败就删除学习。
4. **发布隔离**：知识提议与生产 Monitor 规则发布是不同操作。开发 Bot 无权自行批准规则，更无权下真实交易。
5. **定期再评估**：新市场机制、RPC/GMGN 字段更改、数据源停用、执行成本漂移，应使相关结论降级或重新检验。

当前只是完整体系的 **V1 基础设施**；外部研究的全部脚本、真实行情、案例对照、Grok Bot 实例与长期校准都未在本次实现。

## 与现有 K0/K1/K2 按需研究工作流的关系

**主入口是 `python -m solana_meme_os.research`**，而不是并行建立第二套检索器。它的研究包新增 `ontology_route`（12 领域路径）、`research_unit_candidates`（有证据状态的反证线索），原本的 `sources`（17 个按需固定版本文档）与 `domain_knowledge`（15 张常驻卡）继续保留。这个组合只有“知识导航”能力，不声称实时链上事实或获利判断。

`source-registry.v1.json` 属于 L0，约束来源的 commit、版权、权限和适用范围；`knowledge/source_index.v1.json` 属于 K1，只负责在问题出现时定位某份文档。审计器检查两者的来源版本一致。K0 是少量常驻原则/概念，K1 是按需文献，K2 是待建设的真实链上证据与反例数据。8 层和 12 领域是横跨 K0–K2 的知识本体，而非三套相互孤立的目录。

## 分类 ≠ 依赖 ≠ 证据过滤（V1.1 审查）

[领域审查与过滤方案](REVIEW-V1.1.md) 将 D01–D12 保留为稳定专业分类；`depends_on` 仅表示真正无条件前置，`related_domains` 为可选上下文。**F0–F6 七个证据门槛**独立定义在 [filter-policy.v1.json](filter-policy.v1.json)。D10/D11 作为每一步的横切证据质量与反证检查，而非依赖链终端。研究入口只提出过滤计划，不可自动宣布 PASS。

## Bot 职责映射

[七个 Bot 角色](../../BOTS.md) 以“6 个按需研发 + 1 个最终只读监控”的方式组织。专业领域 D01–D12、七级证据过滤 F0–F6、Bot 实例数是三种不同概念；Bot 不可凭本体图谱自行通过证据门槛。
