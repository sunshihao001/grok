# Skill｜Solana Meme 研究成果专业写作、去重与知识融合 V2.0

**用途**：研究有实质增量、用户明确要求保存或 GitHub 已交付代码后，按需将成果写回 GPT Meme 现有知识体系。不是每个答复都生成新文档，也不是另起一套领域分类。

## 启动条件

出现新的可观察市场方法、具体反例、可核查来源、修正旧认知、真实程序/测试进展，或用户要求研究成果长期保存时执行。简单问答和重复阐述不触发正式写库。

## 按需跨领域检索与专业黑话识别

**触发**：现有知识不足以解释链上机制、字段或身份词义含混、新资料可能推翻已有结论、只有工具营销标签却无原始程序证据。关键词除了搜索，更是发现未知专业知识、真实参与者、关联学科和反例的入口；不规定必搜平台数或轮数。

**研究**：先根据用户口语还原真实问题，再用角色×动作×对象/资产×工具×失败场景定位官方术语、开源代码、论文和从业者实践。按需扩展英文缩写、可靠的中文和俄语行业语言，保留出处及原始语境。官方协议/代码说明语义，独立实测说明样本发现，论坛/X/Reddit/Telegram负责发现圈内说法和失败问题。对多义词标注来源层级，不能将营销黑话升为已证事实。

**写作转化**：仅保存“术语→对应标准概念→可观测字段与事件→歧义/普通反例→监控/解析价值”的有用差异，更新原专题或原条目；无知识增量输出 NO_CHANGE。例：Jito Bundle 是协议级原子交易组，工具所谓“bundled buyers”或同 slot 买入簇不必然属于同一个 Jito Bundle（官方 https://docs.jito.wtf/lowlatencytxnsend/）。出现真问题后继续向 CPI/transaction trace/owner/delegate/fee payer 等真实字段研究；证据足够即停止搜索并交付任务。


## 必须前置：检索覆盖、方向校准和参考复用

对重大研究/工程任务，不能只做论文摘要。先从现有参考项目的源码与历史差异出发，按问题选择官方协议/IDL/版本、实用开源代码/测试/issues、实际交易工具、X/Reddit/Telegram开发者实践与失败反馈、供应商数据契约以及必要跨学科知识；从新术语继续递归发现未知问题。每轮记录实际覆盖与未覆盖的来源类别，具体链接、代码路径、可观察对象和可能推翻结论的反证；不以文献篇数代替深入程度。

选题开始与结束时都要检查方向：项目实际监控能力是否改进、为何优于竞争实现、数据和观察时点是否可得、是否把结构解释误当预测或利润。明确 CONTINUE / PIVOT / PAUSE / REJECT 与最有用的下一项区别性证据。借鉴外部解析器时区分官方语义、项目自述与本地已复跑能力。

持续从常驻参考池按问题重访旧 qb-/Hermes/meme-/Why-Solana/OKX 及后续新增候选：保留原始函数或模块、旧判断、失败/未验证条件、当前改进和下次重访触发条件。不做一次性资料搬迁，不因为当前不适用而删除旧项目；外部结论未复核仍是 source_report / candidate。

每轮的正文报告具体增量与实际 GitHub/Library 状态；**全篇最后必须由 AI 提出一个优先研究/工程任务，并以「✍️ 下一轮可复制输入」作为最后一项**。该输入必须承接真实恢复点，主动继续多类型来源检索、比较原有参考与竞争路线、核查方向并将新知识回填原位置，不以“继续研究”结束。


## 关键操作

**1. Read before write**
检索当前阶段、Dxx-Kxx/现有专题、相关源码与已有 Draft PR，判断新材料是否已经存在。必须回答“更新谁”而不只是“我新写什么”。

**2. Deep read and mechanism reconstruction**
从原文/源码真正弄清输入是什么、地址/事件/资产/时点是什么、输出和限制是什么，恢复背后可观察机制。区分外部报告、链上已证事实、AI 推导和没有验证的猜想。

**3. Delta extraction**
最重要的一句话：“旧知识 X → 新增或修订 Y；改变了哪种观察、解释或执行能力？”没有能力增量就不增加知识记录。

**4. Noise and conflict filter**
剔除套话、重复术语、没有证据的‘庄家’身份和收益推断。遇到竞争解释，不能靠压缩把反证删除；将其作为条件写入原条目。

**5. Synthesis instead of summary**
以具体 Meme 场景、数据字段、机制、正常反例、下一步验证写成能被研究 Bot/开发 Bot 用的文档。对跨域知识只建立关系链接，**不复制两份文本**。

**6. Commit and verify**
写原文件或建立一个真正必要的新专题文件。通过 GitHub Draft PR 提交，回读内容、检查路径与 SHA；镜像到 GPT Library 时读回核对。无法写入则报告未完成，不能只在聊天里声称落库。

**7. Resume**
更新唯一恢复点，生成下一轮具体研究输入；按《持续研究推进机制 V2.0》判定是否进入下一阶段。

## 允许的知识变更结果

- `NO_CHANGE`：内容重复或噪音，不落库，继续研究。
- `AMEND`：原知识需要补数据字段、条件、误报或机制解释。
- `ADD_TOPIC`：确实新领域问题，原有专题无法恰当容纳。
- `CHALLENGE`：新增反例或竞争解释，暂不推翻旧结论。
- `SUPERSEDE`：有足够证据替换旧认知，保留旧版可查。
- `DRAFT_ONLY`：高价值但未证实的假说，不进入正式运行规则。

## 一个实际例子：批量钱包“转账数量增加”

不要写：‘庄家批量转账，可能拉盘，需要关注。’

应写：‘某 Mint 的连续 5 分钟窗口内钱包地址由 8 增至 20，但Token Account需先按 owner 去重，买卖Swap和内部转仓分别计算。若成员更替率升高、买入报价金额下降，记录为**钱包群体变化＋交易规模背离候选**，而非单一控制者证据。下一步比较普通热门币及共享路由钱包，修订 D07 与 D05/D10相关知识。’

这个例子是设计示意，**不代表已观测到真实链上异常**。

## 禁止的三种结果

1. 把本次回答全文复制为新知识，而没有同原条目比较。
2. 把运行通过、知识卡数、PR数当成研究质量或真实盈利证明。
3. 只在聊天里打印‘已记录’，却无文件、PR、commit、Library读回或明确待同步状态。

**成功定义**：新的 GPT 会话/研究 Bot 读取当前专题后，能够知道最近更新了什么、已有依据是什么、哪里还没证实、下一步真正该做什么。
