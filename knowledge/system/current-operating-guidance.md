# Solana Meme 项目｜当前工作准则（2026-11-01）

> **生效范围**：本仓库知识 PR #14 的项目入口与工作方式。它取代历史 P1–P6 固定研究阶段、V2 每轮强制流程和“下一轮可复制输入”等默认指令；不删除历史证据、源码或可用专业知识。本文件是工作准则，不是新本体、Bot 架构或功能清单。

## 1. 两个目标，不互相替代
- **长期目标**：AI 作为外部专业认知与执行支持。用户以普通语言表达目的、现象、约束和反馈；AI 主动承担需求解释、产品决策、现成方案研究、系统设计、编码、测试、事实核查与结果验收。在有权限时实际执行；涉及费用、密钥、真实交易、外部发布等必须遵守授权界限。
- **当前产品**：Solana Meme 只读监控系统。从 Mint/市场事件出发，发现并持续观察钱包、资金和 Token 活动，识别异常与群体关系，按需调用 Grok 专家解释、质疑和呈现可核查报告。跟单仅为可能的研究用途之一；不默认以 K 线或“庄家”标签作结论。

## 2. 以实际任务选择行动
- 优先恢复用户目标、现有成果、真实未知、工具/成本限制及可验收结果；再自主决定直接答复、查证、复用开源成品、集成、编码、测试或停止。**不强制经过固定阶段、固定专家人数、固定输出栏目、研究任务循环或每轮复制提示词。**
- AI 是产品与工程统筹主体；不要把技术栈、架构选择、开源项目筛选和下一步细节常态化交还给缺少专业背景的用户。必要许可/账号授权是例外。
- **现有整体业务成品 > 可安全复用的成熟子服务/SDK > 最小适配代码 > 自研底层**。审实际源码、接口、许可、依赖、运行成本、数据完整性、权限边界和失败行为；不能按 README 声称已实现。
- 与目标无直接关系的整理、全域规划、专家扩编和知识目录增长暂停。研究只在能改变理解、选型、误判或实现时深入；任务达标即交付并停止扩张。

## 3. 知识及证据的正确位置
- 既有 L0–L7、D01–D12、152单元是**历史可检索分类**，22位专家是**可选知识视角**，65项参考是**资产索引**：都不是必须逐项执行的工作流、已验能力或已部署 Bot。旧 PR #15 的104项也不自动并列成为真源。
- 只按当前问题选择有用知识；保留 Hermes、qb-、meme-、Million、pumpwatch、Why-Solana（review_only）、OKX 等真实可用证据与反例。新的证据若改变原有结论，再修订现有专题，标明被替代说法和来源；不为每轮回答制造文件。
- 区分**源码存在/测试通过、供应商报告、真实链上核对、经济解释、未经证实假设、实际 Grok 运行**。缺失不等于零；Token Account、owner、真实经济控制者不能混称；转账不自动等于买卖；观察时间不等于事件时间。
- 历史文档若与本文件或最新实测冲突，只用于追溯，不得当作当前执行指令。保留 Git 历史而非把旧错误改写成从未存在。

## 4. 当前真实进度与最先补齐的能力
- **已实测的 V0.1 基础预览**：工程 Draft PR #16 的 `mint_v01.py --rugcheck` 在 GitHub Actions #41269179918 获取真实 Mint 的5池、20条RugCheck Token Account候选和Creator候选，并交叉识别1条AMM地址。来源可能缓存，19条其余候选未分类；不是完整资金图或Grok部署。
- **当前最有价值的产品缺口：V0.2 真实钱包/资金关系**。从V0.1同Mint的有来源候选出发，优先调查/安全复用RugCheck内幕关系或Million funding/owners等成熟功能，得到至少一条可核查的真实资金或Token活动关系、来源/时点以及一个误归因或未知例子；必要时调整选型，不被未授权OKX接口阻断。
- 之后再按实际可用事件流推进持续异常观察、重启恢复和Grok自然语言研判；V0.3、V1.0是产品里程碑，**不是每轮机械推进流程**。未做交易、签名、自动付款或正式Grok云端部署。
