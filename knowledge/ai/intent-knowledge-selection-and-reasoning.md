## 1. 一项贯穿数月但不应被误读的总目标
原始用户语言往往是感觉、观察、目标、假设和类比的混合。**AI 的工作并非直接替换关键词，而是忠实保留表达与目标，找到适用的成熟专业概念，比较解释和证据，重构可行动的专业问题，再用结果修改认识**。

历史主线（不代表固定任务步骤）：
- **2026-07-31**：F01 处理问题表征、用户原话与 AI 假设分离；F02 给出12个基础概念的定义、边界和关系。
- **2026-08-01**：F04 概念邻域把词语关联、认知流程、主张证据、用户临时映射分开；F05 调查证据来源、冲突与修订；F06 处理内容组织与准确表达；F07 处理多轮共同理解、修复和目标切换。
- **2026-08-07 至 10 月**：A01 及方向重构研究将大型固定架构降为历史候选，保留有价值的知识和职责；历史规则不自动等于现行指令。
- **2026-11 月**：新增真实工作的选择、可核查交付、外部成熟方案复用、跨工作流知识调用、GitHub 审核和结果再审视。

重要：这一历史链描述**用户希望发展和过去研究涉及的能力**，不是任何模型已经稳定拥有这些能力。

## 2. 同一张知识图的四类关系，不能压成一张关键词表
## 2026-11-13｜AI认知与Blix多层对齐的适用性修订

本篇原有语义解析、问题表征、概念邻域、跨来源迁移、证据和持续纠错**保持有效**，但不能把这些概念误当运行时固定管线。最新 [Blix多轴知识模型](../DOMAIN-MODEL.v1.json) 与 [现有交叉对照第7节](../INTEGRATION-CROSSWALK.md#7-2026-11-13-关系型认知修正从层级清单到可审查的专业主张) 将其对齐到 10个独立视角。**AI优先组织的是一项值得判断的具体专业主张**，不是搜齐所有层、所有专家或越多来源越好。

三种关系必须明确：
- 术语与概念：`exactMatch/closeMatch/broader/related` 只帮助理解表达和检索，不证明同一经济身份。
- 事实与推论：`observed_economic_event`、`supports/contradicts` 必须具备原交易/出处、时点、覆盖与竞争解释，才允许有条件形成主张。
- 实施与效果：`implemented_by/tested_by/selected_for_context/changes_decision` 分别说明代码位置、测试范围、模型实际检索轨迹和反馈；不能把代码存在、CI通过、知识被加载直接变成市场事实或智能提高。

如果用户问“这一群钱包是否一起出货”，AI可以形成多个可证伪解释、优先选择能区分解释的Token转移/Swap/资金/库存/池信息；当前证据不足时**先给有条件判断和下一次高价值补查**，不强行贴庄家标签，也不因为无法确定最终控制者就停止所有合理研究。若新证据与旧结论冲突，修订被影响的主张及使用场景，不覆盖旧来源、不把新的专业解释自动升级为用户授权。

**能力边界**：本文件是认知指导，不是模型已经正确检索/推理/掌握知识的证明；`local-knowledge-loader.mjs` 仍只是有限白名单词面候选。实际提升需固定相同Mint/时间截点/模型/工具预算，比较“原事实—加知识—多层交叉反证”在准确率、错误归因、未知处理、补查增量和成本上的差异。

**四种关系**：
1. **概念语义关系**：A 是 B 的一种、A 与 B 对照、跨行业近似匹配。借鉴 SKOS，但非所有边均属于 SKOS。
2. **研究/行动关系**：概念规范化可帮助寻找研究来源；证据反例可促成问题重构。这是条件性工作关系，不是术语上下位。
3. **证据关系**：具体来源支持、反驳或限制具体主张；不因两个文献同属一个主题就把它们当成独立支持证据。
4. **目标/用户表达关系**：一句话与某个概念是部分重叠、类比、组合还是条件成立，必须注明是“AI 的候选理解”，不写成永久事实。

图中箭头是**探索路径示例**，不是线性必经八九步；简单问题可以直接解决。所有跨域连接必须说清关系类别，不能用“它们都与认知有关”冒充机制联系。

## 3. 已有16项基础概念怎样归为少数专业问题？

源：F02 的 C01–C12 与 F07 的 C13–C16；使用历史编号仅为定位原资料。**以下是知识功能分组，不是16个必须运行的模块。**

| 功能群 / 主要问题 | 历史概念及标准术语 | 彼此如何联系，什么不能混同 |
|---|---|---|
| **理解原始意图（P1）** | C01 Semantic Parsing；C02 Abduction；C03 Clarification；C04 Concept Normalization / Entity Linking | 语义解析提取表达结构；溯因提出候选解释；概念规范化对齐标准概念；澄清仅针对会改变结果的歧义。关键词抽取不能替代它们。 |
| **共同理解与方向（P1/P6）** | C09 Mixed-Initiative Interaction；C13 Dialogue State Tracking；C14 Grounding；C15 Conversational Repair；C16 Joint Project Navigation | 追踪当前目标与共同理解、在误解处局部修复、管理子目标与主动权；对话日志不能自动等于长期可复用知识，AI 建议不等于用户授权。 |
| **发现与组织知识（P3/P4）** | C05 Concept Mapping/Relational Organization；C08 Exploratory Search；C12 Retrieval-Augmented Generation | 概念关系帮助发现新研究线索，探索式搜索允许研究问题演化；RAG 是外部资料接入方式，不是“知识正确应用”的证明。 |
| **解释、迁移与更新（P2/P7）** | C06 Sensemaking；C07 Knowledge Integration and Transfer；C10 Conceptual Change | 从分散线索构成可检验的解释；迁移要检查条件与机制；新证据可迫使修订旧解释。不是每次都要“创新”。 |
| **证据的来源和适用（P5/P7）** | C11 Provenance / Claim–Evidence Link | 来源真实性、来源对具体主张的支持、整组证据的确定度是不同问题；不以引用数量替代可靠性。 |

### 现在真正需要强化的交接环节：知识适用与激活
七八月已研究“概念对齐、知识应用、边界、迁移、检索”。**本轮并不宣布又发现了一个名叫 C17 的新概念**。我们要将原有 C04/C05/C07/C08/C11/C12 的联系接到更清楚的行动判断：

“这条知识是什么”≠“现在应当使用它”≠“实际使用后判断更好”。

依 National Academies《How People Learn》的专家研究，专家知识通常围绕核心原理组织，具有适用条件。它是**人类认知的研究证据**；迁移至 LLM 的有效性仍需要本项目实验。

## 4. 八种跨行业“专业知识入口”，与当前问题的实际联系

| 研究行业 / 学科 | 先找的成熟专业关键词（例） | 能帮助推演什么 | 用错时的典型失效 |
|---|---|---|---|
| **计算语言学/语用学** | Semantic Parsing, Pragmatics, Reference Resolution, Abduction | 朦胧想法包含什么指向、假设、行动需求 | 只识别词、误解真正目标 |
| **图书情报/术语学** | Controlled Vocabulary, Concept Scheme, SKOS, Terminology Management | 普通词如何映射行业标准词、上下位和关联 | 把同词当同义、关系边当因果 |
| **认知心理与专家研究** | Conditionalized Knowledge, Expertise, Transfer, Conceptual Change | 专家为何在特定条件下使用某种方法 | 把人的学习机制当 LLM 已证实机制 |
| **科学哲学/研究方法** | Abduction, Hypothesis Testing, Causal Inference, Evidence Synthesis | 如何提出竞争解释，哪种证据能区分它们 | 用相关性代替因果、任意平均冲突 |
| **管理学/组织学习** | Sensemaking, Exploration vs Exploitation, Double-Loop Learning | 为什么研究会改变目标，何时停止扩张和真正行动 | 任意套用企业管理流程到所有 AI 任务 |
| **决策科学/运筹学** | Value of Information, Metareasoning, Opportunity Cost | 下一项搜索/研究/实施是否值得投入 | 预设永远需要检索或三轮规划 |
| **人机交互/协作** | Mixed-Initiative, Common Ground, Repair, Joint Projects | AI 什么时候主动提案、什么时候由人决定 | 借“主动”之名擅自更改重大目标 |
| **软件工程/档案与知识工程** | ADR, Provenance, Versioning, Retrieval, Evaluation, State Persistence | 如何把研究成果变成可追溯 GitHub 资产、真正完成交付 | 上传=验证、保存=长期学习、PR=正式上线 |

这里列的是**检索入口和专业问题**，不是宣布八个学科已经被研究透。每个入口都要在具体问题上进一步追溯经典书籍、标准、原始论文、源码或真实实践。

## 5. 关键词“单独/组合/上下/左右/反向”怎样形成真正不同的研究路径？

以用户一句“GPT 研究好了，但知识越来越乱，感觉 AI 没变聪明”为焦点：

| 探索方式 | 可检索的专业概念组合 | 产生的关键问题 | 对行动有价值的区别 |
|---|---|---|---|
| 直接对齐 | knowledge organization; terminology management | 是否只是术语、目录和别名混乱？ | 优先修索引、去重 |
| **向上**（目的） | problem formulation + goal evolution | 当前做知识库是为了管理文件，还是为了增强判断？ | 可能需要重定 G2，避免做无用目录 |
| **向下**（机制） | retrieval mismatch + knowledge applicability | 是没检索到，还是检索到了却用错？ | 前者改召回，后者改适用性判断 |
| **横向**（学科） | expert knowledge + conditionalized knowledge | 行业内专家凭什么知道哪些知识该在何时用？ | 研究适用条件、反例，而非继续搜关键词 |
| **对照**（竞争解释） | context contamination vs staleness vs model limitation | 旧指令干扰、资料过时、基础模型能力问题是否不同？ | 需要不同修复动作 |
| **反向**（失败） | negative transfer + evaluation leakage | 更多知识为何可能让新任务表现更差？ | 建立对照评测，不自我评分 |
| **迁移**（其他行业） | exploration/exploitation + value of information | 研究新方向的收益能否超过立即完成成果？ | 评价是否继续拓展 |
| **表达**（传达） | explanation planning + grounding | 如何用普通话说明专业结论，又不损失事实边界？ | 调整表达而非降低研究深度 |

### 一个必须保持的限制
“词 A AND 词 B”只是检索组合，不自动构成知识关系；“A 相关 B”也不等于“A 导致 B”。有价值的跨域类比应比较**关系、条件、机制、失败环境**；Gentner 的 Structure-Mapping 理论可作为关系优先的经典依据，但不能保证 AI 的类比一定正确。Bates 的 Berrypicking 说明搜索问题可随发现演变，但不等于所有发现都值得成为新目标。

## 6. 知识真正参与决策：增加一项可检查的适用性问答
对于将影响重要判断的知识，不新增强制 YAML 表，仅在需要时能回答：
- **当前问题**需要判断什么、服务哪个已确认目标？
- **候选知识**的原始定义和适用条件是什么，属于哪一类证据？
- 与当前问题究竟是直接适用、部分适用、类比、仅相关，还是不适用？
- 如果采用它，相比原先的判断**改变了什么行动或关键未知**？
- 存在哪种竞争解释、反证、成本或高风险边界？
- 结果是否真的在实际任务中改善准确性、决策或交付？未测则说明未测。

这解决旧研究的典型缺口：已找到源、已画网络、已编排话语，却没有证明正确的知识改变了实际行动。

### 6.1 选择知识前先判断问题结构：从专家研究到可适用的决策

经典专家研究的一个具体启发是：**问题看起来像什么，不等于它实际上受什么原理支配**。Chi、Feltovich 与 Glaser（1981）在物理题目分类中发现专家更多按照底层原理区分，新手更多依赖表面特征。这是人类专家研究结论；用于设计 LLM 知识选择属于待验证迁移。

据此，面对真正影响决策的复杂任务，AI 应当优先辨别以下几种可能，而不是因为某词匹配就加载所有相关文件：

| 候选知识关系 | 问题 | 合适的行动 |
|---|---|---|
| **直接适用** | 任务机制、条件及原始来源的适用范围一致吗？ | 使用该概念/方法，并保留证据范围 |
| **部分适用** | 哪些条件吻合，哪些变量未覆盖？ | 只使用成立的部分，补足缺口 |
| **关系类比** | 机制的关系结构相似，还是仅用词相似？ | 提出可反驳的新假设，不将类比当事实 |
| **冲突/失效** | 旧方法是否被新目标、版本或证据取代？ | 拒绝默认引用，记录修订关系 |
| **仅相关** | 它只是一个搜索线索，而不支持当前判断吗？ | 可以登记，但不要升级成方案依据 |
| **尚未知** | 是否缺少足以区分方案的关键证据？ | 有信息价值才继续研究或澄清 |

与历史概念的对应：C01/C02 负责形成问题解释候选；C04/C05 将专业词与关系区分；C07 关心迁移；C11 关心来源对主张的支持；C09 与 G0–G4 目标导航决定需要保留哪类用户选择。**这些能力的条件性组合不是新增 C17 节点。**

### 6.2 案例经验怎样合理复用：不能因为有相似案例就直接套方案

Aamodt 与 Plaza（1994）的 Case-Based Reasoning（CBR）对“案例检索、复用、修订、保留”的区分，对 ai-d 的启发是：
1. 检索到与现象**表面相近**的旧案例，只能产生候选；
2. 需要对齐当前任务的约束、变量和错误成本，检查如何**调整**而非复制；
3. 实际可逆行动完成后才能核实有效性；
4. 验证通过的经验再进入可复用案例；失败经验记录失效条件。

如果只是从 GitHub 找到“类似知识库项目”，仍无法据此证明它适合本人的目标或可以运行。也不能声称 AI 在本仓库已经实施了 CBR 引擎。相同原则也适用于经典专家研究与跨行业类比。

### 6.3 何时继续搜索、何时开始交付：把信息价值和证据覆盖结合起来

Russell 与 Wefald（1991）提出元推理的规范性研究思路：评估进一步计算可能怎样改变外部行动。Roh 与 Han（2026）的 HALT 在多跳问答检索代理中，利用所需主张的证据覆盖判断停止，减少冗余检索；它针对特定的多跳问答任务，不是所有研究的一般最优停止算法。

对 ai-d 的**条件性决策建议**：
- 当前决策尚缺一条会改变结果的关键证据：继续定向调查；
- 已有足以支持**可逆的下一步行动**的证据，新资料多是同义重复：开始执行，不再扩展术语；
- 重大或不可逆决定仍有决定性未知：明确限制并请求必要的授权/进一步验证；
- 发现另一领域有新概念，但对当前判断无实际作用：保留为线索，不自动增加新目标或目录。

### 6.4 过时记忆不是可直接引用的“历史事实”

2026 年的 Memora 研究在长期个性化代理的记忆基准中发现过时记忆复用与更新困难。这支持单独核查**记忆是否仍有效**的重要性，却不能证明本项目所有质量退化都源于历史污染。

从此前已保存“固定专家必经阶段”到如今的“按需知识调用”，改变的是**当前默认操作方法**；七八月对知识定义、概念网络和证据的有效研究内容仍可按需复用。

### 6.5 一个具体问题的判断变化（诊断演示）

原始问题：“研究越做越多，总觉得还有新方向，什么时候应该停下来开始做？”

- **仅关键词匹配**：可能返回“探索式搜索”“目标演化”相关论文，继续生成新方向。
- **按问题机制定位**：实际矛盾是“探索新认识”与“交付当前可用成果”的资源冲突；需要关注方案停止条件、信息价值以及用户已确认的 G1/G2。
- **与旧知识关系**：概念邻域 F04 有助发现方向，但不意味着每轮都探索；planning/proposal-review 管理当前决策与最小交付。
- **推荐行动**：检查关键未知能否改变当前可逆选择；若否，选最小可核查成果并实施；若是，继续获取那条区分性证据。
- **反证**：如果新信息会改变安全条件或重大资源投入，则上述“立即做”可能不成立。

对同一仓库 11 份文档运行的**字面二字符重叠静态诊断**已经写入 [现有评测记录](https://github.com/sunshihao001/ai-d/blob/proposal/goal-planning-knowledge-delivery-20261106/evaluation/first-cross-domain-tests.md)：研究报告词语命中高不代表最适合作为行动规范的文档。**这不是独立模型 A/B，也不证明某个新检索器提高了准确率。**

**原始来源**：[Chi et al. 1981](https://doi.org/10.1207/s15516709cog0502_2)；[Aamodt & Plaza 1994](https://www.cs.auckland.ac.nz/research/groups/ai-cbr/classroom/cbr-review.html)；[Russell & Wefald 1991](https://doi.org/10.1016/0004-3702(91)90015-C)；[Uddin et al. 2026 / Memora](https://aclanthology.org/2026.findings-acl.1337/)；[Roh & Han 2026 / HALT](https://aclanthology.org/2026.findings-emnlp.343/)。

### 6.6 检索不应成为默认必经动作，专业知识也可能来自内库之外

来自真实公开问题的补充（完整证据与离线测试见 [2026-11-06 评测记录](https://github.com/sunshihao001/ai-d/blob/proposal/goal-planning-knowledge-delivery-20261106/evaluation/first-cross-domain-tests.md)）：

- LlamaIndex 用户报告，简单问候也产生高分资料引用：首先应识别**这项请求是否需要检索**，而不是一律调整向量相似阈值。
- 另一份 LlamaIndex Issue 报告，TEI 重排的分数与文档对象错配：真正的专业缺口是**返回结果的 index 关联语义**，不是扩大专业搜索词。其最小位置配对错误已离线复现；并不构成当前产品漏洞认定。
- LangChain 的父子文档重新索引报告指向**版本与存储一致性**；其旧模型示例报告则指向**文档更新与运行参数变更的边界**。这两个“过时”问题需要不同知识与证据。

从中得出一个必要的知识选择原则：**没有适合的内部知识，是有效的研究结果；无需检索，也是有效的决策。** 不应仅因内部索引能够返回一个高分文件就强迫引用。对于具体源码或服务行为，若现有 ai-d 只保存了通用认知理论，AI 应进一步访问对应产品的官方规范、原始源码及相关版本，或明确当前证据不足。

这并不是新增一套必经四关的执行框架，而是扩展“知识适用”判断的可选出口。类似问题还要明确：“当前检索分数是否属于正确对象？”“旧知识是否对应当前版本？”“文档表达的事实能否支持实际行动？”这些检查必须按问题机制选择，不需要全部展开。

**边界与反证**：上述是对外部 Issue 的研究判断，不是独立评审结果；方法要真正改善模型作答，还需要陌生任务、正确性标注和交付结果测试。旧16题排名的可重复计算，也只验证检索规则，不验证模型真实认知。

## 8. 三个实例：如何由局部问题推演到整体认识（诊断演示，不是实验）
### A. “只要搜专业词，GPT 就能变专业吗？”
普通词“专业”→专家知识组织与条件化知识（认知科学）→词表与概念规范化（情报学）→语用/问题表征（语言学）→主张证据适配（研究方法）→具体任务评价（软件/教育评测）。
**判断变化**：不把成功指标设为“关键词数”，而设为“正确识别关键问题、使用适用知识、错误更少”。

### B. “已有很多 GitHub 文件，但新问题仍用不上？”
区分：①文档是否正确保管；②检索到哪些内容；③该知识在什么情境成立；④它改变了何种方案；⑤任务结果是否更好。
**判断变化**：先查知识调取和适用性，不优先新造数据库/多 Bot。

### C. “一个行业小工具引出大项目，如何不丢原目标？”
从具体工具功能→真实行业问题→专业机制→产品替代方案→长期目标，逐层提出新的**候选**；区分“拓展了问题”与“用户确认改变项目”。
**判断变化**：允许向上重审目的、向下深挖机制，但 G0/G1 的重大变化不因 AI 检索到新名词而自动生效。

## 9. 本轮方案比较：知识应该怎样在 GitHub 中长期建设？
- A **一次性全量搬迁并重做庞大知识图谱**：细节可能齐全，但来源混杂、重复和上下文负担巨大；不选择。
- B **继续每轮增加一份独立研究报告**：最易做，但知识越积越碎、重复的“专业术语”不进入实用判断；不选择。
- C **保留原件可追溯＋当前知识总索引＋一张跨域总图＋有需要才深入的专题研究**：可延续已有 F01–F07 和 P1–P8，降低重复与纠错成本；**首选**。

**实践中的文件权责**：README=目标；INDEX=按问题查；本总图=概念与机制联系；专题文档=完整论证；research=调查过程；decisions=方案历史；evaluation=真实效果；planning=待审工作方式。词汇/学科增长后优先新增索引关系，只有独立知识对象和长期查找需要时才新增子目录。

## 2026-11-13｜D12：Blix 旧专业知识从静态归档进入可检查的调用

最新整合见[项目P1/P2全域知识对照](../references/p1-p2-knowledge-reconciliation-20261113.md)，不替代本文件原有“意图理解—发展—选择”的非强制认知原则。

**已有可测试组件**：`server/intelligence/local-knowledge-loader.mjs`现阶段在只读允许列表中，根据用户问题的词面与局部经济证据，选择最多几篇历史专业文档、抽取短片段、记录源路径与SHA256版本；`trustedAsInstruction:false`且 `RESEARCH_NOT_RUNTIME_VALIDATED`。有关RED-COHORT数值撤回有强制警示。它由 `ai-workflow.mjs` 可选注入解释阶段；这说明**调用路径和合成测试存在**，不说明模型已经正确理解152旧单元/全部参考项目。

**真正还需验证的问题**：
1. 口语混合“钱包/资金/同Slot/卖出/跨Mint”时，能否区分链上事实知识、经济机制假说、市场执行知识，而不是词重最高就算对？
2. 选中的短片段有无忽略正文中最关键反证、源版本和适用时段？若来源内容过时/撤回，是否避免引用其数值？
3. 模型是否主动选择必要事实工具并补查，还是只复述知识？未授权工具、额外Mint或交易动作必须拒绝。
4. 需要比较Skill Reach式“应选/误选/应不选”的任务集合和无知识基线；事实错误、补查、成本是成效指标，不能以路由条目数或提示词长度替代。
5. 完成一次调查后的结论修正应回到原领域文件，记录新实证、替代解释及反例，而不是继续增添强制步骤或新专家组织。

**目前最重要的认识**：旧研究是可随问题调用的专业候选材料，不是预训练已确认事实。模型负责解释与形成新假设，确定性链上解析/经济核算与数据覆盖由相应程序及独立复核负责；二者要协同但不能互相冒充。


## 2026-11-13｜D12：一项知识从来源到模型判断的可逆追溯

完整的概念、知识命运、状态维度、实际源码承接示例与剩余缺口统一维护在[Blix知识全链追溯](../references/knowledge-lineage-lifecycle-20261113.md)，本文件不再复制第二份知识制度。对一个重要结论，应能反查：**用户问题/权限 → 选中的来源与版本 → 原文主张/适用边界 → 报告所用RPC事实/原始签名 → 解析与解释程序 → 测试/真实运行 → 后续纠正**。

专业知识本身不必有代码落点。保存 \`SOURCE\`、\`CONCEPT\`、\`CLAIM\`、\`METHOD\`、\`CASE\`、\`DECISION\`、\`EVALUATION\` 时分别考虑证据与适用性；旧知识可以被复用、修正、推迟采用或拒绝误用，不能静默改写历史来源。当前本地词面选源只验证部分路由与离线单测，不证明AI对源主张的解释质量；重要经济判断仍以原链上事实、完整性和竞争解释为准。

用现有 D12/AI 源检索回答“知识来源、获取、承接、追溯、继承、转换、失效、变更影响”等问题时，先检索[知识全链追溯](../references/knowledge-lineage-lifecycle-20261113.md)及所指的原领域文件；它是参考说明，不是更高优先级提示词，也不给模型交易权限。
