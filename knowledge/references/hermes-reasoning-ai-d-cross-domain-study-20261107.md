## 二、Hermes真正值得继承的是两种相互制约的知识生产方式

### 2.1 00d：先从专业问题出发重组数据

原文将同一批GMGN字段置于不同问题下，形成钱包角色演化、行为相似、SM质量、市场微结构、生命周期、策略适配等不同推理视角。重要之处不是“230字段”或“37 L1+16 L2”数字，而是：

`想理解什么经济问题 → 应该留下哪些可观察痕迹 → 现有数据能否表达 → 如何组合与反证 → 哪些仍未知`。

例如钱包在一段时间内减少持仓，可分别解释为获利卖出、转到新钱包、流动性操作、账户归属变化、统计窗口错配。只看GMGN单字段会混淆这些机制。

原文对同源、相近成本、相近时间的“三重合”使用“极高概率同一实体”措辞；**这不是经过校准的共同控制概率**。同交易平台、同信号机器人、相同热门时点、供应商标签误差等是竞争解释。适合作为候选特征，不可直接继承为身份结论。

原文关于1m K线买压、价格冲击、阈值与策略有启发，但OHLCV无法唯一重建主动买卖方和具体池子的成交冲击；不同池深度、AMM曲线、手续费、滑点和聚合路径需要更细事件。不能把示意公式当链上事实。

### 2.2 00e：不预设已知模式，从无法解释的异常反向生成新问题

原文给出六条生成路线：
1. 数值字段配对/差值/比值探索；
2. 已知结果样本之间的异常对照；
3. 无预设标签的相似性聚类；
4. 对既有结论构造对立假说；
5. 同一Mint的连续时间变化；
6. 跨链差异对照。

这些是**候选假说生成器**，不是自动产生真理的算法。尤其“80数值字段得到3160配对”仅是组合数示例；任意组合的显著性、后验命名和少量历史案例容易产生数据窥探与伪规律。原文“5–10%意想不到”没有在所读文件中给出实证支持。

真正高价值的研究动作：遇到无法解释的结构时，先保留它的原始事件/字段与未解状态；同时从数据错误、共享服务、独立策略、共同控制、库存转移、池间再平衡等多个机制生成不同预期；随后寻找能够**区分这些解释**的新证据，而不是先取一个“庄家模式”名称。

### 2.3 Hermes 的筹码控制权设计提供第三条关键约束

`Skill4-筹码控制权状态层设计.md` 不只输出状态，还定义了输入时间对齐、数据有效期、基础设施剔除、UNKNOWN原因、状态转移合法性与“已退出实体权重为0”。这提示：即使发现了某种关系模式，也必须询问**这种结构现在还有效吗**。

但其中“贝叶斯状态更新”、0.45/0.25等加权分数和`status_confidence=0.68`均属于设计规格；未在本次阅读中看到真实似然估计、先验校准或外部样本验证。**公式写成贝叶斯形式不自动使概率可靠。**

## 三、qb-与meme-的独特价值：不是旧项目附属品

### qb-：从单个Mint落实为可调查、可追踪、可复查的对象

`sikk_gmgn_token_report.py` 实际源码调用GMGN CLI读取Token info/security/pool及多种持有人/交易者视角，将不同列表按地址聚合，输出8类CSV和报告。其中`04_key_address_matrix.csv`同时保留角色标签、资金来源、Token去向、证据等级、复盘优先级；`05_infrastructure_registry.csv`区分基础设施与普通钱包；`07_review_plan.csv`保留后续复查任务。

重要认识：**研究对象不能只有“某种模式”，还必须能定位到具体Mint、钱包、来源、历史时间、证据缺口与下一次观察。** 这恰好连接Hermes生成新假说与Blix持续观察。

限制：`classify(w)`中的证据等级、优先级与供应商字段是程序规则，不能仅因输出CSV而视为链上核实；CLI可用性、字段时效、供应商价格/授权均未本轮实跑验证。此处也不直接继承原交易动作字段。

### meme-：从“解释市场”进一步逼问“机制是否可验证”

`第一控盘区成本中枢回收模型_成熟度审计.md` 明确将POC/AVWAP二次接受设为Level 2/5的结构化观察模型，承认尚无完整检测器、统一锚点、量化阈值和严谨回测。它特别指出：同一个“重新接受成本区”的叙述，在不同AVWAP锚点下可产生不同结论。

重要认识：**机制解释与可重复识别、可交易、可回测是不同成熟度。** 市场结构术语是研究线索；需要明确观测对象、时间、价格来源、成交量/池覆盖、风险反例、可退出性。用户当前不以K线为主要入口，不应因此丢弃meme-对成本锚、接受/拒绝、失败反抽的专业问题，但要转换成可用的链上资金/库存/执行事实检验，而非直接复制K线策略。

## 四、引入 ai-d 的跨学科思考：专家视角是问题生成器，不是投票席位

针对“一个Mint在拉升前6小时多钱包互转，之后部分新地址卖出”的**假设场景**：

| 学科视角 | 必须提出的独立问题 | 它如何改变原来的研究 |
|---|---|---|
| 科学哲学/溯因 | 同一观测可能由哪些不同机制生成？哪条反例会推翻最吸引人的解释？ | 不让“庄家”成为默认结论 |
| 数字取证/分布式系统 | 每条转账是否有原始签名、指令/CPI、token owner、slot、时间、完整历史和可复算资产净变化？ | 把观察与供应商解读分离 |
| 图论/实体解析 | 共同资助、共同fee payer、服务Hub、转移接力分别建立什么类型的边？多跳是否会错误传递共同控制？ | 从钱包标签升级为多关系证据图 |
| 经济学/微观结构 | Token移出是否真的减少该经济主体库存？转入池后是否产生对价？是否存在跨池/跨币资本循环？ | 把地址移动与经济仓位区别开 |
| 统计/机器学习 | 异常阈值是否在观察结果后才选定？大量字段组合是否产生偶然相关？基线/留出样本是否可比？ | 探索与确认分离 |
| 控制理论/状态估计 | 结构状态是否已过期？观察频率能否捕获角色替换？失效与暂时缺数据如何区别？ | 把静态归因改成随时间修正的候选状态 |
| 组织行为/博弈论 | 同步行为是同控、共同信息、共同服务还是相互模仿？参与者收益与激励是否一致？ | 生成新的竞争机制与可区分的后续观察 |
| 软件产品/知识工程 | 新知识何时调用、改变了哪条调查结论、怎样在Blix报告中说明、如何与无知识增强版本对照？ | 从“保存知识”转为“改变判断且可验收” |

这些视角**不是固定8个专家Agent**；只有其问题改变了证据要求、竞争解释、可证伪条件或产品判断，才在具体任务中采用。不同视角之间的冲突应回到数据，而不是多数表决。

## 五、旧知识怎样真正进入Blix：四种融合结果，先理解再归位

1. **保留来源全貌**：Hermes原始`00c/00d/00e`、筹码控制权文档、qb-程序、meme-审计继续保留在各自仓库，Blix记录版本、路径与尚未审阅部分；不能因已摘要就删除原研究。
2. **形成新专业认识**：本篇把“问题驱动重组—异常驱动生成—竞争机制反证—时效与库存约束—可追踪调查对象”连成一条知识关系；归于Blix既有`references/`研究正文，并链接`mechanisms/`和`methods/`相关材料，不新建固定专家制度。
3. **按任务调用而非全量塞提示词**：当Blix面对异常资金/钱包群体时，AI先读取该Mint的证据及最相关研究，再决定是否需要Hermes反向生成、qb-证据矩阵或meme-成本/接受机制；ai-d指导“为什么选这份知识、它改变哪个解释、什么时候不用”。现阶段仅是**设计中的调用方式**，不声称Blix运行时已经接通。
4. **由证据推动产品改进**：只读报告可先区分“链上观察—候选机制—竞争解释—缺失证据—后续观察”。如果对照证明Blix已有输出会误导，才提出最小代码修改与离线回归；不把知识迁移自动等同于改写程序。

**核心研究链**：

`Blix观察到的异常 → Hermes 00d提出多维专业问题 → 00e生成未知机制候选 → qb-定位Mint/钱包/证据与复查 → meme-质疑成本/执行/策略成熟度 → Hermes状态层质疑时间有效性 → ai-d决定何种知识有信息价值 → 原始链上证据反证/修订 → Blix只读报告与持续监控`。

该链不是一条已实现的运行时Pipeline，而是基于原始资料形成的**待验证知识转化逻辑**。

## 六、发现的冲突、错误前提和新未知

- **同源+同时间+同成本不等于同控**。三重合只是更值得核查的关系候选；共享服务、热点、机器人模板会制造伪相关。
- **任意字段组合不是自动创新**。没有样本外验证、多个假设的比较与稳定的经济解释，“新框架”可能只是数据窥探。
- **经济主体库存不能由单一Holder快照证明**。卖出、Token转移、授权、池Vault、跨币资金与经济受益权必须分层。
- **筹码控制权“概率”不能只凭手写加权和贝叶斯符号成立**。先做可靠状态与UNKNOWN，再研究概率校准。
- **qb-报告的证据等级不是天然证据强度**。供应商标签、启发式分类和原始链上验证需独立展示。
- **meme-的K线成本锚不等于真实链上持仓成本**。交易费用、转移、历史缺口、多个池子及跨币资本流动会造成差异。
- **反向生成机制不应只围绕庄家**。正常市场的模仿、信息扩散、套利、机器人基础设施和多池迁移，同样可能解释看似协同的行为。

## 七、结论：Blix应继承旧项目的“认识生成能力”，不是旧项目的标签与硬编码结论

**优先级**：Hermes 00d/00e方法与其失败边界 → Hermes 00c和两份大体量原始研究及grill-sessions交叉核查 → qb-的证据矩阵/数据来源与真实输出 → meme-的市场结构假设/反例与成熟度 → Blix本地报告/监控可读、可解释、可复核的知识调用。并行核查，不应把单仓研究做成封闭阶段。

## 八、下一轮研究：按证据缺口推进，而不是再造目录

**主研究任务：Hermes 00c–00e + 两份大文档的纵深复原。** 首先完整阅读 `00c-GMGN-思维模型提炼.txt`、`gmgn-byte-combination-reasoning-v0.1.md`、`gmgn-byte-decomposition-v0.1.md` 和 `grill-sessions`；逐项还原从原始GMGN字段到派生变量、机制假说、反向异常的推理链。审查字段是否真实存在、字段口径、观察时间、历史来源、示例阈值、反例与“230字段”假设是否可靠。**产物**：原始问题→字段证据→候选解释→竞争机制→可推翻条件→Blix对应数据/缺口的详细研究，而非一个标签表。

**并行对照：qb-与meme-。** 深入qb-`sikk_gmgn_token_report.py`的`classify`、数据汇总、基础设施边、源字段/优先级和实际测试/样本，追问能否支持Hermes的角色与资金假说；深入meme-策略、庄家周期、指标/回测、失败案例和`SOURCE_OF_TRUTH.md`，检验市场结构解释是否有可重现经济机制。**产物**：至少一条“旧解释被纠正或扩大”的跨项目新认识和一个具体Blix报告验收用例。

**ai-d方法检验**：用同一份静态Mint调查材料比较 A: 只使用Blix现有知识，B: 按需引入Hermes+qb-+meme-并进行跨学科反证；观察新问题发现、错误身份归因、证据缺口识别、结论准确性和上下文负担。没有可重复数据则标记“未测”，不宣称认知提升已被证明。

**边界**：不交易、不签名、不付款；任何运行/安装或代码更改均需先满足只读隔离和可复核验收。后续重点是深化旧知识和形成新的专业认识，不增加专家名单、固定步骤或大型框架。
