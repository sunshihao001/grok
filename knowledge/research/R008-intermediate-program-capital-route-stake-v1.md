# R008｜程序账户改变资金路径：从“钱包转账”发现新的经济角色与资本归集机制

> 日期：2026-11-01。与已存在的 [V5 主研究宪章](../../docs/economic-mechanism-discovery-charter-v5.md) 和 [R007 资本流入构成反转](R007-capital-flow-composition-inversion-v1.md) 连续。**这不是 V6、不是增加专家、也不是声称发现真实幕后操盘者。** 
>
> 研究结论分三层：**Solana 官方程序语义已核实；第三方公开报告中的具体交易/数值属于作者源报告；我们从两者组合产生的跨协议资本路径假说尚未独立 RPC 验证。**

## 一、为何这是“发现未知机制”而非又发现一种异常标签

前 R005：首次 funder 最大余额净亏账户未必是真实转账发送者，未知历史更不能判独立。  
前 R006：没有 System Transfer 不代表没有 SOL 流入，Token CloseAccount/WSOL 解包可改变 lamports；收到 SOL 也不等于外部融资。  
前 R007：40 钱包派生记录中，少数 LP 等非直接转账类型占据多数被命名为“融资”的 SOL 金额；仅比较交易数量会掩盖经济价值结构。

**新增事实入口**：2026-10-27 Bitquery 发表调查，作者称在六个 Solana Meme 发币事件中观察到成批钱包通过 *Stake Account* 把 SOL 归集到少数接收地址；其方法不只是搜普通 System Transfer。作者报告 537 个参与小额持币的钱包、几千 SOL 的群组归集，但这是有商业产品背景的单篇案例叙述，所指真实账户与汇总尚未由本项目逐笔 getTransaction 复算。

公共源（按解释力与证据性质区分）：
- 第三方**案例报告**：[Bitquery，2026-10-27，六个 Meme 的钱包群与 stake-account 归集](https://bitquery.io/investigations/solstice-memecoin-bundling)。其内部也承认部分交易所路径只有时间相关而无链上连续资产路径，且不能从账本识别真实人的所有权。
- Solana **协议说明**：[Stake Accounts 官方文档](https://solana.com/docs/references/staking/stake-accounts)，分别定义 `stake authority`（可委托、停用、拆分/合并等）与 `withdraw authority`（可提取及改变相关授权）；Stake Account 地址不一定有对应控制私钥。
- Solana **账户与资金约束**：[Account Structure](https://solana.com/docs/core/accounts/account-structure)，账户 `owner` 是**有权修改该账户状态和扣除 lamports 的程序**，不是现实资金的最终经济受益人。lamports 是账户余额、不是天然的独立第三方注资。

上述来源支持：**Stake Program 的账户控制与资金出入有独立语义，单纯 System Transfer 追踪会漏掉某些真实资产路径。** 它们**不支持**：任一同时间发生 stake 提现的一组地址必然同一人控制，或任何具体六币案已经由我们复核。

## 二、真正新研究对象：资金边 + 权限边 + 经济职责边

原来的“钱包A→SOL→钱包B”图不足以表达：

```text
交易/执行钱包 W
   ├─ 减少 SOL/支付创建 stake-account 的 lamports
   ▼
Stake Account S（由 Stake Program 管理）
   ├─ stake_authority → Authority A （可管理委托等）
   ├─ withdraw_authority → Authority B （可提取及设置权限）
   ├─ 状态/租金/锁定/停用/委托
   ▼
真实 Stake Program 提取/资产路径（原始指令/余额核对）
   ▼
收款人 C
```

**三种边必须分开**：
1. `ASSET_MOVEMENT`：在指令与余额上可验证的 SOL 变动，包括账户创建、Stake Withdraw/Split/Merge、接收者、金额及 Slot/签名/内层位置。
2. `ACCOUNT_AUTHORITY_AT_TIME`：质押与提取权限是谁、从哪个时间起有效，权限是否更换、是否共享。**Stake Program owner ≠ stake authority ≠ withdraw authority ≠ 现实经济主体。**
3. `BENEFICIAL_CONTROL_HYPOTHESIS`：是否为某个经济网络组织的行动，仅能结合独立路径、跨期重复、非公共账户/执行签名与正常基准作为可反证解释。

**金融量纲**：Sweep SOL 总量不等于净利润；本金、锁仓/租金储备、真实交易所得、手续费、资本在账户间重部署必须按经济身份分开，不能把同一 SOL 跨三笔账路算三次收入。

## 三、由此产生的 HX09 机制假说（创造性，不是口号）

> 当链上经济组织使用不同地址、不同账户程序管理资金时，反复出现的**执行角色—权限模式—资产变动—归集目的地**四元时序结构，可能比直接 SOL Transfer 图更稳定，能够识别部分跨 Mint 重复的资本组织行为。

这不是“同一 stake authority = 同一个庄家”。存在至少四种竞争机制：

- **H1 专属运营网络**：资金从多个执行钱包沿可复算的 Stake Program 指令流向较少接收账户；权限/收款/操作节奏在多次发行中反复出现。
- **H2 正常质押/托管服务**：独立用户使用相同中介服务、API、共享管理员、Fee Payer 或策略；协同时间来自例行脚本/服务任务，而不是共同获利。
- **H3 交易所或公共结算**：提现/存入/交易所归集制造大量汇合，地址标签不充分时不能把所有使用者合并。
- **H4 一次性相关但非持续控制**：单次高度同步的执行可能为特定工具批量管理，不构成跨 Mint 持续资本网络；经济路径真实，但不证明一个持久组织。

**有判别力的实验，而非“还需要更多数据”**：
1. 先冻结真实钱包/交易签名和发生时间，原始 RPC 审计 Stake Program 指令（创建/授权、withdraw、split、merge）及 stake account state；余额守恒，保留实际使用的不同协议、手续费和 rent。
2. 在拥有 **stake authority 与 withdraw authority 两种角色、且存在权限更替**的时间序列上建证据图，不能用当前 authority 回填过去时点。
3. 对照只追 System Transfer：量化漏掉的 lamport 移动笔数/金额、找回的真实路径，以及误连上公共服务商的假共同源。
4. 在同协议、同小时、账户活跃度和普通质押服务使用习惯下取未选择的正常样本，对“同步收款”“共同权限”“共同 fee payer”“跨 Mint 再部署”分别做单特征与组合对照。
5. 冻结首次观察时点，在后来不同 Mint/新地址群体中测角色四元结构是否可重复。若移除服务商/公共账户后提升消失，则撤回 H1 的专属运营解释，不推迟到“未来再说”。
6. 若能发现 Stake Program 更改权限后同一资产经不同地址回到原资金网络，优先解释为“资本可追溯路径”；是否同控仍要另作证明。

**停止/否定条件**：
- 未能从真实原始指令重建 Stake 资金路径 → **此特定资产路径不能称已证实**，先审计来源解码或舍弃；
- 共享权限/同步性在正常服务基准中同样普遍 → **这种特征不是该样本中的有效专属识别指标**，不包装成“低置信度庄家”；
- 在留出 Mint 无额外预测力 → **否定跨发行推广/市场用途假说**，即使历史群体本身真实存在；
- 真实 Stake 资金流存在但没有完整 SOL/Token 回流 → **只保留已验证的资金事实**，不捏造闭环或净利润。

## 四、反向审查第三方报告：正确的认识为何需要果断纠错

该报告同时存在几种不同力度的表达：
- “群体资金通过 stake account 集中退出”是作者基于自有数据的**可复核案例主张**；
- “同几秒归集本身就证明一个所有者”是**推理过强**：同步可以支持协同候选，不能单独证明最终经济受益权，尤其在共享自动化服务下；
- “共同交易所充值地址必然相同实际所有者”同样是**推断规则不成立**：可以构成路径线索，若地址本身接收很多独立来源，则排他性进一步下降；公开报告亦明确一条充值地址此前接收约五十个来源。
- “通过交易所后发生的同步金额是原资本直接流向另一钱包”是**尚未证实的资产连续性**，即使资金发生时间相近，也不能补上交易所内部账。

这里不需要机械地把所有断言“降级一点点”。**作为充分条件的归因规则错误，应直接否定；底层可能真实发生的交易，应保留等待独立重放。**

## 五、给当前已有知识体系的最小增量，不重造专家/运行架构

**研究层（V5）**：新触发 `INTERMEDIATE_PROGRAM_CAPITAL_ROUTE`。只要原有 SOL/Token 追踪无法闭合，但存在 Stake/Token/LP/Bridge program-account 变动，允许发起来源解码与经济身份研究，不要求先匹配已知的“庄家/捆绑/买卖”字典。

**知识层（L1–L5）**：知识图增加账户权限、有效时点与资产流不同的**关系类型**（不必新建第六张图）；经济资本环路的证据依赖 Claim 可被源错误触发重审。

**专家层（现有 17 专家）**：
- `chain,data`：真实 stake-program 指令及资金/权限时间关系；
- `graph,wallet`：地址角色、控制候选与公共服务商分离；
- `inventory,token,liquidity`：真实 SOL/Token/LP/租金的经济守恒；
- `statistics,adversarial`：条件正常基准和跨 Mint 角色模板反证；
- `review,knowledge`：确认新资产机制修正了哪条旧规则，并生成新研究卡，不宣称“专家投票”。

**运行层（V4）**：不必把 Stake 的每条指令送给 LLM 多专家。M1 指令层若已可解析，按账户程序分类记录；只有跨层不闭合、重复结构和信息价值明显时进入深研。**现有 M1 尚未真正覆盖它；本研究没有部署一个 Stake 解析器或全市场监控。**

## 六、下一步可直接检验的量化结果

对同一范围真实历史交易，分别运行：
- `B0` 仅 System Transfer / 普通钱包资金边；
- `B1` B0 + Token CloseAccount/WSOL；
- `B2` B1 + Stake Program 创建/权限/提现与 LP/桥的分类型资金路；
- `B3` B2 + 同市场阶段、公共基础设施对照和跨 Mint 角色时序假说。

衡量**可复算净资产变动覆盖率、假资金边率、错误同控率、跨 Mint 可预注册关系复现率、调查成本、时间可得性**。当 B2 只提高可追踪范围而没有 B3 机制预测增量时，就应该保留 B2 作为数据质量改进，而不虚构“识别庄家”优势。

源数据尚未独立获取，所有 B0–B3 指标都保持**待测**。

**本次认知成果**：未知机制不是“又一种庄家标签”，而是提醒研究从“钱包间转账图”提升到**程序账户资产路径、账户权限、经济角色与条件正常基准相互作用的机制**。这是 R005 → R006 → R007 之后自然产生且可以被证伪的跨领域知识扩展。
