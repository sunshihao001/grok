## 0. 这次真正深化了什么？

“盈利钱包值得跟”包含三个隐含但不必然成立的等号：

```
链上地址的表现 = 完整经济仓位的结果
历史盈利 = 可提前预测未来的能力
原钱包低成本 = 外部观察者可实现的入场成本
```

对真实源文件的交叉审计表明，这三个等号都需要拆解。

旧研究已经提供钱包角色、实体聚类、库存状态与证据 Gate 的概念；取证参考项目提供可复核的创建时交易顺序、钱包转移、实际发生的执行路径；meme- 提供市场阶段/成本区域语义。我们要做的不是把它们合成一个“聪明钱综合分”，而是识别：**在什么市场状态下，一种地址行为是资金路径证据、执行能力证据、预测证据，还是根本无法复核的后验描述。**

此研究给出两类实际结果：
1. 从 42 个发行事件的源文件中完成一项**跨数据表的数量一致性复算**，定位未闭合账本的缺口；
2. 从单 Slot 内的真实记录生成一种**更严格的执行优势与信息优势鉴别问题**。

## 2. 可复算的新结果：42 个仓位账本中有 20 个必须继续核对

对每个 Mint，定义：
- `Q0 = sum(v03.buys[].tokens)`：仅创建 Slot 已记录的初始买入数量；
- `T = sum(v07.wallets[].tokens_transferes)`：相应 Token Account 后续**累计被标为 TRANSFER** 的减少数量；
- `S = sum(v07.wallets[].tokens_vendus)`：后续**累计被标为 SELL** 的减少数量；
- `D = T + S - Q0`：两个不同观察窗口和分类口径之间的*待解释差额*。

按完整 Mint 严格连接两个表后，对 42 个事件逐个复算：

| 检查 | 结果 | 解释边界 |
|---|---:|---|
| 能配对的发行事件 | 42 / 42 | 只证明派生表匹配 |
| `D > 0.01 Token` | **20 / 42** | 相对创建 Slot 的流出超额；不等于凭空增发 |
| `|D| ≤ 0.01 Token` | **22 / 42** | 汇总数量大致相等；不证明经济收益完整 |
| `D < -0.01 Token` | **0 / 42** | 本样本无相对初始买入的流出短缺 |
| `T ≈ Q0` | **35 / 42** | “转出”并不自动表示完整初始成本核销 |
| `S > 0.01 Token` | **21 / 42** | 仅指源代码按规则分类为 SELL 的代币减少事件 |

**计算是本轮对 GitHub 源 JSON 逐事件重新汇总的结果**，不是直接摘抄项目 README 的总括结论。

特别值得注意：
- 有一个事件 `5CCnqQy9cyze...`，流出超初始买入量约 **132.33%**；这不可能用“仅转移最初那一次买入且没有任何其他流入”的模型解释。
- 一个事件 `HSAuwh7kJ9sS...` 没有源脚本归类的直接卖出，累计转出仍超过创建时买入约 **6.88%**。
- 有两个事件，初始化买入数与直接卖出数大致相等，而转账数为零；这说明“所有早期钱包主要靠转账出货”同样不能从该 42 例推出。
- 不能把 20/42 写成“47.6% 的交易数据有错误”。当前只证明**不同时窗的数字不能直接作同一张闭合账本**。

### R002 的具体差额与语义

目标 Mint：`87QChghgFr2XBNumi2Tg1MJCWHLqoTTT5KThtnDspump`，创建 Slot `429307208`。

```
Q0：780,464,208.09 Token
T ：780,464,208.09 Token
S ： 18,119,267.30 Token
D ： 18,119,267.30 Token（相当于 Q0 的 2.3216%）
```

这里的 `D` **不是 Token 库存守恒的链上违反量**，更不是该币持仓盈利。它恰好是本次必须继续查找“其他正向余额变化”或检查分类/聚合的缺口。

可证伪问题：在四个地址完整、按 Slot 与交易序号排序的相关账户账本中，是否存在合计至少能解释 18,119,267.30 Token 的**额外买入、转入或其他合法余额增加**？如果有，应精确定位对应交易签名并重算；如果没有，则检查脚本是否发生重复事件计数、owner/ATA 口径偏差或分类不匹配。

必要条件应以每个地址逐笔余额作账，而不是仅凭 4 个地址的合计数抵消。


### R002 逐地址核对：差额不是合并抵消产生的

对同一 Mint 下的四个地址按完整地址键分别连接 `v03.buys[]` 与 `v07.wallets[]`，得到：

| 钱包前缀 | 最初买入 Token | 后续累计归类为转账 | 后续累计归类为卖出 | 需要解释的额外净流入下限* |
| --- | ---: | ---: | ---: | ---: |
| `2AqFJzcg...` | 441,614,045.62 | 441,614,045.62 | 3,406,055.28 | 3,406,055.28 |
| `9yxmCNwZ...` | 178,246,713.26 | 178,246,713.26 | 6,792,216.31 | 6,792,216.31 |
| `2wHHnAmd...` | 98,716,276.95 | 98,716,276.95 | 3,028,033.59 | 3,028,033.59 |

| **合计** | **780,464,208.09** | **780,464,208.09** | **18,119,267.30** | **18,119,267.30** |

*“下限”是**条件性守恒推导**：假设源数据的所有流出均为独立真实 Token 流出、初始库存无其他来源且不允许期末库存为负，那么每个账户必须至少另有表中相应数量的正向 Token 变化，才能满足守恒。这不是已经找到这些流入签名，更不是声称原始数据一定有这些流入。若分类或重复计数不正确，结论随之变更。

特别要注意：`v07` 输出没有逐事件时序，**无法从汇总表判断这些被归类为卖出的事件究竟在首次转移之前还是之后**。所以不能写成“刚转完仓位又卖出”。下一步必须读完整的按签名账户余额序列，才能判断是真实增量买入、外部转入还是分类错误。

## 3. 真正的代码审计：哪一步可能生成“被误认为市场事实”的标签？

在 `code/v07_exit.py` 中：

- `sigs_all(ata, cap=6)` 每页最多 1000 签名，最多读取 6 页；这对高度活跃 Token Account 的全历史读取存在明确上限。
- `classify()` 用相关 Token Account 的 `delta_owner > 1` 标为 BUY，**没有要求这一正增量必须来自市场 Swap**。
- 相关 Token Account 减少且 owner SOL 净增量 `>0.0005 SOL` 时标为 SELL；否则若其他 owner 的该 Token 正增，就标为 TRANSFER；剩余情况标为 BURN/OTHER。**SELL 是一个余额启发式类别，尚非经过程序指令/Swap event 独立验证的成交事实**。
- `buy = next(... kind == BUY)` 只用于第一笔买入时间；逐钱包汇总记录 `tokens_transferes`、`tokens_vendus`，却没有保存后续全部正向余额变动的累计量。
- `part_transferee = T / (T + S)` 是“已归类流出的 Token 中转移所占比例”；并不是“供应量转移比例”，也不是“已全部退出的经济仓位比例”。

因此需要一项具体修正：研究报告中不要直接使用 `SELL`→“真实市场卖出”、`TRANSFER`→“相关经济主体已经退出”两种未经证实的语义替换。

**转换方案：** 对每个 signer's Token Account 留存原始余额前后、Token Program 指令、所涉 AMM/曲线程序、SOL/WSOL 等对价变化、账户 owner、token decimals、费用及交易顺序；由独立解释器定义 `confirmed_swap_sell`、`confirmed_token_transfer`、`unclassified_outflow`。未独立复核的旧数据维持 `vendor_or_researcher_classified`。

对后续完整买入、额外转入及其他 Token 增量也必须合并为 `positive_inventory_events`，避免只汇总减少数后人为制造“多卖出”的研究叙事。

## 4. 执行位置优势：同 Slot 不同价格，为何不是“信息领先”的证明

源代码 `code/v04_slot_order.py` 下载完整创建 Slot，并通过区块中的交易顺序索引识别创建者、早期钱包及外部买入者。此处 index 是**交易在区块中的位置**，不是额外精度的交易执行时刻，也不能当作毫秒延迟。

在 42 个样本中：
- 34 例早期买入索引相邻；
- 31 例首笔早期买入紧随创建交易；
- 41 例在该来源的 BUY 识别规则下，早期序列结束前没有观察到外部买家；
- 37 例具有可比较的 Slot 内外部首位买入报价；这些比值相对早期组 VWAP 全部 `≥3`，中位约 **4.31**，范围 **3.111–17.466**。

R002 单例：创建 index 312；四笔早期买入 313–316；首位记录的外部买入 index 601。四个早期地址共付约 84.9415 SOL，平均买入 780,464,208.09 Token。四个地址由于曲线顺序不同，单钱包的单位成本已相差约 6.80 倍；外部记录的首位买入价相对早期组 VWAP 为 **3.805 倍**。

该现象能支持什么？
- **支持：** 在所记录的创建 Slot 内，交易顺序和执行时的曲线状态共同造成强烈的入场成本分层。
- **不能直接支持：** 四钱包具备超前信息、所有外部交易者都只能在 3.805 倍后买入、普通用户能够在看到已确认交易后插入同一 Slot、该 3.805 倍是实际可兑现净收益。

这一次的认知变化是：**历史钱包的价格优势有时是交易过程中创造的，而不是独立于交易事件的预测信息。**

新提案 `H_order`：在这些早期样本中，一大部分所谓“成功地址”的成本优势可由创建 Slot 的价格曲线和交易位置解释，钱包历史标签在控制这些因素后可能没有额外预测力。

反证测试：在其他未用于发现该模式的发行群体中，使用当时可重现的创建时报价与交易队列顺序构建不依赖钱包身份的基准；若钱包过去的身份和业绩依然在可见时点以后预测独立需求，并在扣成本后为正，则纯顺序优势解释不完整。

## 5. 资金循环：能追到哪一步，就说到哪一步

对 R002 能直接关联的当前派生数据路径：

```text
创建交易 (Slot 429307208)
    ↓
四笔早期买入 (313,314,315,316)
    ↓
四个 Token Account 的首次转移（19,19,28,35 秒）
    ↓
三个 Token 接收 owner：8uSfX74...、eUrS4Fa...、5Xbhac...
    ↓
? 接收者是否进行市场卖出、成交对价多少、库存何时退出
    ↓
? SOL 经过何种地址回流，相关操作者/受益者是谁
```

两笔首转指向 `eUrS4Fa...`，这是**已记录的共同接收通道**，但不能从共同接收直接推出同一实际控制者。

另一份研究 `exit_destination/results.md` 在 8–9 月相关**另一个筛选群体**中记录接收地址在 PumpSwap 进行卖出和 SOL 经多个地址回流等具体结构。其方法可用于设计下一次调查；它的群体结论不能拿来补填 R002 的未知交易，更不能把“中位 81 秒后首次卖出”写成 R002 已证实的退出时间。

更值得探索的非共识假设是：**原始买入者只是短生命周期的库存接收端，而真正决定何时卖出及回收资本的执行能力可能部署在下游地址或服务层。** 但“经济执行分工”和“统一受益人操盘”是竞争解释，不是同义语。

`H_route` 的判别测试：
1. 明确接收 owner 是否为普通钱包、托管账户、流动性池或独立执行服务；
2. 验证每笔 Token 转移是否由真实持钥人签署、是否有额外授权及谁支付交易费；
3. 从接收地址追踪与 Mint 相同的全部真实 Swap、余额、WSOL/SOL 对价；
4. 查证是否重复接收不同发行的库存、是否按固定方式清算以及现金流可能汇入的资金网络；
5. 排除广泛服务多用户的公共 hub 后，才讨论受益实体归并。

若接收者为独立买方而非统一执行体系，这个模型需撤回或改写；若主要转移之后没有及时卖出，便不能继续称其为“已经清算”。

## 6. 市场变化与可证伪优势：三类假设，不急于生成交易规则

### H_order｜顺序优势主导早期成本

**因果候选：** 首个 Slot 内购买顺序 + 曲线价格冲击 → 早期钱包拥有极低成本；外部看到已确认链上事实时已经换了成本基准。

**预期观察：** 收益指标与入场 index、当时池状态高度相关；固定市场条件后，历史钱包标签的独立贡献较小。

**挑战条件：** 冻结真实可见时点和成交模型后，钱包标签仍在独立发行中提供稳定正净价值。

### H_route｜库存执行分工主导表面“出货”

**因果候选：** 早期地址采集 Token → 资产经接收层归集/拆分 → 另一个执行层卖出 → 资金回流或再部署。

**预期观察：** 下游地址的已确认 Swap，而非上游地址的余额减少，才决定新增可售供给是否真正进入市场；单地址 PnL 对完整资金循环不闭合。

**挑战条件：** 下游接收地址只做托管、没有共同行为，或原平台单地址 PnL 已正确计入所有跨地址经济现金流。

### H_risk｜无法复制买入，但库存信息能预测风险

**因果候选：** 在可见时点，上游/下游已确认仓位变化可能领先于未发生的卖出压力、池深恶化或风险状态变化。

**预期观察：** 在价格、成交量、池深、市场年龄和路径延迟相同的条件下，额外加入可见 Token 库存路径，能够改善未来风险预测，而不必提供买入优势。

**挑战条件：** 增量预测全部由已发生的市场价格冲击解释，或数据可得时间滞后于风险事件。此时只保留历史解释价值。

三种假设仍须通过独立市场时段、样本外检验和成本模型审查，不因表述完整就成为已验证 alpha。

## 7. 下一步最小可复现取证单元：逐签名仓位账本

本研究提出一个专注于**记录事实、保留不确定性**的最小案例合同：

- 逐交易输入：`signature / slot / transaction_index / block_time / first_seen_at / source`。
- 逐账户库存：`owner / token_account / mint / pre_amount_raw / post_amount_raw / decimals`；使用原始整数重算，避免 UI 浮点累计误差。
- 逐事件语义：`token_transfer / swap_buy / swap_sell / mint / burn / other / unknown`，保存支持该解释的程序指令。
- 逐现金流：`pre_SOL/WSOL / post_SOL/WSOL / fees / rent / counterparty`，记录无法确证的对价。
- 双图分离：`confirmed_asset_edge` 和 `hypothesized_entity_edge`，不允许把第二种关系写成第一种。
- 库存约束：`opening + all_positive_changes - all_negative_changes = closing`；对每一笔逐账户核实，对不完整数据显式保留 `UNRECONCILED`。
- 可复制性约束：`decision_at` 只能使用 `available_at ≤ decision_at` 的信息；独立计算可执行入场价与卖出价。

**第一阶段最值得新增的数据**：本例四个 Token Account 在创建 Slot 之后所有正向余额变动的签名与数量，以及三个接收 owner 对该 Token 的真实下游交易。在完成库存账前，不应该从当前卖出汇总推导主体真实 PnL。

## 8. 对 Grok 系统的知识转化

本案例已有能力转化价值，但不是买卖策略：

1. **新研究判断：** “同 Slot”必须保存交易顺序；不要把所有 Slot 内钱包当成同价同时入场。
2. **新错误拒绝：** 如果创建时买入与后续流出统计的观察窗不同，必须先对账，不能把差额解释成盈利、卖压或伪造交易。
3. **新问答动作：** 当用户问“它卖了吗”，优先分开 Token 转出、Swap 卖出、接收者仓位、资金回流和受益人假设。
4. **新取证优先级：** 在提高钱包评分之前，优先查后续正向 Token 变动和接收者实际卖出对价；这是决定当前解释能否成立的高信息量证据。
5. **新效力界限：** 对一个参考项目的异常结构说明“看到了什么”，只能在决策当时已有信息和独立执行评估下，才能说明“跟单能赚多少”。

未完成事项：本项目尚未重新向 Solana RPC 取回原始交易、未做完整的资金与 Token 守恒复原、未验证任何市场正净优势、未进行 Grok 云端 Bot 盲测。本报告内容不自动写入生产 `rules/` 或模型固定标签。

**认知引导词：** 由原始资产账本纠正地址叙事，由 Slot 价格形成分辨执行与信息，由独立对照识别真正可复制的经济优势。
