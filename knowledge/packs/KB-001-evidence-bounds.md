# KB-001｜证据、语义边界与反证基础包（参考级）

- 版本：0.1.0；阶段：`reference_only`；更新：2026-10-29。
- 目标：让 Grok 监控 Bot 在读到真实数据之前就知道「能说什么、不能说什么、为什么需要更多数据」。
- 非目标：继承 Hermes runtime、复制全部知识库、生成买卖建议、认证庄家、预测盈利。
- 真源：`knowledge/registry.v0.json` 中锁定的 **仓库、commit、文件路径、blob SHA**；源仓库本身继续拥有原文真源。本包只是跨仓综合理解，不替代原文。

## 1. 分清四种对象

1. **原始事实**：交易签名、slot、时点、池地址、按已核实单位表示的字段值；保留原始引用和采集时间。
2. **归一化观测**：如 `liquidity_usd`、`top10_holder_pct`。必须写出来源映射、单位、分母、更新时点、适用池；映射未验证则为空。
3. **解释性假设**：例如「有筹码集中」「可能在派发」「成本区重新接受」。需要列竞争解释、反证与缺失项；不得写成确认事实。
4. **可执行研究规则**：需先锁定定义、字段、样本、成本、时间边界，再用样本外及对照实验审查，最后经人类接受才能晋级。KB-001 不含此类规则。

**为什么这样分层？** 原工作流的 handoff 契约要求 `evidence`、`counter_evidence`、`missing_fields`、`downgrade_reasons`、`valid_until`。qb 的数据护照进一步要求区分存量事实、结构证据、行为推断、缺失信息和可继续使用状态。两者合并比复制 Hermes 控制平面更适合跨 Bot 协作。

## 2. 第一轮只处理四个解释问题

### A. 流动性下降

- **观测**：同口径池的流动性下降（工具字段未经独立确认前，只是来源报告的值）。
- **不能直接推断**：某地址撤池、死亡盘、发生 rug、预期收益变负。
- **竞争解释**：池切换、报价资产价格变化、口径/汇率变化、真实退出、另一个流动性池承接。
- **所需补证**：池标识、两个时间点及源字段、链上流动性变化事件、交叉池和报价资产价格。
- **当前输出**：仅 observation alert；不可升级为交易 gate。

### B. 前十持仓集中度上升

- **观测**：同口径 top10_holder_pct 的百分点变化。
- **不能直接推断**：同源控盘、聪明钱囤货、庄家建仓。
- **竞争解释**：小地址退出导致分母变化、托管账户、LP/CEX/PDA 未过滤、token account 与 owner 混淆。
- **所需补证**：地址实体映射、所有者账户及排除规则、历史余额变化、关联资金和时间簇。
- **当前输出**：结构风险候选问题，未确权。

### C. 数据缺失与冲突

- **事实纪律**：缺失不是零值；GMGN 标签不是最终钱包角色；上游 `ERROR` 或过期状态不能被报告为已完成。
- **数据护照最小字段**：token、来源/原路径、已有事实、已有结构证据、行为推断、缺失项、来源时间、置信边界、下一补采、是否可继续。
- **处理**：关键数据缺失 → `NEED_MORE_DATA` 或停；非关键缺失 → 留下降级原因并限制解释范围；反证冲突 → 显式列出，不凑出确定叙事。

### D. 第一控盘区与重新接受（仅假设）

- 源理论认为，早期成本区不是随意低位箱体，也不能以**事后大涨**定义早期控盘；POC/AVWAP「触碰」≠「站回」≠「停留/回撤不破/二次推进」。
- **迁移保留的是术语和常见误判**，不是将该模型宣布适用于 Solana DEX 的实时复制交易。
- 若缺少可重建的成交分布、AVWAP 锚点、K 线序列、池迁移历史，则应输出 `未能检验`，不能套用图形叙事。
- 阈值（例如几根 K 线才算接受）和因果解释在源库仍属待校准，不能混入 `rules/monitor.v0.json`。

## 3. 证据卡（每一次新解释必须填）

```json
{
  "hypothesis_id": "H-EXAMPLE",
  "token_address": "REPLACE_WITH_REAL_MINT",
  "observed_at": "ISO8601 with timezone",
  "raw_sources": [{"repo_or_provider": "...", "ref": "...", "captured_at": "..."}],
  "facts": [{"field": "...", "raw_value": null, "unit": null, "source_ref": "..."}],
  "inferences": [{"claim": "...", "method_version": "...", "scope": "..."}],
  "counter_evidence": [],
  "missing_fields": [{"field": "...", "severity": "high", "recovery_action": "..."}],
  "competing_explanations": [],
  "failure_conditions": [],
  "valid_until": null,
  "review_state": "REFERENCE_ONLY"
}
```

数据真实前不要把占位值当成真实记录。不得因观察结果改变事前定义。源库反证设计明确强调 B（符合但失败）、C（漏掉上涨）、D（疑似死亡盘）、E（图形成立但无法执行）类反例；**任何能用未来行情才能发现的特征都不能成为实时监控准则**。

## 4. 四个验收问答（Bot 必须能回答）

- **问**：「流动性跌了 30%，是否确定撤池？」**答**：不是；核验池标识、计价口径和链上交易证据，列出替代解释。
- **问**：「前十大地址比例上涨，能直接称控盘？」**答**：不能；先排除托管/LP/PDA 并核验资金关系。
- **问**：「只触碰一次 POC，算重新接受？」**答**：不算；缺少停留、回撤和再次推进证据，而且模型当前是研究假说。
- **问**：「这个指标缺失可以当 0 继续评分？」**答**：不可以；记录 missing/downgrade，决定重采或 `NEED_MORE_DATA`。

## 5. 本包自身的反证条件

- 原文与摘要概念冲突 → 以源仓对应真源目录和当前主线判定，本包降级并修订。
- 证明某一个数据来源的「顶十占比」分母不一致 → 暂停跨时点比较。
- 发现指标有显著漏报/误报或受池迁移影响 → 先修口径，**不**调高或调低阈值掩盖错误。
- 如果更简单的单指标解释与复杂叙事同样有效 → 复杂叙事不升级。
- 本包不是表现评估证据。不能声称其提高了准确率、收益或监控覆盖率。

## 6. 有选择地延后迁移

- **KB-002（待审）**：钱包实体/资金关系/时间簇。依赖地址排除、原始交易和缺失覆盖率，必须补 Solana 链上验证；`qb-` 是实现候选，不是事实真源。
- **KB-003（待审）**：生命周期/筹码控制/死亡盘竞争模型。先定义可观测反证，保留争议模型，不立即变成高分即 BLOCK 的机制。
- **KB-004（待审）**：跟单可捕获性：检测延迟、复制滑点、手续费、抢跑竞争、交易失败、卖出流动性、钱包选择偏差；作为是否存在**正净期望**的独立证明层。
- **KB-005（待审）**：追踪工具、GMGN 字段验证、Telegram/开发者/跨市场线索。按来源可靠性分层，不以关键词命中数代替证明。

## 7. 真源优先级

1. 安全与执行边界：本仓 `AGENTS.md`。
2. 源理论定位：`meme-/SOURCE_OF_TRUTH.md` → 核心分线主文档 → 样本记录 → 吸收笔记；检索材料不能推翻已冻结定义。
3. 证据字段：`-/design/phase0-workflow-contract.md` 与 `-/docs/missing_data_policy.md`（只是历史规范，Grok 只实现受测子集）。
4. 数据护照：`qb-/hermes_harness/.../wallet_intel_data_passport_rule_v2.md` 只吸收可跨框架移植的语义。
5. 任何演示/模拟/fixture 不得冒充已验证的现场信号。
