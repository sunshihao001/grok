# D12｜GPT 知识研发、GitHub 版本、Grok 执行与持续进化

> **现有专家**：E-L7-01 知识综合专家；E-L7-02 冻结监控专家（L0 共同审查）。**研究状态**：八个知识单元已编写机制解释与错误边界；协议核对、实证和上线各需独立证据。
> **来源与内部研究**：docs/gpt-build-grok-run.md；docs/local-runtime-framework.md；knowledge/transfer/README.md；knowledge/experts/registry.v1.json。

## 专家真正要解的问题

把研究能力做成可传递、可定位、可审阅、能在本地程序中调用的专业知识；GPT 负责研发，GitHub 保存固定版本，Grok 云电脑按批准程序运行而不现场发明规则。

## 从最小单元到系统能力的八部分

### D12-01｜L0–L7、D01–D12 与知识类型

**机制/专业能力：** L 层代表研究职责，D 域代表专业主题；K0 常驻护栏、K1 按需知识、K2 真实观察；F0–F6 审批门、C0–C4 教学深度不要混成新本体。

**不能发生的推论跳跃：** 创建新章节不能自称已安装 Bot 或已具备实盘研究能力。

### D12-02｜现有 21 位专家的认知职责

**机制/专业能力：** 每位专家以专业问题和机制解释为主体，选 1 位主专家+必要挑战者；相同来源不能重复投票加权；专家角色与真正 Grok Bot 不同。

**不能发生的推论跳跃：** 把 21 位专家同时发言不等于知识更深。

### D12-03｜B01–B07 分工与知识搬运

**机制/专业能力：** B01 组织研究、B02 数据、B03 资金、B04 策略、B05 反证、B06 独立 QA、B07 单监控；研究、审批、上线权限不应合并。

**不能发生的推论跳跃：** GitHub 的 Bot 文件不会自动在 Grok UI 创建 Bot。

### D12-04｜原始参考、来源准入和引用

**机制/专业能力：** Hermes 方法、meme 策略、qb- 数据与程序、Why-Solana 对抗方法、OKX 官方 Skills 逐域研究；固定版本、许可、隔离和未复验结论必须可追踪。

**不能发生的推论跳跃：** 整库复制不代表 AI 真懂；未经审计论文不能直接进生产知识。

### D12-05｜知识最小单元到专家纵深研究

**机制/专业能力：** 每个主题至少有对象、机制、竞争解释、专家问题、条件、专业交接、知识状态和来源；深度专题先由专家真实问题激发再回原理。

**不能发生的推论跳跃：** 只有标签、术语或技能名称不构成专业知识。

### D12-06｜可复用本地程序和 Grok 运行边界

**机制/专业能力：** Python 3.11+ 离线入口、SQLite 研究任务队列、Git checkout SHA、doctor、合成样例和回归测试已在项目定义；真实 Grok 云部署要单独核查。

**不能发生的推论跳跃：** 运行 CI 与一次合成 demo 不能证明真实网络接入或长期稳定。

### D12-07｜数据源、计费、权限与安全护栏

**机制/专业能力：** OKX/GMGN/RPC 真实调用按授权、费率/限流、只读参数白名单、日志、凭据隔离和审批处理；私人签名、swap、自动收费绝不从研究阶段偷偷启用。

**不能发生的推论跳跃：** 标为 read-only 的 API 调用也可能存在第三方收费副作用。

### D12-08｜知识反馈、版本更新和冻结发布

**机制/专业能力：** GPT 提案 → 独立草稿 PR → 审查/测试 → 人工批准固定 SHA → Grok 按批准版本运行 → 报错反馈 GPT；研究假设与 B07 Monitor 冻结规则有隔离。

**不能发生的推论跳跃：** 知识被研究、考试通过、源文件提交均不等于获批交易或部署。

## 体系内位置与下一层思考

深入研究应从可观察的账户/字段与时点开始，经本领域的专业机制与替代解释形成可检验的研究命题；交易经济性与发布等级由 D09、D11、D12 严格分开。只有知识理解不要求立即有单币样本，但市场 Alpha 绝不能仅凭理论成立。
