# L0｜知识、来源、研究权利和版本治理（12 领域的横切基础）

> **定位**：L0 本来就是现有 L0–L7 的一层，但原本体没有把它定义为新增 D13。这里将它作为**所有 D01–D12 的共同治理能力**，不创建新领域、新专家或 Gate。现有 E-L0-01、E-L0-02 负责不同的证据与语义问题。状态：研究治理知识草案；不表示每条外部资料都已经验真。

## L0-01｜项目目标、边界和权威归属

GPT 优先研发专业机制与可调用程序；GitHub 管知识、版本、源码及测试；Grok 云电脑仅按审阅过的工作流运行。主分支、外部计费、交易与私钥操作均须独立授权。**研究完成不等于部署，部署不等于盈利。** 

## L0-02｜来源链条与版权

每份来源应固定 `repository + commit(40 hex) + path + license`。区分官方协议源码、一手链上日志、平台 API 文档、用户项目旧方法、独立论文及未经复算的研究结果。历史知识可借其问题和方法，但不能大段搬运限制性第三方文本。

## L0-03｜主张的知识等级

分成可核查的协议事实、平台自述定义、原始链上观察、经济机制推导、经验研究假设、独立复验结果和冻结后批准规则。**理论知识丰富不等于某条假设已经通过市场实证。** 所有级别可互相引用但不得无证据升级。

## L0-04｜版本、时钟和冲突

区分来源发表/提交时间、事物发生时间、数据被捕获时间、模型获得时间以及判断时间。后来提交、回填和同源转载不得冒充独立的早期证据。冲突双方应同时保留至可由原始来源区分。

## L0-05｜负面知识与失效储存

不只保存“发现了什么”，还必须保存机制失效场景、不可识别经济主体、原始日志不足、供应商字段变更、部分模型被推翻和研究尚未完成。防止知识库每轮重置后重新产生已知错误。

## L0-06｜K0/K1/K2、F0–F6、C0–C4 分离

K0 常驻必要约束、K1 按需专业资料、K2 有时间及源的观测；F0–F6 是研究/发布门槛；C0–C4 是知识教学深度。它们不是与 L/D 并列的新领域，也不能把课程通过当成市场规则批准。

## L0-07｜专家冲突与复合知识判断

只调真正掌握不同机制的专家。主专家解释该问题的经济因果链；挑战专家指出不同的现金流、权限、供给或时序机制。多人同意若使用同一信息源，不构成多份独立证据。E-L7-01 负责保留分歧，B07 不靠共识修改冻结规则。

## L0-08｜完成定义和失败报告

区分：目录单元已存在、专业内容已编写、源语义已独立核对、机理已被挑战、市场总体研究已验证、工作流可离线调用、Grok 云电脑已实测、B07 已运行。每个状态必须有不同证据。发布清单不能只写“完成”。
