# D01｜Solana 交易、账户与可观测事实

> **原有专家入口**：E-L1-01 Solana 交易逆向与账户关系专家。**知识状态**：本篇是 GPT 专业知识整理、机制推导与问题地图（不表示这些单元已完成独立验证）。
> **原有知识与来源入口**：knowledge/domain/L1-L2-chain-market.md；https://solana.com/docs/core/transactions；https://solana.com/docs/tokens。

## 专家的中心问题

先问某笔链上记录真正改变了谁的什么资产；其次才讨论它是否意味着买入、持仓或控制。

## 从基础对象到专业机制的八个知识单元

### D01-01｜Mint、Token Program 与 decimals

**这个知识真正解决什么：** 同样的 Token 名称并不是同样的资产；以 Mint、公钥、Token Program、精度、供应权限建立身份。Token Account owner 与程序 owner 不同。

**必须拆穿的误解：** 符号相同、价格相近、平台标签相同都不能合并 Mint。

### D01-02｜System Account、Token Account、ATA 与 PDA

**这个知识真正解决什么：** ATA 是默认 Token Account；同 owner 可有多个 token account；PDA 可按程序规则授权；创建 ATA 的 payer 不等于受益人。

**必须拆穿的误解：** 不能把一个 Token Account 当一个自然人，把 PDA 当普通私钥钱包。

### D01-03｜Signer、fee payer、delegate 与权限

**这个知识真正解决什么：** 交易签名、费用承担、token 处分与经济受益是四种关系。Token-2022 扩展、Mint authority 与 Freeze authority 需要按标准/程序版本解释。

**必须拆穿的误解：** 看见 fee payer 或转移批准者不能直接推断交易决策者。

### D01-04｜指令、CPI、innerInstructions 与余额净额

**这个知识真正解决什么：** 一笔聚合器 swap 可有多层 CPI 与多条转账腿；先解指令树与账户列表，再看前后 raw 余额、失败状态与费率，避免按转账数统计 swaps。

**必须拆穿的误解：** pre/postTokenBalances 单独不能还原所有中间经济意图；失败交易也可能付费。

### D01-05｜Slot、blockTime、commitment 与重组

**这个知识真正解决什么：** 事件发生 slot、RPC blockTime、processed/confirmed/finalized 与提供商实际收到的时间分别记录；提前可见性不能从历史回填重建。

**必须拆穿的误解：** 交易历史出现的时间不是我方策略当时已知道它的证明。

### D01-06｜SOL、wSOL、rent、token fee 与单位

**这个知识真正解决什么：** lamports、decimals、wSOL 包装/解绑、priority fee、tip、租金资金流分别处理；固定资产单位之后才能计算净额。

**必须拆穿的误解：** SOL 主账户余额差并非严格的单次买入金额，更不是账户最终利润。

### D01-07｜Swap、transfer、mint/burn、LP 的事件语义

**这个知识真正解决什么：** 按经济权利和资产变化区分买卖、内部转仓、供给变化、池储备变化；保留原指令的其他合理解释。

**必须拆穿的误解：** Token 到账或出账不能自动写成买入或获利卖出。

### D01-08｜可回放原始证据与去重键

**这个知识真正解决什么：** 保存签名、slot、instruction 路径、mint、owner、amount_raw、program_id、observed_at、available_at、provider 与来源哈希；按业务事件去重，避免聚合器多腿被双计。

**必须拆穿的误解：** 只有处理后的平台 summary 时，不能声称能精确复算原始 swaps。

## 本领域应该向其他领域提出什么问题

本领域不是孤立百科。研究者须把当前机制向上追溯原始事实、向下追问经济影响：数据口径/交易解码 → D01 内部机制 → 钱包/市场角色或策略 → 跟随者可见性与可卖性。对尚未能由观察支持的市场结论保留竞争解释，不设置主观概率。
