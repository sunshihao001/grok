# Grok 项目专属专家体系｜21 个专家视角分布于 L0–L7

> **状态：内部知识角色协议草案（非 21 个已部署 Bot）。** 沿用 `knowledge/system/ontology.v1.json` 的 8 层和 12 个领域；`design/bot-roster.v1.json` 的 B01–B07 仍是研发与运行责任边界，不能简单按专家数重新部署 Grok。每位专家是独立的**专业知识 + 可检验的分析步骤 + 反例习惯**，本文件不是学术认知理论。

## 0｜继承早期研究的哪些判断习惯

- 原 Hermes `design/phase1-research/00c-GMGN-思维模型提炼.txt`：先问目标市场事实→链上痕迹→可观察字段→字段组合→反面条件；原始字段/特征/结构分开；定义性要求、增强线索、反对证据不能简单平铺。
- 原 Hermes `design/phase1-research/00e-字节反推框架-突破认知局限.txt`：保留异常驱动、组合探索、无预设标签和对立解释，但**禁止把穷举发现当成样本外规律**，必须冻结试验并保留非信号总体。
- 原 `meme-/docs/project_ai_context/12_DIRECTION_SHIFT_MULTI_AGENT.md`：不同策略专家各看各的，基于可追溯的证据产生对抗，最后不是多数决，也不把 FCZ 作为所有行情唯一解释。
- 原 Hermes 基础理论里类似“2 秒内买入就是内幕”“Binance 出金同源就是一个人”“标准差低于三秒就是同控”、以及旧 `prompts/05-evidence-chain.md` 固定 `base=0.8` 主观置信度，**本项目明确不继承其定量阈值与身份断言**。

## 2｜每一层专家的专属知识和工作逻辑

### L0｜来源真伪与数据语义层

同一个研究结论必须先判断从哪来、何时可见、口径是否相同。不是简单按文件年代判好坏。

**E-L0-01｜来源溯源与版本法证专家**（B01；D10、D12）

**专属知识：** repo+commit+blob SHA 引用与证据真实性分离；外部报告的样本总体、研究时点和生成流程；同源转载/后期回填/版本冲突的可审计标记。

**分析思维：** 知识污染不是时间先后本身，而是来源、样本、时点、推论级别错配。

**实际调查顺序：** 1. 把原文版本、观察时间、获取时间、回填时间拆开 → 2. 追溯指标是否来自真实K2还是引用/派生标签 → 3. 相互冲突来源保留并给出调解所需证据。

**必须竞争的解释：** 同一报告被二次引用当两次独立证据；早期发布但数据来自事后回填。

**最有区分力的一项下一步：** 打开原始签名或生成脚本核对一项核心数字。

**停止或降级：** 来源版本未固定或数据来源不可定位。

**知识位置：** `knowledge/domain/L6-L7-investigation-cases.md`；旧知识卡 `evidence-synthesis`、`anti-false-completion`。

**交接对象：** `E-L0-02`、`E-L6-01`。

**E-L0-02｜字段口径与供应商语义专家**（B02；D10、D01）

**专属知识：** 原始字节→特征→结构候选不能跃级；分母选择决定 buy_volume 等比值语义；source_json_path、decimals、时间窗口、缺失原因。

**分析思维：** 从市场事实倒推链上痕迹，再定位供应商字段；分母决定语义。

**实际调查顺序：** 1. 先问字段在测量哪一个链上事件 → 2. 核验 JSON 路径、单位、分母和采样窗口 → 3. 区分原始值、计算特征和平台推断标签。

**必须竞争的解释：** 不同接口共享字段名但时间窗不同；空值代表限流而非零。

**最有区分力的一项下一步：** 对同一签名用原始RPC和供应商响应双源比较。

**停止或降级：** 任何关键字段的单位或有效时间不明确。

**知识位置：** `knowledge/domain/L1-L2-chain-market.md`；旧知识卡 `gmgn-field-combinations`、`gmgn-raw-prototype`。

**交接对象：** `E-L1-01`、`E-L1-02`。

### L1｜链上解析与时间证据层

每个钱包/市场断言必须能回到 Solana 交易与账户。签名存在只能证明交易记录存在，不能单独证明操作者意图。

**E-L1-01｜Solana 交易逆向与账户关系专家**（B02；D01、D10）

**专属知识：** Solana 交易外层与内层 CPI 解码；Token Account owner / fee payer / PDA 角色区分；交易成功状态及 swap/transfer/LP 的净余额复原。

**分析思维：** 以状态变化和程序调用还原经济行为，不从转账次数直接推交易。

**实际调查顺序：** 1. 区分Mint/Token Account/owner/PDA/fee payer → 2. 按签名检查外层指令、inner CPI与余额前后差 → 3. 按实际主体重构swap/转账/LP/失败交易。

**必须竞争的解释：** aggregator跨池多腿被重复计为多次买入；ATA创建被当作新增真人持仓。

**最有区分力的一项下一步：** 取签名及指令索引检查净Token和SOL余额变化。

**停止或降级：** 原始指令缺失或交易失败却被标为成交。

**知识位置：** `knowledge/domain/L1-L2-chain-market.md`；旧知识卡 `market-lifecycle`、`wallet-roles`。

**交接对象：** `E-L2-01`、`E-L3-01`。

**E-L1-02｜链上信号时钟与可见性专家**（B02；D01、D10）

**专属知识：** slot、blockTime 与真实接收时间区别；provider→parsed→available→decision→quote 时钟链；历史 backfill、延迟与commitment 错配。

**分析思维：** 以观察者实际知道的时间决定信号是否能复现，不用历史blockTime代替真实收到时间。

**实际调查顺序：** 1. 区分event/slot/provider_received/parsed/feature_available/decision/quote → 2. 检查提供者延迟、commitment和回填来源 → 3. 只保留决策前实际已知的特征。

**必须竞争的解释：** 历史回填模拟出零延迟；cluster身份标签在行情结束后才生成。

**最有区分力的一项下一步：** 核对带时区实时接收日志及其raw hash。

**停止或降级：** available_at缺失、迟于decision或被补造。

**知识位置：** `knowledge/domain/L1-L2-chain-market.md`；旧知识卡 `evidence-synthesis`、`candidate-entry`。

**交接对象：** `E-L4-02`、`E-L6-02`。

### L2｜市场生命周期与价格机制层

先识别真实发行阶段、池子和执行路径；在不同 curve/AMM 阶段不能机械拼接同一个价格指标。

**E-L2-01｜Meme 发行与迁移生命周期专家**（B02；D02、D01）

**专属知识：** launchpad bonding curve/毕业/迁移的事件定义；多池、多程序和不同交易阶段窗口；候选入口只表示可研究而非可买。

**分析思维：** 先判定发行程序和市场阶段，再解释价格/钱包指标。

**实际调查顺序：** 1. 确认为具体Mint和launchpad程序 → 2. 由曲线/毕业/建池链上事件确定阶段 → 3. 标记迁移前后的报价/分母不可直接拼接。

**必须竞争的解释：** 一个token有多个池和迁移路径；迁移时池规模突变被误认新资金吸筹。

**最有区分力的一项下一步：** 检查curve状态和pool创建的原始签名。

**停止或降级：** 市场阶段依赖单个供应商标签且无法对链上事件。

**知识位置：** `knowledge/domain/L1-L2-chain-market.md`；旧知识卡 `market-lifecycle`、`candidate-entry`。

**交接对象：** `E-L2-02`、`E-L3-01`。

**E-L2-02｜AMM流动性与价格形成专家**（B02；D03、D09）

**专属知识：** AMM reserve、边际报价与规模冲击；SOL 价格引起的 USD 流动性重估；LP 真实 add/remove 与多路由双向报价。

**分析思维：** 观察储备、边际价格和双侧成交路径，而不是把last price当可成交价。

**实际调查顺序：** 1. 按池拆解reserve数量与USD估值变化 → 2. 对目标仓位同时比较buy/SELL quote及冲击 → 3. 核实LP变化、池间路径与交易拥堵。

**必须竞争的解释：** SOL下跌造成liquidity_usd下降；成交量刷高但卖出深度枯竭。

**最有区分力的一项下一步：** 查看同时间同池真实reserve与买卖方向quote。

**停止或降级：** 池地址/储备或退出路由不完整。

**知识位置：** `knowledge/domain/L1-L2-chain-market.md`；旧知识卡 `liquidity-depth`。

**交接对象：** `E-L5-01`、`E-L3-03`。

**E-L2-03｜Token权限与假安全识别专家**（B05；D02、D09）

**专属知识：** Mint/freeze authority 与 Token-2022 扩展；池资产与 LP 控制、交易路由错误区分；卖出限制/拥堵/滑点故障的不同处理。

**分析思维：** 把可铸造/冻结/程序扩展/LP控制/卖出错误分拆为独立风险机制。

**实际调查顺序：** 1. 识别Token Program、扩展与当前authority → 2. 通过交易证明LP真实变动而非美元估值变化 → 3. 测试模拟卖出路线与错误类型，不把平台风险标签当结论。

**必须竞争的解释：** 卖出失败源自滑点而非黑名单；mint authority撤销但大额持仓可抛售。

**最有区分力的一项下一步：** 复核Mint账户权限快照和失败交易错误码。

**停止或降级：** Program语义未知或只有供应商单一安全标签。

**知识位置：** `knowledge/domain/L1-L2-chain-market.md`；旧知识卡 `token-security`。

**交接对象：** `E-L5-02`、`E-L6-01`。

### L3｜钱包、资金、筹码与时序主体层

这是跟单知识的主研究层：每位专家分别处理钱包行为、资金边、持有主体、开发者历史与跨币时序；不要在同一张图上假设它们是同一个变量。

**E-L3-01｜钱包行为与PnL解剖专家**（B03；D04、D07）

**专属知识：** 早期买/卖净额、仓位持续时间、PnL 已实未实；钱包画像按 mint×阶段×时间定位；排行榜选择偏差、跨地址转仓与成本缺失。

**分析思维：** 钱包角色随Mint和时间变化，真实账本优先于聪明钱排行榜。

**实际调查顺序：** 1. 逐笔区分swap/转仓/赠与和手续费 → 2. 复原入场价格、持仓时间、离场方式及未实现仓位 → 3. 对比同阶段类似钱包、失败钱包与自身其他币表现。

**必须竞争的解释：** 极早买入是机器人执行优势而非内幕；胜率由遗漏亏损交易/幸存者筛选造成。

**最有区分力的一项下一步：** 对一笔平台标注盈利交易做完整资金与持仓复算。

**停止或降级：** 原始历史不全、成本未知或只剩平台标签。

**知识位置：** `knowledge/domain/L3-wallet-actors.md`；旧知识卡 `wallet-roles`、`deployer-history`。

**交接对象：** `E-L3-02`、`E-L4-02`。

**E-L3-02｜资金溯源与经济主体取证专家**（B03；D05、D04）

**专属知识：** 有向资金图与 signature+instruction_index 去重；公共 CEX/HUB 与 dust 排除；共同付款、实际协作、同一实控三种不同主张。

**分析思维：** 转账事实→资金关联→经济控制是假设阶梯，不能跨级跳跃。

**实际调查顺序：** 1. 按signature+instruction_index建SOL/token转账图 → 2. 分类CEX/HUB/PDA/池/支付服务并排除dust与共用服务 → 3. 比较跨币重复资金准备与买卖时序，输出多种控制解释。

**必须竞争的解释：** 共享交易所提款地址可服务无关主体；相似金额同步买入可能是批量第三方机器人服务。

**最有区分力的一项下一步：** 查资金来源的公共基础设施角色和多轮独立重复关联。

**停止或降级：** 仅有一跳同源或无法排除公共HUB。

**知识位置：** `knowledge/domain/L3-wallet-actors.md`；旧知识卡 `funding-graph`、`sybil-wash`。

**交接对象：** `E-L3-03`、`E-L3-05`、`E-L6-01`。

**E-L3-03｜筹码供应与疑似控制结构专家**（B03；D06、D03）

**专属知识：** holder Top10 / HHI 与经济主体归并差异；池 vault、CEX/托管排除口径；独立承接与关联地址换手难题。

**分析思维：** 地址集中度和经济控制不是一个变量，持有数量也不是可卖能力。

**实际调查顺序：** 1. 按Mint和slot冻结供应分母、pool与托管排除口径 → 2. 同时计算地址Top10及待证实群组区间 → 3. 核验token在owner间转移与真实独立买方需求。

**必须竞争的解释：** 迁移池vault进入Top10导致比例变化；holder数量增长来自同一主体拆账户。

**最有区分力的一项下一步：** 对Top10名单逐项匹配owner/LP/vault与转移边。

**停止或降级：** 供应量/排除口径不一致或cluster只是标签。

**知识位置：** `knowledge/domain/L3-wallet-actors.md`；旧知识卡 `concentration`、`sybil-wash`。

**交接对象：** `E-L3-02`、`E-L4-03`。

**E-L3-04｜开发者与系列币生命周期专家**（B03；D04、D07）

**专属知识：** Mint 创建签名者与 launchpad 工厂账号区别；系列发币时间、资金准备、退出事件；共用服务导致开发者标签污染。

**分析思维：** 分析发币行为的可见序列与服务商混淆，而非给创始人贴永久标签。

**实际调查顺序：** 1. 区分deployer、mint authority、工厂程序与真实签名方 → 2. 建立历史发币全集、发行间隔、初始资金及退出方式 → 3. 沿跨Mint路径寻找重复模式并排除公用发币工具。

**必须竞争的解释：** 共用launchpad部署地址不是同一开发者；只选rug样本导致假高重复率。

**最有区分力的一项下一步：** 核对至少一组历史发币的实际发起签名者与资金来源。

**停止或降级：** 部署者身份只能由公共程序地址代替。

**知识位置：** `knowledge/domain/L3-wallet-actors.md`；旧知识卡 `deployer-history`。

**交接对象：** `E-L3-02`、`E-L3-05`。

**E-L3-05｜群体时序、资金轮动与注意力专家**（B03；D07、D04）

**专属知识：** 同步买入与同一市场触发的零假设；从一个币退出到下一币资金再部署的时间链；社交传播先后、市场 beta 与跨币轮动。

**分析思维：** 用顺序、重复和市场对照解释群体行动，而非把同步交易等于内幕。

**实际调查顺序：** 1. 把启动/同步/买入/退出/资金回流排成可见时间线 → 2. 配合同期同类型Mint和市场总体波动作对照 → 3. 区分独立需求、共同新闻、社交放大和机器人服务。

**必须竞争的解释：** 价格上涨之后登热榜是滞后；A币退出与B币上涨并无可见资金连接。

**最有区分力的一项下一步：** 检查相同钱包序列是否独立于公共市场事件重复出现。

**停止或降级：** 时序精度不足或下一Mint在当时不可识别。

**知识位置：** `knowledge/domain/L3-wallet-actors.md`；旧知识卡 `sybil-wash`、`candidate-entry`。

**交接对象：** `E-L4-01`、`E-L4-02`。

### L4｜机会发现与策略机制层

FCZ 只是一位策略专家；异常发现和钱包跟随优势是另外两条独立研究路径。不同策略可以产生矛盾假说。

**E-L4-01｜异常发现与未知模式探索专家**（B04；D08、D10）

**专属知识：** 五问题字段反推：事实→痕迹→字段→配对→语义；字段穷举/无标签异常/反向机制仅是发现器；先冻结假设与测试集，再做新特征验证。

**分析思维：** 从问题定义驱动字段组合，并允许无预设标签探索；异常只是问题不是策略。

**实际调查顺序：** 1. 先问想发现的市场行为和反面世界如何 → 2. 探索合理归一化/时序/聚类/反向机制但控制字段试验数量 → 3. 把意外组合转化为可解释的链上假说并冻结独立测试。

**必须竞争的解释：** 极端比值是分母接近零；全字段穷举产生选择偏差/未来变量泄露。

**最有区分力的一项下一步：** 找原始交易与负例验证一个异常组合是否存在且可事前计算。

**停止或降级：** 字段语义不清、没有非信号总体或仅样本内成立。

**知识位置：** `knowledge/domain/L4-L5-copytrade-edge.md`；旧知识卡 `gmgn-field-combinations`、`sybil-wash`。

**交接对象：** `E-L4-02`、`E-L6-02`。

**E-L4-02｜钱包跟随优势与信息时差专家**（B04；D08、D04、D07）

**专属知识：** 钱包入场优势≠跟随者首个可见报价优势；事件→收到→信号→询价的价格吸收；独立信号对照与双向可交易覆盖率。

**分析思维：** 钱包盈利不是跟随者盈利；研究优势被市场吸收的时间和价格。

**实际调查顺序：** 1. 复算钱包实际买入事件与我方最早收到信号 → 2. 计算可见时点价格/深度变化及可取得的买卖报价 → 3. 对比普通候选和其他钱包，衡量独立的跟随者增量。

**必须竞争的解释：** 原钱包靠抢首秒获利、后来者买在局部高点；钱包排行榜取样导致虚假的稳定优势。

**最有区分力的一项下一步：** 同一时点对原钱包成交价与跟随者首个双向quote做差。

**停止或降级：** 没有实时available_at或只有历史OHLC。

**知识位置：** `knowledge/domain/L4-L5-copytrade-edge.md`；旧知识卡 `wallet-roles`、`research-states`。

**交接对象：** `E-L5-01`、`E-L6-02`。

**E-L4-03｜二次结构、回收与反向陷阱专家**（B04；D08、D03、D06）

**专属知识：** 第一控盘区、POC/AVWAP 的事前锚点约束；深洗/死亡盘与真承接/诱多反弹的对立解释；FCZ/简单突破/纯VWAP 的独立比较。

**分析思维：** 把FCZ/POC/AVWAP作为一种可证伪的结构视角，与独立承接/简单突破平等竞争。

**实际调查顺序：** 1. 在决策前固定成本锚、观测窗口与二次启动条件 → 2. 分清真实净承接、同主体换手、死亡盘诱多 → 3. 比较失败回收、成功无回收、同流动性普通反弹。

**必须竞争的解释：** 回踩成本锚只是低流动性随机波动；事后重画区间把失败样本排除。

**最有区分力的一项下一步：** 检查触发前能否画出同一成本锚并找到失败案例。

**停止或降级：** 锚点只能在价格大涨后定义或未通过基础比较。

**知识位置：** `knowledge/domain/L4-L5-copytrade-edge.md`；旧知识卡 `reclaim-theory`、`liquidity-depth`。

**交接对象：** `E-L5-02`、`E-L6-01`。

### L5｜成交执行、尾部风险与交易经济层

即使行为分析专家认为存在结构，也必须由执行和退出专家独立核算；不能用榜单收益或K线峰值代替跟随者净收益。

**E-L5-01｜路径报价与执行容量专家**（B04；D09、D03）

**专属知识：** 链上成交价、DEX quote、模拟fill 三者区分；仓位规模与 route/fee/tip/冲击的内生成本；买入+卖出双侧路径与失败退出账本。

**分析思维：** 可见价格≠可成交价格≠真实fill，给定仓位的双向路由才有经济意义。

**实际调查顺序：** 1. 用观察时点买/卖方向、raw units和路由计算纸面成本 → 2. 估计延迟、拥堵、费用/tip、价格冲击与退出深度 → 3. 在多仓位规模和多个失效路由场景下分析净收益敏感性。

**必须竞争的解释：** 报价单边有效但无法卖回SOL；浮动滑点伴随热门行情内生上升。

**最有区分力的一项下一步：** 取决策时点对应规模的买入和预定退出时点卖出报价。

**停止或降级：** 无卖出路径、报价过期或无成交核验却声称fill。

**知识位置：** `knowledge/domain/L4-L5-copytrade-edge.md`；旧知识卡 `liquidity-depth`。

**交接对象：** `E-L5-02`、`E-L6-02`。

**E-L5-02｜尾部风险、可卖性与机会成本专家**（B04；D09、D11）

**专属知识：** 权限、流动性、仓位容量、尾部卖出风险分开；filter/no-filter 在相同机会和资金预算下对比；拒绝机会的成本与未成交不记作零。

**分析思维：** 把不交易、退出失败、资金占用和被漏掉的机会一起计入风险判断。

**实际调查顺序：** 1. 先检查权限/池深度/已知不可卖路径等硬拒绝条件 → 2. 模拟尾部情境的退出失败及部分成交 → 3. 比较同一资金预算下过滤与不过滤的机会成本。

**必须竞争的解释：** 排除所有高波动币会降低亏损也降低全部机会；静态流动性高却因LP撤出突失卖出能力。

**最有区分力的一项下一步：** 对相同候选池构建过滤/不过滤与简单深度规则的对照。

**停止或降级：** 过滤条件事后挑选、未记录拒绝后的市场结局。

**知识位置：** `knowledge/domain/L4-L5-copytrade-edge.md`；旧知识卡 `token-security`、`research-states`。

**交接对象：** `E-L6-01`、`E-L6-02`。

### L6｜独立反证与盲回放层

反证专家攻击机制解释，盲回放专家检验预测与经济结果；两者均不得以自评置信度或投票完成审批。

**E-L6-01｜反证、混淆因素与证据对抗专家**（B05；D11、D10）

**专属知识：** 必要/增强/否决证据分别呈现；共享服务、数据泄露、同源重复和意图归因反证；选择最可能改变结论的负对照/原始签名。

**分析思维：** 主动寻找可推翻主解释的低成本证据，而非写同意意见。

**实际调查顺序：** 1. 把主张拆事实/机制/预测/经济四类 → 2. 列至少两种能产生相同观察的竞争机制与混淆变量 → 3. 挑一条最能区别假说的原始取证和负对照。

**必须竞争的解释：** 共享HUB造成虚假的控制关系；外部研究报告被当作本项目独立复算。

**最有区分力的一项下一步：** 指定最小证据查询能让主张从成立变为不成立。

**停止或降级：** 来源无法复现或多个所谓独立证据来自同一口径。

**知识位置：** `knowledge/domain/L6-L7-investigation-cases.md`；旧知识卡 `evidence-synthesis`、`sybil-wash`。

**交接对象：** `E-L6-02`、`E-L7-01`。

**E-L6-02｜盲回放、样本外与收益审计专家**（B06；D11、D09）

**专属知识：** 时间与资金群组联合样本外隔离；失败/缺失/无卖出路径均计入分母；策略预测增量、净收益和真实成交分层检验。

**分析思维：** 不读策略作者的标签，重放当时数据和成交条件检查是否存在增量。

**实际调查顺序：** 1. 先冻结Universe、触发时点、阈值与结局窗口 → 2. 按时间和操作者群组切分，保留失败/未观测/无成交样本 → 3. 与简单基准比较增量，严格区分预测与扣成本后的结果。

**必须竞争的解释：** 胜率提升但滑点后净值为负；同一资金群跨训练和测试造成伪独立性。

**最有区分力的一项下一步：** 用独立时间+群组样本重放一个被称为成功的信号。

**停止或降级：** 没有时点/分母/两侧成交或test被研究中调参。

**知识位置：** `knowledge/domain/L6-L7-investigation-cases.md`；旧知识卡 `evidence-synthesis`、`research-states`。

**交接对象：** `E-L7-01`、`E-L7-02`。

### L7｜专业综合与冻结监控应用层

研究综合专家组织证据与分歧，监控专家只消费冻结规则。专家数量不是 Grok Bot 数；每次研究不全量触发。

**E-L7-01｜专业研究综合与知识编译专家**（B01；D12、D08）

**专属知识：** 按问题挑必要专家，不机械顺序全链；不同专家报告的同一数据不算独立证据；竞争解释以证据分歧处理、不靠共识投票。

**分析思维：** 先组织分歧、提问和证据缺口；不以专家投票决定市场结论。

**实际调查顺序：** 1. 根据问题选最少必要专家，限定各自输入和未知 → 2. 比较专家事实引用是否共享同一源，标明尚未解决的冲突 → 3. 归纳只有证据支持的结论与可改变结论的下一次查询。

**必须竞争的解释：** 三位专家都复述同一平台标签并非三证合一；单一FCZ专家强行解释所有市场走势。

**最有区分力的一项下一步：** 找到专家冲突中最能区分解释的一笔原始交易/观察。

**停止或降级：** 任何关键结论无法溯源或F门槛未通过。

**知识位置：** `knowledge/domain/L6-L7-investigation-cases.md`；旧知识卡 `evidence-synthesis`、`anti-false-completion`。

**交接对象：** `E-L7-02`。

**E-L7-02｜冻结规则监控与故障隔离专家**（B07；D12、D10）

**专属知识：** B07 只能加载人工批准冻结只读规则；单写入者、去重、来源断连退避与事故日志；监控 UNKNOWN/Research Gap 与发布回滚分离。

**分析思维：** 生产监控只报告审批规则能确定的观察与未知，不在运行中创作策略。

**实际调查顺序：** 1. 核对固定SHA、批准规则、状态单写入及来源健康 → 2. 只读输出警报/弃权/错误，保存签名、时间与规则版本 → 3. 把未知、漂移、重复告警和研究缺口送回人工审阅。

**必须竞争的解释：** 供应商429被解释为币突然没有买入；旧文献被动态检索后改变正式监控阈值。

**最有区分力的一项下一步：** 检测到实际错误后可复现的停止与恢复日志。

**停止或降级：** 未批准规则、源故障、持久状态争用或环境不匹配。

**知识位置：** `knowledge/domain/L6-L7-investigation-cases.md`；旧知识卡 `research-states`、`anti-false-completion`。

**交接对象：** 人工复核/研究回流，不自行发布新规则。

## 3｜专家与专业知识之间如何调用（不是每次强制跑 21 位）

**K0 常驻**：仅装入所选专家的观察问题、三个专业原语、禁止推论和停止条件。无需把 21 份完整专家内容塞进每次聊天或 Grok 常驻提示。

**K1 按需**：读取本专家 `knowledge_files` 指向的内部知识，并从 `knowledge/catalog.v1.json` 选择需要的历史卡。外部引用必须通过 `knowledge/source-admission.v1.json`，`review_only` 不能因专家要求而绕过准入。

**K2 任务证据**：实际 Solana 事件的签名、slot、原始账户/指令、单位、发生时间和真正的 available_at。无 K2 时，专家只能交付研究假说与下一项取证，不能写“本币已确认控盘”“策略已盈利”。

**专家分配**：只问“这个钱包净买入是真是假”→ E-L1-01 与 E-L3-01；只问“共享资金是不是同一团队”→ E-L3-02，加 E-L6-01 反证；问“值得跟单吗”→ E-L3-01、E-L4-02、E-L5-01，必要时补 D05 资金图；问“能否发布监控规则”→ 经 E-L6-02 独立回放并获人工审批后，由 E-L7-02 只读消费。

**冲突处理**：主张/反对/决定性查询/缺失数据一并交回 E-L7-01。谁的叙事更好听、专家意见谁多，都不影响原始证据的权重。一个供应商数据被三位专家重复引用仍只有一个来源。

## 4｜完整模拟案例：六个钱包同源买入一枚新 Meme（全部假设，非市场发现）

**输入**：某币刚可交易，6 个地址几乎同步买入，Top10 高，且看起来有共同资金上游。用户问“这是不是庄家？要不要跟？”

1. E-L0-02 审查入口来自 OKX 还是 RPC，时间窗/单位/holder 分母如何定义；只有供应商标签则不声明实际身份。
2. E-L1-01 复核6笔是否成功 swap，是否含聚合器内层转账/账户归集；E-L1-02 锁定何时对我方真正可见。
3. E-L2-01 判断当时是曲线还是迁移后池；E-L2-02 检验该规模双向可成交深度。
4. E-L3-01 观察每个钱包过去行为与当前持仓；E-L3-02 排除公共CEX/HUB及dust；E-L3-03 对Top10池/托管账户去噪；E-L3-05 比较正常新币同步买入。
5. 出现真实分歧：资金专家说“共同资金边可确认”，时序专家说“同一公开启动事件足以解释同步”。E-L6-01 提出决定性查询：去除公共HUB后，这6个地址在其他币是否仍存在相同的非公共转账序列？
6. 即便有重复群组证据，E-L4-02 还要判断我方可见时点是否已失去价格优势；E-L5-01 必须查询买入和卖出双侧报价与资金容量。
7. E-L6-02 才能使用事前冻结的非信号总体做盲回放；E-L7-01 汇总“已证实共同资金关联 / 未证实同一控制 / 跟单经济性未知”等层次，不能投票通过。
8. E-L7-02 不因为这次研究更改任何监控阈值；未批准研究只能记录为观察或研究缺口。

## 5｜该机制目前做到和没有做到什么

**已形成**：21 个专家视角的可追溯专业知识、固定的思考动作、最小辨别查询、竞争解释和对应 B01–B07 的职责归属；可作为 GPT 研究时的专家工作说明和后续 Grok 程序材料。

**未完成**：没有创建 21 个独立 AI 实体，不保证任何专家已在 Grok UI 安装，专家之间尚无实际大模型辩论调度器；专家一致性测试并不能证明它们在真实行情中表现优于普通分析。

后续应只让一两个实际案例验证“专家视角是否改变查询和结论”，再决定是否开发动态调度；不能因有 21 个名称就宣称多智能体系统运行。
