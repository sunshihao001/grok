# Blix 在 Grok Bot 云电脑如何使用：网站 / 后台 / 监控 V0.1

日期：2026-11-06。**只做研究，未运行Blix、未开网站、未部署、未建Routine。**

## 一、不能把三个问题混成一个

**界面：** Blix已有React Web和经典UI，可直接作为以后的网站展示层（Pulse、Coin、Bubble Map、钱包、AI），不需要再开发第二个市场网站。
**数据与监控：** 需要可靠进程采集事件、落地SQLite、管理游标、重试、缺口及回补。持续监控不等于AI每次打开网页。
**Grok Bot：** 接收自然语言、调用只读API/MCP、对异常做深入研究、维护知识并汇报。Bot是指令和研究控制层，不是交易钱包或全市场长连接解析器。

## 二、官方Grok Bot能力及限制

- https://docs.x.ai/grok-bot/overview ：持久云电脑有浏览器、文件和终端；**同用户所有Bot共用同一云电脑和凭据**，多Bot之间不是密钥隔离。
- https://docs.x.ai/grok-bot/skills-routines-and-automations ：Skill复用成功流程，Routine可定时/事件/webhook触发，在用户不在线时执行，但任务可能失败/消费额度。
- https://docs.x.ai/grok-bot/security ：**空闲云电脑自动休眠**，持久文件不等于进程24小时常驻；未证实它提供可稳定公开的网站托管、入站端口或Solana不断线监控SLA。

## 三、三种使用方案

| 方案 | 用户从哪里用 | 持续性 | 建议 |
|---|---|---|---|
| A. Bot+原厂官网只读API/MCP | 直接问Bot查Mint/钱包、定期报告；原厂网页看图 | 依赖原厂采集及Routine采样；不是个人fork代码 | 可作为后续低成本功能试验候选，需核实账号/额度 |
| B. 在Grok Bot云电脑中放Blix做短时开发与研究 | Bot指令、浏览器看本地Blix UI（能否访问待验） | 云电脑可能休眠，不默认承担24h监听 | 适合受控研发，不等于可靠网站托管 |
| **C. 独立常驻Blix + 原Web + Grok Bot** | 需要图形看Blix网站，需要研究问Bot；异常直接通知 | 由常驻程序处理事件/存储/重连/回补，Bot按条件解释 | **长期最符合目标**，但要另做隔离、鉴权、数据成本与备份审查 |

## 四、实际业务使用

1. 问一个Mint：Bot调Coin、Holder、Bubble Map、钱包和时间来源，生成事实、候选解释、UNKNOWN，并给原Coin页面。
2. 日常或固定时间：Routine获取市场候选快照，报告热点与风险；这是周期抽样，无法证明间隔内所有转账被记录。
3. 真正7×24异动：未来独立常驻程序持续写签名/动作/钱包/资产净变化、重连和历史回补，触发真实异常后用Webhook调Bot做深度分析。
4. 看市场：直接使用现成Blix UI；只有多人公开访问或强交互报表需求成立时，才研究正式网站托管和用户鉴权。

## 五、还不能执行的原因

- 本分支npm start虽然有启动审查门禁，但bin/supervise.mjs可绕过并直接拉起server.js和邻近Vault，不能视为已安全只读。
- 官网更新的交易API可使用带权限密钥花费真实SOL；**不把私钥或可交易密钥交给多个共用云电脑的Bot**。只读应有真实服务器端权限限制。
- 原域名/账号/数据库/密钥/供应商配额不会自动随MIT源码复制。需独立校核Node>=24、web构建、SQLite WAL/备份、网络限额、日志和历史缺口。

**下一项高价值未知：** 完整理解原Blix的HTTP/MCP读接口能证明哪些事实、SSE事件如何转成持久监控；再判断需不需要额外运行服务器和新的能力模块。当前仍只读不运行。
