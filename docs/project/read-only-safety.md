# Blix 只读建设｜安全阻断审查（2026-11-06）

**审查对象：** `sunshihao001/grok` 仓库 `blix` 分支。此文件属于已有 Blix 的安全审查，不是另起市场产品。**尚未运行主服务，不承诺“已隔离”“已安全上线”。**

## 本轮确定的源码风险

| 事实与位置 | 为什么阻断只读启动 | 处理状态 |
|---|---|---|
| `server/accounts.js` 的 Wallet/Vault 买卖、提现、签名相关入口 | 存在真实资产路径 | 待隔离：仅静态识别 |
| `server/hosted-accounts.js` 的 Swap | 托管钱包交易可能写链上 | 待隔离 |
| `server/autoclaim.js` 的后台 claim | 即使没有人操作，也存在已授权用户的定时资金动作 | 待隔离 |
| `server/settings.js` 默认 `researchAuto:true`、`grokOff:false`、`desk:true` | 可能调用模型/额度；用户当前未授权费用 | 待阻断后台路径 |
| `server/server.js` 启动时调用 Grok 订阅/计费接口 | 即使部分 AI 设置关掉，启动仍能请求外部接口 | 待隔离 |
| `public/mcp-tools.js` 存在 paper buy/sell | AI 工具目录可写 | 研究版 `mcp/blix-mcp.mjs` 已从暴露清单与调用入口排除 write=true 项 |
| `server/settings.js` 默认 `marketFeeds:true` | 读取本身不签名，但可能使用 RPC/供应商配额 | 成本和数据源待核查 |

## 本次实际措施

1. `npm start` 前插入源代码安全检查器 `scripts/read-only-audit.mjs --gate`；**在真实风险路径未解决前默认拒绝启动原服务器**，避免旧 Blix 的历史默认配置在研究分支意外触发。
2. `npm run audit:read-only` 可只审查本地代码，无网络/私钥/签名或模型请求。它输出“代码存在性证据”，**不是完整安全证明**。
3. AI MCP 只暴露读取工具，且调用入口使用相同只读清单；底层原始 HTTP/网页路由未改动，因此**不能仅靠 MCP 防护宣称原服务器安全**。
4. `npm run test:research-safety` 检查静态审计逻辑；`npm test` 的原测试不改变。

## 尚未解决的硬问题

- 原主服务默认启动会挂载大量网络、AI和状态变更任务；还需建立真正的只读运行入口/权限隔离，包括关闭自动领收益、密钥入口、付款与模型计费。
- 不能直接把 `data/settings.json` 的设置当安全边界；启动升级逻辑能自动重写设置，而且已有数据文件可能覆盖默认值。
- HTTP GET 的某些端点也可能触发外部查询与额度消耗；只读不等于无费用。
- 本分支 Node 需求 `>=24.16.0`，GPT 当前隔离环境此前只有 Node 22，未完成全项目运行验收。
- 如果有人直接执行 `node server/server.js`，可绕过 npm gate。因此在隔离完成前**不得直接启动现有主服务**。

## 后续安全完成判据

- 独立只读入口可启动，不加载钱包、交易、签名、自动 claim 或未经授权的模型调用。
- API 与 MCP 的请求级权限一致；禁止非授权写入、链上广播、模型付费；已有钱包密钥不进入运行进程。
- 读取确实完成后才逐步启用市场采集，并核实是否发生数据或费用风险。
- 由可重现的 Node 24 运行日志、测试记录、网络请求/费用审计确认，不以这个文档替代验收。
