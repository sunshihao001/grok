## A. 项目北极星：这个系统究竟要替人完成什么

以**完整原版Blix**为成熟市场产品基础，建设**独立、可与Coin/Pulse/Wallet衔接的AI专业研究工作台**。它不仅回答问题，而是：

1. 在明确声明覆盖范围、采集来源、时效和成本的Solana Meme市场内**自主发现与筛选潜在交易机会**，同时能发现具有研究价值的异常代币；其中**实际交易机会评价比一般调查兴趣优先**。
2. 发现关键钱包、地址角色、最早买家、发行者/Dev历史、接收转入新地址、资金来源与可疑协调现象；排除共享设施、Pool、Vault和Token Account混淆。
3. 用原始交易和足够完整的持仓/对价记录调查买卖、Token转仓、资产库存、资金流向与经济机制，不以标签冒充经济事实。
4. 从单Mint扩展到跨Mint资金接力、群体成员变化及重复行为，并记录竞争解释；不能仅凭相近时间或Jito Bundle宣称共同控制。
5. 结合信号首次可得时刻、真实报价、资金量、流动性、费用、滑点、退出风险及样本外证据，判断值得调查、只观察、可以评价参与条件还是不能下结论。
6. 对已进入案件/观察范围的Mint、Wallet、Group持续更新，发现新交易和反证后修订结论，形成可回开的调查历史与长期质量反馈。

**用户交互**：用户只需说“看看市场上有没有值得参与的币”“打开这个币调查庄家和接收地址”“跟着这个钱包看它跨哪些币”。AI识别真正目的、补齐前置问题、选知识与安全工具、组织结果和下一行动；不要求用户具备专业编程或交易解析知识。

**权限**：当前扩展默认只读/纸面模拟。保留原版真实交易功能，但新AI研究服务未经明确授权不得触发交易、签名、自动付款、付费模型或公共部署。模型输出不等于操作授权。

**成功衡量**不是“有多少AI页、文档、专家、指标、PR或通过多少合成测试”，而是能否比原版Blix更及时、准确、全面地找出有价值对象，能否追溯真实资金事实，能否判断信号之后的参与条件，能否在真实新证据下可靠修正，单位成本与用户指挥负担是否更低。

### C1. 数据形成的闭环（关键逻辑）

外部市场与Solana链上事实 → 确认来源/授权/覆盖宇宙 → 轻量实时发现流 → 原始落盘与历史补查 → 数据去重、时间/版本/Pool/账户标准化 → 质量与缺口说明 → 市场候选与已过滤样本 → AI/确定性工具按需调查关键钱包/经济净额 → 跨Mint关系/竞争解释 → 有首次可见时间和可执行报价才做机会评估 → 保存案件、监控增量、修订知识与筛选逻辑。

如果上游断流或样本截断，后面全部带该缺口；不允许单靠模型把UNKNOWN转换成确凿不存在、幕后同控或盈利结论。

### C2. 必须区分的七种时间/来源

交易链发生时间、链Slot/确认状态、数据提供方观察时间、Blix实际接收时刻、本地库存/界面观察时间、模型首次可用时刻、策略可执行报价时刻。无法证实其中某项时写UNKNOWN；浏览器Date.now不等于信号在链上刚产生，历史走势图也不能提供真实前视交易报价。

### C3. 数据量与成本分层

- 第1层：明确覆盖范围内轻量收录发行/迁移/成交/池活动与初筛结果；保留选/未选的分母；
- 第2层：高信息价值候选再补多个源的Pool/Holder/市场安全/Dev等；
- 第3层：少数调查Mint/Wallet才按预算查原始RPC及多跳历史；
- 第4层：只有需要判断可参与性时才查同时间窗可执行深度/路由/费用与退出；
- 第5层：只有确证增量触发时才运行重复AI解释，避免无新数据时反复花钱。

没有对目标宇宙、价格时效、数据预算与漏样的实测，不因为系统“应该全面”就自动购入重型Indexer/付费API。

## D. 六个业务结果的完整内部能力与前置验收

### O1 自主发现“值得调查”和“可能值得参与”的Mint

**目标产物**：一个可复查的候选队列，其中包含全部在声明覆盖范围内被观察/被过滤对象、信号、关键原因、候选优先级、数据质量、第一可用时间、待查事实、实际后续结果。

前置小阶段：
1. 明确链、DEX、发射平台和新币/迁移/活跃市场宇宙；哪些源永远不覆盖须注明。
2. 检查来源API/WS/RPC协议、许可、速率/费用、字段、服务故障备选。
3. 保存发行、池建立、交易、价格、流动性、Dev和钱包关注事件，分清原始与派生。
4. WS断流、429、漏页、fork、缓存恢复与历史回填；同Mint多Pool/Token2022/错误供应量清理。
5. 记录source-event/chain-slot/provider-observed/blix-received/first-usable/quote-window，源时间缺失时降低信号等级。
6. 以原版覆盖工具核查遗漏，保留被筛掉/没进入AI的样本，避免只学习最终涨幅大的成功者。
7. 原版Triage/Early/Brain/钱包异动与规则筛选产生候选，AI按需读取专业知识提出调查理由并可拒绝全部候选。
8. 后续按真实信号首次可见、调查价值、可执行报价及错过样本做时间隔离对照。

**现状**：原版拥有多个市场入口；新AI /discover只处理当前浏览器提交最多12个候选，尚未覆盖上面1–6及8的真实验收。**不能标“自主发现市场机会完成”。**

### O2 关键钱包、角色与资金参与者

**目标产物**：真正有调查价值的地址集合，而非只按Holder TopN排名；每一地址有发现来源、账户角色、捕获签名、历史窗口与可能误判。

前置小阶段：
1. 从O1、指定Mint、发行者、早期买家、转入接收、SOL资助/跨币钱包事件多入口发现。
2. 把TokenAccount、Owner、Authority、FeePayer、Pool/Vault/Router/CEX/KOL营销设施分开；有疑问标UNCLASSIFIED。
3. 查关键地址历史：签名分页/交易原文/游标/429/时间窗/重试/Token及SOL转账；不只查看当前Holder。
4. 解析买入、卖出、转仓、接收/输出、LP、Bundle、刷量候选；时间相关不等于共同控制。
5. 根据真实库存、资金、重复交易、利润可计算性、与风险/机会的关系选最值得深入的Wallet；可放弃低信息价值地址。
6. 记录未发现的钱包类别、截断、反例，跨来源对照Wallet/Bubble/Tracker的口径。

**现状**：原版BubbleMap和钱包历史有可复用实现，经济扩展只提取局部已捕获Owner；非Holder完整扩张、角色准确率和真实验收仍缺。

### O3 资金、Token与库存经济链

**目标产物**：交易签名可回查的真实买入/卖出/转仓、账户资产净变、余额库存和成本边界；能逐笔说明什么观察到、什么推断、什么未知。

前置小阶段：
1. 从关键钱包和Mint选择有代表性的真实签名、Slot及捕获范围，保存RPC交易完整原文与hash。
2. 解析v0/v1、ALT、CPI层级、Token/Token2022、System、SOL/WSOL、Swap、Transfer与LP混合动作。
3. 按指令/资产/TokenAccount Owner/Pool角色识别交易对价、净余额变化、手续费与失败交易。
4. 签名级去重、防重复计费、数量守恒；每个余额/转账边有源交易引用。
5. 构建买、接收、卖、转出、LP增减的实际库存变化；历史不全、批次成本/经济所有权不能确认时不算盈利。
6. 研究吸筹、库存组织、刷量/假成交、转仓后出货及正常做市竞争解释，保留真实反例。

**现状**：PR23存档与Token Transfer候选有离线测试；整套完整经济动作与真实资金闭环未通过。

### O4 跨Mint联系、群体和多跳

**目标产物**：链上签名/账户/时间可复查的跨币路径与群体成员演化，按“同地址”“疑似资金接力”“可能协同”“共同控制未知”分级。

前置小阶段：
1. 从O2/O3的钱包卖出、Token转仓、SOL转出和新Mint买入触发扩查，也允许从同钱包跨币操作直接进入。
2. 查接收钱包与非Holder中间地址，按需获取其它Mint的真实签名及资产净额。
3. 将时间、金额、交易对价、费用、共享服务/交易所地址、资金混同、多跳环路分离。
4. 比较多Mint群体重复、Bundle/Jito/营销资金和正常市场行为；排除共同使用路由导致的伪关系。
5. 保留证据边的签名/调用位置/覆盖水位/竞争解释；对新增事实重新评估同一群体。
6. 对反例和误归因做真实对照；没有直接资金事实就只输出TEMPORAL_CANDIDATE。

**现状**：已有跨Mint时间候选、BubbleMap多跳线索，但完整真实Solana资金来源与控制权不可认定。

### O5 是否值得参与、跟单与实际策略

**目标产物**：区分WORTH_INVESTIGATING / WATCH_ONLY / FOLLOWABILITY_EVALUABLE / NO_DECISION_DATA_MISSING的判断依据；只读模拟，不代替用户交易授权。

前置小阶段：
1. 明确机会类型：新币早期、钱包领先买入、资金协同前兆、跨币复现、库存/流动性变化及价格/成交机制；不同类型需要不同假说。
2. 证明信号在研究者/用户当时第一次可见，严禁用事后Chain/Chart高低点作可买入价格。
3. 获取指定交易尺寸、Pool/路由、报价时刻、深度、手续费/优先费/滑点/MEV与失败率。
4. 检查Token销售限制、LP撤出、流动性抽走、钱包资金实力、库存可用量、可退出条件。
5. 根据给定参数做严格只读纸面模拟，拒绝历史报价缺失和虚构最优成交；以不同资金/延迟/退出条件做敏感性检查。
6. 保存参与/拒绝/漏报的相同样本宇宙和时点，按真实可用性做时间隔离和样本外原版/规则/AI三组对照。
7. 证据不足时给出进一步核查成本或停止原因，不将“潜在庄家结构”直接变成买卖信号。

**现状**：followability replay只是有限纸面收据，缺真实历史可执行入场/退出价格和前瞻对照；当前不得声称发现盈利机会。

### O6 持续观察、修正与长期改进

**目标产物**：一个真实调查Case可保存、重开、接收新事实、修正旧结论、暂停与恢复；不会反复处理同一事件或持续产生无用模型账单。

前置小阶段：
1. 建立Case的原始目标、Mint/Wallet/Group、来源与签名、证据版本、知识/模型版本、未知清单及用户授权。
2. 定义实际可监控事件（买/卖/转仓/新钱包/跨Mint/Pool/Holder/价格变化），明确来源/触发范围/失效与费用。
3. 增量游标、去重、429/backfill、fork、重启恢复；区分“新发生”和“今天才补到旧交易”。
4. 数据确实变化后重算经济库存与群体关系，再由AI按需重新解释和反证；没有新事实时不让AI重复写报告。
5. 保留原判断与修订理由、告警限频/止损风险、可停止/恢复/导出结果、隐私与授权边界。
6. 比较未监控/原版工具/新AI监控对错报、漏报、真实调查效率和费用的影响。

**现状**：原版Tracker与事件基础可复用，但独立AI没有可验的持久Cases与长期自主监听，不能说已“持续观察”。

| 用户场景 | 入口 | AI应自动补齐的专业工作 | 同一报告的可复查输出 |

| “现在市场有哪些可能的机会？” | Pulse/Discover/AI工作台 | 源时效与候选全集→异动→关键钱包/经济线索→可参与性先验与有限补查 | 候选排名与未选理由、源覆盖、首可见时点、资金/风险、下一调查 |

## F. 预先考虑的失败/风险：为什么以前总在开发后才发现漏项

| 风险组 | 已预见的具体失败 | 预警/退路 |
|---|---|---|
| 市场范围与采集 | launchpad/DEX覆盖缺失、发行流断开、旧缓存当实时、Provider429、同币多池错价 | 分母和覆盖声明、WS/历史补查水位、sourceFirstAvailable UNKNOWN |
| 交易与地址 | Token Account!=Owner、Pool Holder、错误供应量、Token2022、ALT/CPI、WSOL、同签名Swap/LP重复 | 原始RPC与事实级去重、地址类型和数量守恒，缺失写UNCLASSIFIED |
| 资金归因与策略 | 接收方旧库存卖出误认为转入卖出；共同资金服务/Jito误判同控；历史高点当可执行报价 | 资产批次UNKNOWN、竞争解释、按当时可见/可成交数据模拟 |
| AI与知识 | 旧资料污染、作者营销当证据、模型幻觉、多Agent重复工作、工具注入、上下文过载 | 最小必要检索、来源/证据分级、工具白名单、对照测量知识增益 |
| 产品与工程 | 原版GET写库、副作用读；SQLite WAL不一致；模型密钥泄漏；移动端localhost假可用；PR冲突/旧功能回归 | 原版保留+静态副作用审查、一致只读副本、限权/成本硬闸、本机先验收、合并/回滚方案 |
| 运营与学习 | 重启丢案件、断流误报、无限重试/费用、采集延迟、只复盘被选中赢家、同样知识反复扩文档 | Case/游标和日志、有效新增事件触发、失败样本分母、停止/暂停和核查审计 |

**红色阻断的具体条件**：影响资产/付款或未经授权外发、真实身份/控制权判断缺关键证据、给用户标“实际可参与”却无交易时点/报价、PR安全冲突未解决却要合并部署时，必须暂停对应高风险动作；其余局部未知可在明确边界下继续低风险调查。

**无法一开始彻底知道的未知**（应主动提示而非事后才发现）：
- 部署时到底运行哪些协议/DEX/市场，目标宇宙的漏采分母是否有独立基线；
- 实际是否可合法访问用户Blix本机/云端历史数据库与真实RPC，是否有连续原始签名；
- 哪家RPC/Indexing提供商能给指定窗口的历史，实际费率/吞吐/限速和数据许可；
- 用户所需的机会类型、交易尺寸、可接受延迟与样本外评估窗口；
- PR#23与blix实际冲突、原版用户/交易路径的真实运行回归；
- AI模型实际费用/上下文/隐私、远程授权机制、持续Case更新能否达到可靠性要求；
- 自主机会筛选是否带来真正统计优势，不能凭理论或CI预先承诺。

上述每项只在其影响当前实施包时取证，不要求用户马上回答全部。整体规划可以先覆盖大类，再随真实情况打开对应子项；**承认无法预测所有未知未知。**

## H. 重新安排的实施路线：目标整体先考虑，交付按真正依赖推进

| 交付批次 | 解锁前提与建议工作 | 出现什么**可检查**产物才能进入下一种主张 |
|---|---|---|
| **R0 基线/权限/冲突** | 固定原版Blix+PR23作为唯一集成候选，核清PR24已复用/未复用、当前GitHub合并冲突、原版登录/交易/存储不被意外调用，定义可回滚读隔离 | 精确SHA、原版回归、功能差异及安全副作用审查；已有CI不等于可部署 |
| **R1 真实市场与RPC源头** | 取一枚真实Mint与明确时间窗，优先使用既有Blix只读数据库副本和源码/日志；按需授权历史源补关键签名；检查市场→源→原文→索引→AI输出的完整链 | 真实Market/Slot/签名/哈希、每种数据的范围/缺口、前后查询一致及非修改证明；若没数据就报告阻塞 |
| **R2 钱包与经济事实纵切** | 沿同一Mint真实钱包买→Token转→接收钱包卖：补关键非Holder/池、CPI/Swap/LP/净额、库存/费用/批次UNKNOWN | 可逐笔回放的正负样本，排除重复/漏记/跨源错时；正确承认不完整部分 |
| **R3 市场与跨币自主研究** | 原Blix轻量候选、独立市场样本对照、未选原因、跨Mint多跳、AI知识按需选、工具/成本门禁 | 同源条件下找出原版漏报或修正错误事实，证据能回溯；不是模型空口“看涨” |
| **R4 跟随性和策略评价** | 明确真实信号首次可见、报价、规模、手续费/滑点与退出，可做只读真实时间模拟 | WORTH_INVESTIGATING和FOLLOWABILITY_EVALUABLE有可复查分界；保留不可成交与亏损样本 |
| **R5 案件持久运行** | 经授权选择Mint/Wallet观察范围，增量游标/补查/恢复、Case新旧事实和AI重审 | 至少两次真实观察或有界可复现演练，新事实/迟到回填/故障被正确区分，停止/恢复与成本可靠 |
| **R6 公平对照与产品发布** | 完整覆盖受控真实场景后，原版Blix vs 确定性经济证据增强 vs AI+专业知识，同输入、同时间、同预算 | 前瞻漏检/误报/时效/资金错误/调查效率/可参与性和运行成本的真实差异；无增益就削减复杂度或采用成熟替代 |

**不是一条长瀑布**：可以同时阅读参考项目、补一个明确解析反例、做好UI安全；但不能没有真数据先宣称市场Alpha、没有原始经济事实先宣称资金同控、没有认证就开放生产自动研究。

当前最重要下一实施包：**R0核实合并/安全及原版采集边界；R1优先定位和改善有共同复用价值的上游数据源/接入层缺口。** 在授权现有SQLite/真实归档范围内的一枚Mint只读检查属于**定位断点与验收上游修复的测试工具**，不能反过来成为新建AI侧采集器、手工给报告补数据或绕开原版源缺陷的交付目标。若真正缺失第三方供应商能力，先核实接口/覆盖/费用、比较成熟替代或组合方案；不得猜填、付费或在无权限下接入。具体源职责与源码已核问题见[多层锚点第11节](cross-layer-anchor-map-20261113.md#11-2026-11-13数据源优先纠偏职责所在处修复拒绝ai下游重复采集)。

## I. 九类端到端业务验证：真正让系统更“靠谱”的硬条件

1. 真Mint的原版Pulse市场记录与新AI观察能关联到同源、同时间窗，显示源时效与失效；
2. 发行流或RPC断线、429、恢复补历史，不把迟到数据当新市场动量；
3. Top20 TokenAccount/Owner、Pool/Vault、公共服务、多个TokenAccount合并不误标巨鲸与经济控制；
4. 一个签名有多CPI/Swap+Transfer/LP/WSOL/Token2022时不重复计账且原始数量守恒；
5. 钱包A真实买→转给B→B后卖（不证明同批库存时正确留UNKNOWN）；
6. 同充值服务、多钱包同Slot/Jito、跨Mint时间共现，正确拒绝错误同控；
7. 一条跨Mint真实资产路径能回溯签名，无法证明资本来源时不编造；
8. 信号真实可见之后存在/缺失有效入出报价，对成本、滑点及退出失败如实计入；
9. 一个Case保存后新事件/迟到回填/故障恢复导致可核修订，AI不重复消费旧数据和费用。

验证等级依次为：SOURCE_CODE_REVIEW、SYNTHETIC_UNIT、ARCHIVED_REAL_REPLAY、CONNECTED_READONLY_RUNTIME、PROSPECTIVE_SHADOW、SECURE_OPERATIONAL。任何级别不冒充更高级别；不能因为九类测试全绿便保证未来盈利。

## J. 以后每轮的实施准入、异常预警与目标锚点

**开工前最少应有七个答案（由AI先自行核对，不向用户索取已有信息）**：
- 这次工作服务哪一个用户已确认目标，实际产物是什么？
- 其前面还有哪些数据源/权限/存储/解析/业务前置没有满足？
- 原Blix/当前PR/完整开源成品能否直接复用？为什么还要新开发？
- 哪条具体事实或现象是正确性的依据，来源与时间/覆盖是什么？
- 最可能的失败、竞争解释和反例是什么？其风险若发生如何停止/降级？
- 哪些结果已知、只是假设、仍不知道？何时需要额外验证/用户权限？
- 怎样做最便宜且有辨别力的真实验收；未通过如何恢复/回退；新增成本值得吗？

**预警状态**：KNOWN_VERIFIED / CODE_OBSERVED / OFFLINE_TESTED / UNKNOWN / ASSUMPTION / BLOCKED / REAL_RUNTIME_VERIFIED。不要强设统一100%“知识完整”，不知道时明确指出影响和取证计划。

**风险锚点**：若研究数轮仅增加报告、专家提示词、代码接口而没改善数据覆盖、经济事实、参与判断或部署质量，首先怀疑工作方法与证据入口，不一定怀疑目标价值；选择原位修订/复用成熟成品/缩小真实范围/暂停，而非循环扩知识层。新事实能改变选择时可以修改局部实施方法，**稳定业务北极星不轻易更改**。

**停止条件**：本蓝图已足以指引R0/R1，不继续为了覆盖“所有可能知识”而无限新建规划。真实项目会出现未知未知，正常做法是及时识别类别、评估影响并做最小必要修订，不宣称可以预言一切。
