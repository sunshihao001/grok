# Blix AI 工作台｜完整目标锚定、全局预规划与实施准入总纲 V1.0

**建立：2026-11-13。类型：PRE-IMPLEMENTATION MASTER PLAN。状态：规划与源码基线已梳理，未获得真实业务通过。**

此文件是已有 goal-map / six-business-outcomes-dependency-audit / build-register 的**统一导航与实施准入**，不是第四套目标体系、项目架构或专家制度。不废弃这些文档里的经济知识，也不以不断添规划代替实际运行验收。本轮仅提交计划与建设台账；**不修改运行代码，不调用模型、付费数据、签名、交易或部署。**

## 0. 失败根因与本次纠偏

过去多轮返工的共同机制：
- **认知入口错误**：用户表达“发现机会、资金追踪、独立工作台”，AI立即理解为某一页面、某一接口或六个终点功能，没有首先重建从数据到真实业务的前置条件。
- **实现先于评审**：发现新名词就新增模块，在评估已有 Blix 组件、仓库其他PR与成熟成品、权限边界之前写入代码。
- **证据/状态混淆**：静态源码、合成测试、真实RPC、持久运行、模型知识增益、可跟随净收益被近似放在同一个“完成”叙述中；UI显示观察候选不等于全市场发现。
- **没有横向工程准入**：漏掉监控恢复、时间来源、供应商配额、账户角色、成本、数据分母、失败样本、性能、隐私与回滚，随后每轮临时加层。
- **整合债务**：截至本轮核查PR #23为Draft、未合并、mergeable=false，292 commits/93 changed files，原Blix保护测试绿色但未真实部署；不能再仅以新提交数衡量进展。
- **没有“规划未知事项提醒”**：后来才发现遗漏的子问题，没有提前登记为UNKNOWN、开放问题、探索试验与停止条件。

**新行为**：先完成全局规划覆盖评审和具体实施包的前置检查，再执行可逆且授权的代码；实施时允许新发现，但只有跨层证据改变依赖、价值或安全时才改大方向。避免把“研究充分”误解为“必须预测所有未知”。

## 1. 固定项目北极星（除用户改变目标，否则不得被局部研究替换）

**长期产品目标**：保留完整原版 Blix（Pulse、Discover、Coin、Wallet、交易、账户和原AI入口），在其上形成**独立但深度连接的 AI 研究工作台**，自主发现Solana Meme潜在真实交易机会，并能从原始链上事实调查关键钱包、资金组织、库存、跨Mint行为，依据新证据持续修正判断。

**六个并行业务结果**：
O1 自主市场发现与候选筛选 → O2 关键钱包/设施地址识别 → O3 资金、Token、库存、交易对价还原 → O4 跨Mint资金/钱包群体关联 → O5 可参与性/跟单策略的只读评价 → O6 持续观察、更新与纠错。

**价值优先级**：能评估“实际存在可能的交易机会”比单纯找到“值得研究的异常”更重要；但没有首可见时间、可执行报价和退出条件，系统只能输出调查机会，不能硬判可以赚钱。

**使用体验**：用户用简单口语提出目的；AI承担提出下一问题、选择成熟知识与只读工具、反证和验收，用户保留资金和风险权限。AI要能从Market/Coins、某Mint、某钱包和持续事件等多个入口开始，**六环不是所有问题必须走完的流水线**。

**既有约束**：可授权的本地读取/离线模拟优先；不自动调用交易、签名、付款、购买数据、公开部署或跨权限操作；保持原版功能完整但不在研究过程中启动有交易副作用的原服务器。成熟成品可直接借鉴、有限移植或整用，不预设必须造轮子。

**排除**：不为达成指标伪造钱包关系、同控、资金批次、盈利、实时性；不把知识目录、Agent角色、测试文件数、PR数视为商业价值；不承诺零错误或稳定盈利。

### 2.1 事先需要登记、但当前无足够事实决定的开放问题

- 实际目标市场宇宙要覆盖哪些发射平台、链上协议与运行时段；缺成本/延迟实测时先按原版可用范围作为试验宇宙。
- 数据是否来自部署者的真实Blix业务库，历史时点与签名能否复查；现有GitHub只有源码和合成测试，不能假设用户实际SQLite已连接。
- 当前主要成本约束（供应商每日额度、模型计费、存储和云资源）及部署场所（本机、受控Grok云电脑、远端访问）。
- 哪些数据源许可外发到第三方模型、哪些只能留在本地确定性处理。
- 机会类型/交易尺寸/最大可接受信号延迟与测试窗口，没有可靠基线前不强设数值门槛。
- 原版Blix真实运行对安全隔离/性能/多用户登录有何副作用，PR23与PR24、blix base的最新合并冲突要逐项判定。
- 继续采用独立工作台作为主要复杂调查入口是否经真实使用证明优于原Coin内嵌。用户已选择独立工作台，但页面/模块分工仍可以优化。
- 监控是按事件触发、按用户研究案例触发还是周期全市场扫描：应由后续实测容量、费用、目标事件决定，而不是先编定时器。

以上属于“**有预警但暂未能证明**”，不是漏掉，也不是需要用户立即提供8个答案。每项只在进入相关实施包时收集必要事实/自主查询。

## 3. 一条业务完整闭环的共同事实输入

任何市场/经济结论须尽可能保留：
- 调查身份：caseId、Mint、Pool/Program、相关地址/TokenAccount/Owner、研究目标、触发来源；
- 事实原文：数据提供者、API版本/许可、签名与outer/inner指令、Slot/Commitment、RPC/快照hash、解析版本；
- 时间口径：链上发生、提供方发出、系统接收、首次可供模型/用户观察、行情报价时点、模型解释时点；
- 覆盖口径：本次可用的市场宇宙、历史范围、采样阈值、RPC失败/游标、源间冲突、未知/截断；
- 经济口径：Token/SOL/WSOL原始金额、Decimals、对价、费用、余额前后、Pool/Vault/TokenAccount归属及资产守恒；
- 推理口径：已证实、候选、竞争解释、缺失证据、可以推翻的观察条件、失败/停止理由；
- 决策口径：调查优先级、当时流动性及交易尺寸、入出报价/滑点、风控、可观察性、模拟假设；
- 演化口径：本次相对旧案的新签名/新边、迟到回填、旧结论修订、成本、算法/模型/知识版本。

**这些是逻辑字段语义，不意味着需要立即新增全部SQL表。** 先给原Blix现有存储建立只读映射，确无现成落点的字段才加适当的扩展记录。

## 4. 六个业务结果的完整实现子链（不跳过前置，也不强制所有样本逐级流转）

### O1 自主发现可能的交易机会和研究机会

01 明确市场宇宙与目标协议；02 数据源可用性/授权/费用清单；03 发现源WS与发行/迁移/池事件；04 市场/行情/资金关联源接入；05 事件原文落盘、去重与ID；06 补查丢失/断连及重组；07 多池/多源归并与Pool识别；08 统一事件/首可见/缓存时点；09 流动性/合约/异常/噪音基础过滤；10 早期动量、资金组织或钱包关注事件生成；11 保留所有候选与拒绝、漏报采样；12 AI选择调查对象与理由/成本；13 来源失效或证据不足时拒绝选择；14 后续观察/真实报价验收；15 与原Blix Early/Triage/Brain/Pulse三组对照。

**不要重复写第二个市场爬虫。** 旧版发现链先对齐，再决定AI扩展在哪个增量观察上确实提高选币效果。当前12个候选只是步骤12的一部分。

### O2 关键钱包与经济主体识别

01 发现入口（Holder、首买、Dev/Creator、资金出资/Token接收、别的Mint）→ 02 精确定义账户类型 → 03 TokenAccount Owner/Authority/fee payer、Pool/Vault/Router/CEX/KOL服务排除 → 04 钱包签名分页与历史窗口恢复 → 05 未在Holder榜单的中转/新钱包发现 → 06 多协议买卖/LP/转仓行为解析 → 07 按时间划分钱包角色、避免永久单标签 → 08 同Slot/Bundle/资金共源等竞争解释 → 09 精选后续要查的地址及理由 → 10 标明覆盖与身份 UNKNOWN → 11 独立正负例和误归因评价。

### O3 资金与库存

01 取原始签名和完整tx/meta → 02 v0/1、ALT、inner CPI、Token/Token-2022 → 03 失败/手续费/WSOL unwrap界面 → 04 Swap/Transfer/LP/路由多动作分解 → 05 Token与SOL精确前后净额 → 06 映射钱包/池/公共设施与真实费支付主体 → 07 买入、转入、卖出、转出、LP持仓库存流水 → 08 分辨库存成本/转入批次不可知 → 09 签名级去重和资产数量守恒 → 10 资金来源多跳、充值中转、混合账户竞争解释 → 11 逐条资金网络/库存可追溯证据 → 12 负例与缺口补查。

**钱包历史不全时可以得出“已捕获局部资金变化”，不能得出“完整筹码占比/成本/收益”。**

### O4 跨Mint资金联系与群体

01 从已观察Wallet/Mint事件选择追踪入口 → 02 发现卖出后接收、转出后再买等窗口 → 03 取新地址与其它Mint涉及的原始签名 → 04 交易顺序和Lamports净额与资产变化 → 05 避免把CEX/Pool/Router/公共Funder当同控 → 06 多跳探索预算/剪枝/循环检测 → 07 群体时序、成员变化与重复关系 → 08 区分同地址、同资金候选、共同控制假说与实证 → 09 保留反例/置信边界/时间错位 → 10 动态事件索引到原案件与其它Mint → 11 路径重放与原交易引用 → 12 对跨Mint误报抽样。

### O5 可参与性/跟单与策略研究

01 定义机会类型、目标交易尺寸与可观察信号 → 02 确定最早知道该信号的真实时点 → 03 同时点Pool/路由报价与可执行数量 → 04 Token卖出/合约限制/LP撤出与流动性风险 → 05 费用、优先费、滑点、手续费、MEV与信号延迟 → 06 可执行的部分入/出场模拟及退出失败 → 07 成本/库存与跟随钱包复制可行性 → 08 交易规则参数的敏感性 → 09 历史时间隔离、完整候选及负例/幸存者偏差 → 10 原版规则/链证据增强/AI辅助同数据对照 → 11 纸面净收益与不确定性/不参与原因 → 12 长期样本外和行情漂移观察。

**输出至少分** WORTH_INVESTIGATING / WATCH_ONLY / FOLLOWABILITY_EVALUABLE / NO_DECISION_DATA_MISSING。只有实际报价、退出与验证材料允许进入“可评估”层；“可评估”也不是“建议买入”。

### O6 长期观察、纠错与学习

01 Case持久主键/关联Mint钱包/原始来源 → 02 可撤销的观察范围和事件目录 → 03 增量订阅/可靠水位/重新拉取/幂等 → 04 原始新增、迟到回填、数据重解析差异区分 → 05 重新计算余额/群体/可参与性 → 06 改变了哪个假设/为什么 → 07 只在有新事实或未知可减少时调用模型 → 08 监控质量、告警合并、限频/费用 → 09 故障暂停/恢复、重启后不丢调查上下文 → 10 人工反馈与失败记录 → 11 反证变更前后的研究正确性与成本 → 12 可停止、可重开、可导出证据，模型版本可追踪。

注意：能在报告上写“持续监控”不等于有持续事件系统；当前 O6 主要仍在设计/原Blix能力复用与待验证阶段。

## 5. 产品与技术路线：保持一个可修订的总判断，不在每轮重做架构

**已选方向**：原Blix为成熟行情/数据/用户产品基础，独立AI研究工作台负责深入多Mint调查、案件留痕与AI解释，支持Coin/Pulse/Wallet互跳、共享现有证据。只读适配层隔离原Blix账户/签名/交易/可能有副作用GET。

待具体实施选择的三种落点：
- A 原Blix既有接口/数据库的**真正无副作用快照读取** + 目前侧车AI：优先，减少复制；
- B 在原Blix内部新增有安全界限的只读共享服务并由侧车调用：当测试证明接口被重复维护或实时延迟不可接受；
- C 独立完整Indexer/新市场服务：只有A/B实测无法达到范围、延迟和成本目标才采用。

**平台责任边界**：确定性采集器负责完整记录、证据/净资产计算、准入限制、价格与费用；模型负责提出问题、选择调查步骤、比较解释、识别未知、生成有依据的结论；知识库存储历史机制/工具适用条件/失败反例，不授予模型额外权限；UI展示来源、受限条件和后续操作。

实现前做**直接复用/有限修改/组合/另造**比较，尤其对照成熟索引/回补、钱包账本与Agent工具门禁。外部源码注意许可证与真正运行能力，不能把参考成品营销描述等于源码事实。

## 6. 容易漏掉的跨层工程要求（失败预演）

| 风险ID | 预先想过的典型失败 | 先制定的退路或验收 |
|---|---|---|
| F01 | 发行流漏币、二级DEX未覆盖、WS断连 | 市场范围与缺失统计，来源故障降级，不产完整召回结论 |
| F02 | 数据源第一次可见时间不可知、缓存时间冒充行情时点 | 各类时间字段分开，不能拿行情事后高点做入场 |
| F03 | 供应商429/档案缺口/补查超过预算 | 游标/暂停/恢复、费用闸、数据缺口说明与有界补查 |
| F04 | 同Token多池/LP+Swap/跨接口重复事件 | 签名+指令层去重，多池源标识与库存守恒对照 |

## 7. 在写下一段代码前必须完成的一次“实施包评审”

每个即将实际执行的任务必须有清楚的简短决策记录，不要对每个小函数走复杂流程：

| 评审关口 | 必须说清楚 | 不满足如何处理 |
|---|---|---|
| G1 目标/价值 | 对应哪一个O1–O6，最终用户看见什么提升；失败会损失什么 | 若只是新界面/词汇，停止 |
| G2 依赖复原 | 输入来自何处、前置哪些代码和数据、谁会消费结果、是否复用原版 | 不知道输入或后续消费者时先核查 |
| G3 既有能力/备选 | 原Blix、PR #23/#24、Hermes/qb-/meme-及成熟项目谁已做好；整用/改/组合/新建四选依据 | 相同功能优先复用，拒绝盲重做 |
| G4 真事实/权限 | 是否拿得到合法存档、什么时间窗、来源水位与费用、是否存在签名/交易副作用 | 输入不可取得时只设计替代方案，不造虚假功能 |
| G5 失败/反证/未知 | 至少一组成功、反例、来源失败、未证实情况；任何未知如何降级 | 关键未知会影响安全或结论时阻断 |
| G6 验收/回退 | 最小有价值纵切验收、原版对照、前瞻检测条件、回滚/历史兼容、CI检查 | 没有可观测成功标准不实施 |
| G7 代价/停止 | 新增调用配额、存储/维护复杂度、预期信息增益与不值得继续的条件 | 复杂度明显大于实测价值时不扩 |

**不需要每次重新规划全项目**。只检查本次实施包在总规划中的位置，补填真正缺失的一项，按证据修改局部即可。

### 7.1 预警：明确哪些“没考虑到”还在排队

所有需求、风险、实现问题可用这五种状态，无需再新建一套专家目录：

- KNOWN_AND_VERIFIED：已用指定源码/原始记录/正确测试核查；
- KNOWN_UNVERIFIED：知道应该有，但缺正确样本或实际运行；
- ASSUMPTION：为了推进暂用的可推翻前提，必须列验证途径；
- UNKNOWN_OPEN：尚未掌握的外部条件/供给/API/业务要求，记录触发探查的时点；
- BLOCKED_CONSEQUENTIAL：继续会带来数据造假、资金操作、破坏原版或未经允许的外部费用，停在当前安全边界。

每项开放事项记录**相关目标、负责人（AI先自行检查）、重要性、依赖、验证入口、阻断与否**。可以存在无法预知的未知未知：当事后发现它属于某一风险类别时登记反例并调整评审，而不是宣称能预见所有异常。

## 9. 追踪进展不再犯的三种“完成”错误

- **文档完成**：已经说明设计、权限和测试方案；不意味着有代码或市场数据。
- **工程完成**：源码+离线测试/CI有保障；不意味着已接真实RPC/模型/运行。
- **业务完成**：真实对象/时间窗/来源/收据完整，确实覆盖用户业务任务，错误和未知可解释；而真实机会效果还要前瞻Shadow。
- **产品完成**：兼容原版、有实际操作界面、持续运行/恢复/成本/权限和用户验收；不等于承诺盈利。

仓库中已有的单条模拟A→B→C→Mint B，不可以拼接到任何真实Mint并当作“真资金闭环”。历史已采DEX源快照也不能自动转成真实钱包Swap签名。**“只读”是一项操作与接口层属性，不是“模型说不会交易”就够。**

## 10. 本轮的计划结果与下一项被允许的行动

**这轮只做“计划/核查”**：无代码运行改动、无付费模型调用、无联网链上抓取、无Blix服务器启动；已经明确整个O1–O6需要考虑的范围、跨层数据契约、技术备选、错误预演、开放问题、验收和纵向交付顺序。

**下一次实施任务的唯一推荐起点**：R0的当前分支/原版保留/安全与合并冲突事实核查 + R1的真实市场源/已存在SQLite可读性能力测试。优先取**一枚同源真实Mint/同一时间窗**，不凭“源码里已有表”就宣称可读到，没权限就记录该阻断并改选安全的已存档资料。

**设计停止点**：上述全局覆盖和可观测验收已经足够指导第一批任务；除非新的证据实质改变目标、实现路径或风险，不继续无限建规划。每批做完复盘“目标还一致吗？有真实信息增量吗？是否重复/偏离？是否该换成熟实现？”只改变必要局部，不重写北极星。
