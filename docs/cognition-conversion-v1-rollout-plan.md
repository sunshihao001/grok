## 1. 首先校准问题

当前项目不是缺少更多“知识卡”或更庞大的提示词，而是缺少跨来源的机制关联、可追溯知识转化、独立证据审查与真实案例验证。已有 15 张概念卡、21 份历史快照、17 条来源索引与按需研究入口；这是起点而不是专业程度的证明。

目标不是统一所有作者的说法，而是建立：原始知识及其上下文 → 可竞争的机制假设 → 观测与反证 → 决策时点可用的信息 → 净收益可行性 → Grok 可调用的研究能力。

## 3. 双轴规划：全面覆盖，但不浅层扫过

**横轴：专业知识领域地图（滚动补齐，不当作唯一分类）**

1. 发行与市场阶段：创建、曲线、迁移、池深、权限、路径；
2. 钱包与经济实体：地址、资金来源、执行者、服务商、控制关系、历史行为；
3. 交易和筹码机制：早期买入、做市、派发、回流、真实与虚假成交；
4. 市场微观结构：流动性、价格冲击、优先费、路由、延迟、可退出性；
5. 价格、成本与策略：价格接受、POC/AVWAP、结构失效、状态切换；
6. 跟单优势：信息时差、可观测性、钱包选择、选择偏差、净期望；
7. 风险与对抗：合约风险、虚假标签、Sybil、数据错误、反向诱导；
8. 研究工程：来源证据、时间可得性、假设检验、回放、评价和版本审计。

**纵轴：每次围绕一个实际问题深研**

问题与决策时点 → 原始事实 → 竞争机制 → 关键判别证据 → 可测指标 → 反事实/对照 → 可交易性 → 复盘。不能由旧结论直接跳到策略规则。

横轴负责“不遗漏”，纵轴负责“吃透”；发现新机制可立即修改横轴。

## 4. 执行次序与成果门槛

**P0｜知识资产审计（起点）**
- 将已知来源按“已读原文/只读目录/待核验”分层；查重、冲突、失效假设与代码-知识边界。
- 成果：来源矩阵、冲突清单、知识缺口表。
- 门槛：每个优先结论能回到原路径和提交；不能从单一仓库归纳全领域。

**P1｜V1.0 认知与转换规范（本次）**
- 定义最小共同推理语言、开放探索权限、证据边界、转换层次、不同项目角色。
- 成果：可阅读的规范文本、一个实际跨项目示范、下一阶段试点规则。
- 门槛：不强制单一“正确思路”；能清楚说出事实、推断、假设、可交易性之间的区别。

**P2｜首个纵深单元：钱包的可跟随性**
- 以“某钱包值得跟吗”为核心，重新辨别经济实体、短期行为、历史绩效、决策可用信息、成交可得性。
- 成果：机制图、原始证据与反证、特征词典、模拟执行评价方案、失败例。
- 门槛：能解释为什么历史盈利钱包不一定有可复制的交易优势。

**P3｜选择性工程化**
- 在现有 knowledge/source_index、research.py、case-template 和监控输出之上建立关联；不批量拷贝与旧 Hermes 环境绑定的实现。
- 成果：一个能被问答与观测情境调用的知识单元；保留相关来源、反证与下一步采集请求。
- 门槛：不能只复述命中的关键词；对未知机制应支持继续探索。

**P4｜盲测与修正**
- 对已有/新增真实案例做冻结时点重放，与无知识、仅提示词、带知识版本对照；检查错报、漏报、来源准确率、前视信息、反证能力及净成本。
- 成果：可复算的对照报告、回退记录和下一轮优先研究问题。
- 门槛：未通过真实数据与独立复核的内容不得升级为已证实交易规则。

## 5. 第一轮研究的具体顺序

1. 先统一旧仓库“地址—实体—角色—控制权—Gate”和新仓库研究语言，逐项指出证据跳跃。
2. 接入取证项目对样本/分母、共享基础设施、时间泄漏与失效收益的审查方式。
3. 将 meme- 的周期、成本、回收等概念拆为“实时可识别”和“事后可描述”两类。
4. 用 QB/OKX 的真实字段能力核实可观测性；不以可用的字段反过来限制研究提问。
5. 将知识转化为首个“钱包可跟随性”研究包，再测试 Grok 是否真正优于现有最小知识路由。

## 6. 治理与非目标

- 研究笔记可以开放发散，运行时判断必须保留证据、时间、反证、未解部分。
- 可新增或否定分类；不得因为已有目录/关键词而禁止新机制。
- 不把“确定庄家”“同源即同控”“价格相关即操纵”等无法支持的推断写为事实。
- 商业平台字段必须区分原始观测、供应商推断与模型推断。
- 第三方资料优先引用并独立概括，遵守来源许可；不批量转载有限许可的文章。
- 先在独立草案分支保存文档，不修改 main、现有 rules/、Bot 或 Routine。

## 7. 本阶段完成定义

完成 V1.0 规范草案与来源对照，至少能回答：一份外部知识为何适用于跟单、何处不适用、如何转化为新的研究问题、哪些事实仍未知、如何证明 Grok 的判断比只会复述文档更好。

本阶段不宣称：全仓知识已吃透、策略盈利、实时市场数据已验证、Grok 云 Bot 已执行。
