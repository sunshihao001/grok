# 下一阶段路线图｜从知识架构 V2 到真实证据能力

> 以 [知识架构 V2.0](knowledge-architecture-v2.0.md) 为唯一层级规范；研究原则 V5、运行架构 V4。按证据缺口排序，不按新增文档或 Agent 数量排序。

## 当前完成的结构工作

- [x] 盘点当前 15 张知识卡、21 个历史快照、30 个来源指针、17 专家/12 域、40 条交接边、8 个机制假说和 R001–R007 研究资产。
- [x] 统一 L0–L7 知识层级，明确与 S0–S7、软件模块、V4 双循环、K0–K4 成熟度的区别。
- [x] 更新 README、CONTEXT、Skills 入口、Knowledge README、Bot 职责和关键架构文档导航。
- [x] 将 V1 整合蓝图和旧专家编排文档标记为历史/专项，避免与 V2 争夺总层级。
- [ ] 对 15 张种子卡逐张补齐 domain、claim、成熟度、失败模式、source IDs、supersedes，并做机器 Schema 校验。
- [ ] 对 30 条来源逐条核验当前 pin、原文、许可证和已阅读范围；发现队列、已审阅来源、实际数据连接器分别维护。

## P1｜链上事实本体与 M1 真实数据（最高优先）

- [ ] 冻结事件 Schema：交易签名/Slot/index、外部/内层指令、账户索引/ALT、Program、Token Account owner、Mint、raw integer、decimals、pre/post balances、block_time、observed/available/received_at、source/version/coverage。
- [ ] 先覆盖 System Transfer、SPL Token/Token2022 Transfer、SyncNative/CloseAccount/WSOL、Swap、LP add/remove、Mint/Freeze/authority change、create/migrate。
- [ ] 对选定签名逐条调用可信只读 RPC，复原 inner instructions、余额守恒、费用/rent、账户归属和多程序 SOL 收入；保存原始响应摘要/版本和可重放结果。
- [ ] 对数据分页、历史缺失、速率限制、迟到事件、重试、ALT、RPC 失败、冲突供应商建立质量与覆盖报表。

**通过条件**：对一个限定 Mint/时间段，独立复算的交易和资产事件可逐条回溯；所有 UNKNOWN 和数据缺失显式可见。此时才把对应命题升到 K3。

## P2｜资金/库存时序路径与经济行为片段

- [ ] 资产图与主体假说图分离；资金边、Token 边、Swap、LP 和账户 owner 都带签名和时点。
- [ ] 建立时序 Motif：资金来源→注资→买入/创建→持仓→归集/转移→真实 Swap/LP→SOL/WSOL 收入→跨 Mint 再部署。
- [ ] 区分转账、内部指令、Token 账户关闭、WSOL 解包、LP 释放、手续费领取、桥接、CEX/服务商资金。
- [ ] 允许公共 hub、共享执行基础设施、独立机器人、受益人未知和未归属库存；不强制地址合并。
- [ ] 将 R005/R006/R007 的派生结论拆成可检验 Claim，并选签名原始回放。

**通过条件**：至少一个真实案例在明确范围内资产守恒/未闭合差额可解释，主体关系仍允许 UNKNOWN，竞争机制能被不同签名证据区分。

## P3｜正常总体、协调 null 与概念漂移

- [ ] 建立未经过当前检测器筛选的 Mint/发行/时间窗口总体及未命中样本。
- [ ] 按协议、发行阶段、活跃度、池深、参与者数量、公共 hub、机器人密度和数据覆盖做条件匹配。
- [ ] 实施图置换/null、时间随机化、hub 排除、同源/同 Slot 对照、多重检验控制。
- [ ] 量化误报/漏报、灵敏度、基准不确定性与样本外漂移；未知数据覆盖不能当零活动。
- [ ] 区分统计偏离、协调行为、经济同控和操纵意图四种结论。

**通过条件**：独立留出集上给出基准定义、分母、误报/漏报和不适用条件；没有总体就不得发布全市场异常率。

## P4｜市场微观结构、生命周期、开发者与风险

- [ ] 复原曲线/AMM 池状态、真实储备、价格冲击、滑点、路由和退出容量。
- [ ] 将发行者/部署者/权限历史、创建者费用领取与资金网络按时间联结，但不把关联当同控。
- [ ] FCZ/POC/AVWAP 等理论冻结事前计算方法，区分实时可见区域和事后标签。
- [ ] 把风险预警、预测增量和纸面交易价值拆开；用真实当时报价、延迟、费用、失败成交和退出成本。
- [ ] 跨协议/市场阶段做独立样本外检验。

## P5｜知识架构与专家调度效用评估

- [ ] 逐卡结构化 15 张 legacy cards；新增知识须带 source refs、claim、scope、maturity、baseline、reject_when。
- [ ] 检查 40 条专家交接边是否都有可用 artifact/schema、反证触发器和回归测试；无效边应删除/降级。
- [ ] 在陌生案例上做盲测：无知识基线、单模型+来源、按需专家+独立反证，固定 token/时间/来源预算。
- [ ] 比较来源准确率、事实错误、错误归因、可判别新机制、反证命中率、成本和延迟。
- [ ] 若专家调度不优于更简单基线，缩减复杂度，不因已有投资而保留。

## P6｜真实运行与 Grok 云端

- [ ] 先在本地/CI 完成真实来源只读回放，再验证云端 Python、GitHub 读取、Skill 加载和实际回答。
- [ ] 验证持久化、幂等、迟到事件修订、断流恢复、日志保留和告警去重。
- [ ] 一个只读 Monitor + 一个按需 Research Manager；17 专家按需作为知识能力，不建 17 个常驻 Bot。
- [ ] 任何 Routine、通知、生产阈值变更均需单独人工批准；真实交易仍不在当前授权范围。

## 当前禁止的“假进度”

- 新增知识卡数、专家数、来源 URL 数不等于知识成熟度。
- CI 通过不等于真实 RPC 解码正确。
- 资金关系图高密度不等于经济主体同控。
- 同 Slot、同步买入或共同 funder 不等于 Jito Bundle/操纵。
- 研究报告的历史上涨不等于当时可预测或扣费后可成交。

**下一步只做一个纵切片**：挑选一个有明确签名范围的真实事件窗口，完成 M1 原始解码与时间/覆盖合同 → M2 统计 → M3 资金/库存路径 → 一个普通竞争解释 → 独立 QA。先证明事实链条，再扩展覆盖。
