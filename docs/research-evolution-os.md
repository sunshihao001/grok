# Scientific Edge OS — Grok 的研究→知识→规则演化体系（KNOW-003）

## 不应该建设成什么

不要变成一堆关键词和标签、自动追求高 AUC 的策略、把上传过的历史长文冒充实际已掌握的知识、把第三方研究对象的历史胜率替代自己可成交净收益。也不要把阅读更多 Solana 资料本身当作目标。真正的目标是不断定位：**何种数据能在某个时间点被 Bot 看见，并改变其未来可复制收益分布**。

## 因果问题地图

| 研究问题 | 对应层 | 真实可观察量 | 当前最常见假象 | 合适的反证 |
|---|---|---|---|---|
| 是谁把资金送来 | 资金关系 M | 方向/签名/原生 SOL | CEX 出金、粉尘、托管中继 | hub 对照、真实交易页完整度 |
| 是否同一批执行者 | 行为复现 M | 相似配置/同源与同 slot | 高频撮合、统一抢购模板 | 时间/度数保留 null、留一地址 |
| 谁能领先公开市场 | 信息时间 P | 记录实际 first_seen_at 和 latencies | 回查时间伪装历史可见 | 禁止未来时间与复盘 hindsight |
| 已知组是否还能预测 | 条件预测 P | 事前组特征、下一次发币结果 | 组与入场价、池深重合 | P0/premium/阶段/日/运营群匹配 |
| 跟单者能否赚到 | 成交捕获 C | 买入和退出可执行报价与真实/模拟成交 | MFE 顶点、流动性不足、尾部 0 退出 | fixed order size + quote replay + cost tails |
| 不跟单是否更好 | 机会成本 C | 对照策略、被过滤的币、损失规避 | 只记避开亏损，忽略错失机会 | 反事实净收益和类别分布 |
| 跟踪新机制是否正确 | 体系漂移 | 随时间变化的错误类型和字段 | 概念变化或平台源字段变更 | 样本外前瞻、变化点回放 |

## 研究平台的七个互斥对象

1. **Source Passport** — 链上交易签名、slot、原始 RPC/GMGN 字段与可用时间、HTTP 错误及来源版本；并非在 README 写一个链接。
2. **Observation Ledger** — 去重后保存什么、何时由哪个 Bot 得知。缺页不是空历史，匿名地址不能上升为人的身份。
3. **Mechanism Graph** — 发行、资助、关联交易、建池、筹码分发、外部买入、退出、回流：有向事件图带时间，不先猜“庄家”。
4. **Hypothesis Ledger** — 一条机制是否可解释、一条条件预测是否成立、一条交易动作是否可复制，用独立编号及否证记录。
5. **Protocol Freeze** — 先写数据集合、对照、null、窗口、交易假设、费用与退出约定，再读目标结果；训练/验证/全新测试按时间切分，不循环刷 TEST。
6. **Execution Laboratory** — 按预先定义的挂单/路由、进出价、池深、报价时效、交易失败与全部成本计算现金流；与最简单持有/观察/固定成本策略比较。
7. **Promotion and Retirement** — 只在有独立数据、统计稳定性和经济净收益时申请人类审批；失效时降级、回滚，保留失败案例与原版本。

## 运行对象和职责

- Grok Rule Architect：生成精确定义、竞争假设、实验冻结与反证计划；不得靠类比直接发布。
- Grok Data Bot：记录原始事件与实际观测时间、来源异常；不能在 API 报错时返回 []。
- Grok Wallet Bot：复核 source/terminal/hub 与已知组，输出证据图和基础设施争议。
- Grok Execution QA Bot（新增研究职责，沿用原 QA Bot）：独立计算可交易收益与时间泄漏，测试高胜率、低净值、退出失败、密集重复群。
- Grok Evidence Gate Bot：生成研究裁决/负面证据；不允许参考包“升格”成已验证规则。
- 最终 Monitor：只读，加载 **已人工冻结** 的规则；能解释来源、缺失和反证；不运行探索搜索，不修改规则、不交易。

## 关键契约（阶段划分）

S0 SOURCE_REVIEW → S1 HYPOTHESIS → S2 VERIFIED_OBSERVATIONS → S3 PRE_REGISTERED_TEST → S4 PAPER_CANDIDATE → S5 HUMAN_FROZEN_MONITOR。晋级需要人工审批；“规则的 CI 全绿”只证明代码契约，不能视作市场验证。

S2 门：真实事件签名与原始字段单位的交叉校验、first_seen 记录、完整样本框、独立平台比对。
S3 门：基本对照 + 时间随机化和节点度数保持 null、具体失败条件、真实成本数据、正反例、禁止看未来。
S4 门：连续新样本，按实际可得延迟填单、留出测试群/周、独立回放、负 ROI 和错过机会的审计。
S5 门：来源冻结、可复算报告、回滚方案、人工签字；即便通过也只使用只读 paper monitor。

## 最新一轮研究线路

**路线 A（最高优先级）：观察时间 × 可跟性**
- 采集候选币从资金事件→链上确认→API 返回→Bot 决策→报价有效→成交的每个时间戳。
- 目标：估计条件于 Bot first_seen 的机会衰减曲线，避免用交易发生时间代替自己收到信号的时间。
- 否证：与随机延迟、普通钱包跟单、分层匹配币相比，没有可稳定提升的执行净值。

**路线 B：资金图做反面筛选而非直接买入**
- 比较共享 hub、独立非 hub、粉尘欺骗、同钱包轮换的失败退出率；留意样本池的结构性差异。
- 否证：同阶段同深度下的风险差异为零；拦截的机会成本超过避免的损失。

**路线 C：阶段重接纳研究**
- 对第一控盘区、POC/AVWAP 回收等理论设计前瞻位置、保守模拟成交和期限，不使用事后最低点。
- 否证：扣滑点/退出失败后，与简单基线相同或更差。
