# 目标演化与 AI 自主决策｜首个业务试点记录（2026-11-05）

> **当前状态：项目目标重构与源码证据审查已完成；主体运行及完整 Mint 深度调查仍未验收。** 本文既是实际业务的选择记录，也是未来判断 AI 是否真正改善目标理解和交付质量的试点说明。不是自动化 Agent 已上线的声明。

## 1. 用户一句简单要求背后，有五种不等价的目标

输入示例：“找出这个 Mint 的异常钱包，再持续看是不是一群人在其他币上重复操作。”

- **人的最终价值：** 获得有证据支持的市场信息与可能有用的经济机制，而非预设“庄家”和必然盈利。
- **业务价值：** 从 Mint/Creator、持有人与买卖交易发现关键行为；分析资金和群体关系；长期观察成员替换、库存和时序变化。
- **证据要求：** 准确记录 Token Account/owner/fee payer/AMM 的不同身份，链上交易位置、来源时间、漏失和 UNKNOWN。
- **工程任务：** 选择成熟应用可承载的界面和只读数据能力；建立或复用历史补查、事件去重和持久化。
- **战略可变性：** 如“实时市场终端”不足以调查历史，应调整调查数据获取方式，必要时重评产品主体，而非继续扩大看板。

## 2. 这次已经取得的真实证据，绝不升级为更多能力

来源 [PR #16 的真实供应商记录](v01-real-rugcheck-holder-2026-11-01.md)，对 `EYqygbhZjP7EbM4fSn8devctnksAvPAD1Bt57XBFpump` 在 2026-11-01 曾真实联网取得：
- DEX Screener：**5 个池**；RugCheck：**20 个 Holder Token Account 候选**和 Creator 候选。
- 一条 Holder 的 Owner 与某 PumpSwap 池地址相等，且 RugCheck 标签为 AMM；仅可当作公共设施排除的**候选证据**，非链上独立证明。
- 来源可能缓存，观察发生于特定时点；**非完整历史、非已确认经济主体、非跨 Mint 行为、非实时监控**。
- 公开 RPC 对此样例曾 HTTP 429；不能把限流当不存在数据。

现有这些数据足以形成一次 **“目标升级是否合理”** 的真实案例：原先“找 Holder 大户”会把池账户误认为鲸鱼；升级为“验证账户角色、经济主体和实际控制关系”能够避免一类明显误判。

## 3. 不同成熟路线及其真正的优先级

| 路线 | 对目标的帮助 | 当前证据 | 代价与风险 | 取舍 |
|---|---|---|---|---|
| Blix 整体终端＋必要调查增强 | 交互、行情、钱包跟踪和市场发现已有大量功能；距离可用 UI 近 | [API](https://github.com/blixvip/blixtrade/blob/main/docs/API.md)、[wallets.js](https://github.com/blixvip/blixtrade/blob/main/server/wallets.js)、[journal.js](https://github.com/blixvip/blixtrade/blob/main/server/journal.js)源码可审 | `wallet_trades` 主键为 `(sig,wallet,mint)`；需验证单签名多经济事件有无合并；历史和 RPC 覆盖可能不足 | **第一候选**，先安全隔离验证 |
| Pulse 成品作为专业后台或主体 | 归档和数据层清晰，接入历史追查有可能容易 | [stream](https://github.com/nirholas/pulse/blob/main/src/collector/solana-stream.ts)、[schema](https://github.com/nirholas/pulse/blob/main/src/db/migrations/001_init.sql)源码可审 | 交易选择性归档；队列 `splice(0)` 后写入失败没有在当前路径恢复，仓位累计缺少同事务保护；未做故障复现 | **必须保留对照**，故障测试先行 |
| 已有 grok PR #16＋成熟专业来源 | 有真实 Mint 报告和供应商源证据，可充当独立基线 | [运行证据](v01-real-rugcheck-holder-2026-11-01.md) | 缺完整历史/钱包/跨币与交互终端 | **对照基线**，防止把已有成果重造 |

**本轮判断：** 第一试点不需要先做“全市场全功能集成”。先用上面的真实 Mint，以 Blix 为体验/业务主体第一候选，对照 Pulse 和 PR #16。只在有必要时接入 Million/PumpTrace 等成熟调查能力，不预先合并所有仓库。

## 4. 真实运行验收：一条业务链而不是功能清单

| 业务验收点 | 实际检查方式 | 当前结论 |
|---|---|---|
| 同一 Mint 的公开市场池和基础 Holder 候选 | 核对原始供应商响应 SHA、采集时间、数据源与池/账户角色 | **曾通过供应商级真实联网**（PR #16，2026-11-01） |
| Blix 在隔离环境无密钥/交易/自动付款地启动 | 审查依赖、网络行为、接口/权限；实际启动后读取 health 与 Mint | **未执行、未验收** |
| Pulse 同环境可重复对照 | 使用相同目标输入，检查源覆盖、缓存与 UI/API | **未执行、未验收** |
| 任意历史 Mint 输入能否查询 | 查无当前追踪的 Mint，观察 404/部分输出/历史补查及缺口声明 | **未执行、未验收** |
| 单 Mint Creator、owner、资金路径 | 至少一条原始交易/资金边，证明对象/资产/时点，并排除公共服务误读 | **未执行、未验收** |
| 同签名多钱包、多事件及多池 | 测原始 instruction/CPI/账户净变化；一个 Swap 不双算，多钱包不漏报 | **未执行、未验收** |
| 重启/写入错误/断流后恢复 | 注入可控的断网、429、数据库失败，核对缺口/回补/去重 | **未执行、未验收** |
| 同群体跨 Mint 长期变化 | 连续观察成员增减、资金链、库存变化，记录来源覆盖 | **未执行、未验收** |
| UI 报告与自然语言命令 | 同一证据能展开原始来源、UNKNOWN、反例及关注项 | **未执行、未验收** |

不以“某项目 README 声称支持”替代表格任何一项真实验收。没有相应运行环境时，按源码/理论/旧样本等级汇报阻断，而不把未知填成通过。

## 5. AI 目标演化能力的四个挑战题（验收用，尚非真实评测通过）

| 只说一句话 | AI 应识别的变化层级 | 正确行动应包含 | 错误行动 |
|---|---|---|---|
| “帮我找赚钱的钱包” | 原始业务目标，有潜在价值目标 | 区分历史盈利、可跟性、未来可见时间和执行成本，并提供几个成熟路线 | 只列最高收益钱包并称可赚钱 |
| “跟单只是个小领域” | **战略扩展** | 保留原跟单知识，提议市场发现/资金调查/群体监控和机制研究的战略组合 | 抹掉跟单知识，或者只增一个“扩展模块” |
| “用 Blix，不要研究那么多了” | **实施路线收束**，不一定是永久战略 | 尽快安全实跑；说明哪些未证数据/资金问题必须通过测试而不是继续空谈 | 无证据直接宣称所有功能已经可用 |
| “我觉得知识系统让回答变差了” | **方法失效反馈**，不是专业知识失效 | 停用过度规则；保留原专业内容；通过具体任务对照评估是否改善 | 删除全部知识，或者再增加一套专家/提示词 |
| “继续” | **授权内任务选择** | 恢复已完成、选择信息价值高且可行动的断点、执行并核验、末尾二次推演 | 重新列巨大计划等用户再次催促 |

这几条是测试设计和预期结果。只有在独立任务中比较 AI 的实际行为、实际运行证据和无此引导的基线后，才能称能力已验证。不能让提示词复述替代评测。

## 6. 第一轮由 AI 承担的具体下一动作

1. **先查隔离环境**：确认 Node 24+、无生产秘钥、无钱包签名组件、可关闭不必要外联/AI付费调用，防止把市场终端的可写接口误接到测试中。
2. **真实启动候选**：优先 Blix 的本地开源终端只读页面/GET 接口；在同一 Mint 下记录 health、市场信息、钱包与缺失状态，并对 PR #16 旧原始记录做时间/供应商差异说明。
3. **关键失败即改变路线**：若任意历史 Mint 无法获得可靠钱包/资金历史，比较外接专业数据源与 Pulse 的改造成本，不先写第二套采集器。
4. **再做专业深化**：按实际数据去检查 Token Account/owner/AMM、同签名多事件、多池、仓位变化、共享基础设施排除；来源不够就说明 UNKNOWN。
5. **本轮完成后主动再推演**：是否发现新的经济机制、其他成熟成品或更好的长期目标？如证据不足，停止发散，继续最有价值的实际产品测试。

**项目接收标准**：能够从这份文件恢复目标和当前选择；不会把旧知识当约束，不会把源码当实跑，也不会只在报告末尾重复“建议继续”。
